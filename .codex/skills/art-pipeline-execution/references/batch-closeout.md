# 批次收尾与返工定位

用于多帧集成、确定性镜像和跨工具交付；不增加生图次数、规格门或批准层级。

## 一份现行记录，不反复抄账

在现有 request/manifest/source ledger 中维护本批适用的任务seq、批准来源、选定文件及SHA、替代版本、处理参数、待门状态；不为此另造并行台账。收到修改只更新受影响帧及其派生，不根据“最新文件”或目录排序选择成品。

Leo 逐帧通过时即登记对应文件；PM转达须写转达来源，不虚构现场过程。已确认的同一决定不重复问。候选待目验期间完成该帧允许的QA、对照和记录；不以等待为由漏登记，也不越过明确的逐帧停点生成下一张。

共享死亡件、镜像源、已存在选定帧先查现行清单。此为防重复生产，不授权扩大或缩小任务范围。

## 加工与验算分开

运行旧脚本前核对实际入口与输出：有的 release_preflight.py 会重写PNG和报告，而且不解析命令行参数；不要凭文件名或传入 --report 就当它只读。对已交付包只做只读验算；必须复现加工时复制到临时目录，逐字节比较后再判断，保留原交付证据。

新检查工具默认只读；加工工具明确输出目录和覆盖边界，未知参数应报错。不得手工改报告中的 PASS/ratioGate 来补脚本缺失的判断；分类不适用或逻辑缺失时，说明缺口并补独立检查证据。

QA写明公式与坐标约定：二值 alpha>32 前景点平均、alpha加权平均、bbox中心互不等价；bbox exclusive-end=300 与最末像素行299可同时成立。遇口径冲突先记录两套实测及来源，交PM厘清，不自行换算法、容差或重判历史验收。

镜像至少分两段记录：原始水平翻转的逐像素一致性；最终输出相对翻转图的平移dx/dy及清边diff。最终有5px清理差异就不能简称“最终18/18逐位全等”。记录透明像素/不透明像素变化，报告与对照图指向同一SHA。

集成用精确帧名集合：before − removed + added = after；检查保留帧内容SHA未变化，帧名与清单无重漏。不要用宽泛 left 前缀删除旧 _2，避免补 _1 时误删已交付帧。涉及实际替换仍服从现有两道门与任务授权。

## 发前核清单，发后补回执

artifact_paths 从现行manifest和明确QA/contact文件构造，不从整仓 git status 抽取，也不手抄几十条文件名。列表中的每一项必须是完整仓库相对文件路径，不以目录代替文件。

提交并推送后运行 skill 自带只读工具：

```bash
python3 .codex/skills/art-pipeline-execution/scripts/check_delivery.py --repo . --commit <已推送SHA> --paths-json <清单JSON>
```

JSON输入为路径数组或含 artifact_paths 的对象；输出完整SHA、核验路径、内容hash及错误。工具不证明远端可达、审美/规格通过，不fetch、不提交、不发送消息。使用输出的同一SHA与路径列表构造delivery，发送后记录seq并核对回显；发现运输清单错漏明确发更正单，不重做无问题素材。共享LOG/thread只追加自己的行，不夹带提交其他人的工作；持久交付正文须在提交里，不能只存在总线正文或未提交日志。

## 调研与试产接口

“截图看着握得住”仅是效果目标，不证明内部图层结构；开源复刻不冒充厂商源码，API存在不代表小游戏真机性能通过。先验证最关键假设，再建议铺量；用户已限定零生成时仅交调研和获准示意。

全图RGB频次不等于肤色色板：用于换手/肤色门检时，需要角色手部ROI、采样源SHA、皮肤/袖口/描边语义与色阶。缺项按证据缺口登记，不把文件名 truth 当作验收依据。
