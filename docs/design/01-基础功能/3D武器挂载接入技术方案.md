## 2. 渲染接入

### 2.1 静态网格 draw path（新增，角色蒙皮路径零改动）

- **加载**：`ui/character3d/glb.ts` 新增 `loadCharacter3DStaticMesh(buffer)`：复用 `parseGlb/readAccessor`，要求 **1 mesh / 1 primitive / skins 0（或缺省）/ 无动画 / POSITION+NORMAL+TEXCOORD_0**（JOINTS_0/WEIGHTS_0 必须缺省，出现即 fail——防误挂蒙皮剑）。现役 `loadCharacter3DModel` 的 `skins===1` 硬门**保持原样**（角色解析器不为武器放宽）。
- **程序**：新增独立 weapon program（VS ≈15 行：`gl_Position = uProjection * uModel * vec4(aPos,1.0)`；FS 与角色 FS 同式样：sRGB→线性→`×uTint`→无光照→sRGB×alpha 预乘输出；无光照版**不需要法线与光向**）。角色 skin program 与 FXAA program **零改动**。顶点布局沿用 16 float（joints/weights 填 0，1,457×64B≈93KB，换取与既有 interleave/上传代码同构）。
- **矩阵来源与每帧上传**：`uModel = placement × worldV[R_Hand] × M`。`placement`＝该单位既有摆放矩阵（含 yaw/scale/squash，pass 内 scratch 复用，武器画在**同一单位迭代内**、矩阵内容仍有效）；`worldV[R_Hand]`＝`controller.sample()` 完成后的最终姿态手骨世界矩阵（含交叉淡化，pass.ts 现成 `pose.worldV`）；`M`＝装配期合成的挂点矩阵（§3，常量）。每帧每挂武器单位新增上传：1×mat4（＋受光版另加 1×mat3 法线矩阵，见 §9-拍板2）。CPU 每帧成本 = 2 次 mat4 乘法/单位，可忽略。
- **计数口径**：drawCalls 从「1/单位」变为「1 + 武器段数/挂武器单位」。默认无染色（§5）时武器 **1 段合批 = 1 draw**；四段染色时 4 draw。S1 一把剑：20u 场景 GL 侧 20→21（同批更新对应测试断言与 §7 计数口径说明），性能面在 S0 已证余量内（+1,758 面 ≈ +3.6% 顶点）。
- **资源装配**：weapon VAO/VBO/IBO/texture 在装配期**上传一次、多单位共享**（W7：武器不占角色资产 = 独立资产文件 + 共享 GPU 资源 + 每单位仅矩阵不同）；context lost/restore 走与角色相同的 `buildAll/disposeAll` 生命周期重建。

### 2.2 doubleSided（W8）

管线现状即**全局不开背面剔除**（角色 placement 含 y 翻转、winding 已反，`renderer.buildAll/beginFrame` 显式 `disable(CULL_FACE)`）⇒ 剑自动双面渲染，无破洞。落地动作：① 资产 `doubleSided:true` 记入武器资产门常量与 profile 字段（契约留档）；② 诊断串 `weapon-cull=off` 记录渲染态；③ **红线**：若将来为性能开启剔除，`doubleSided` 资产必须豁免——写进易错点。验收 = 放大截图目视（§7-W8）＋ 深浅双底无缺面截图归档。

### 2.3 遮挡与层序

- **层内（剑×人）**：同一透明人物层、同一深度缓冲（LEQUAL、无混合、不透明写入），先画身体后画剑（顺序无关紧要，深度解算）⇒ 摆动中剑与身体互相遮挡正确（W1「无穿透」的几何前提）。
- **层间（3D 层×2D 层）**：维持主方案 §4.3 口径不变——整张人物层在 hero 的 `depthKey` 槽位**一次 drawImage 合成**；剑随层整体与 2D 敌人前后关系由槽位决定，不做逐像素交叉排序（既有边界，不因剑改变）。
- **FXAA**：剑画在 FXAA 全屏 pass **之前**（层内），自动进入 alpha-aware 抗锯齿。⚠️ 剑身是薄几何——深/浅双底 FXAA 边缘质检必测（风险 R2，§8）。
- **死亡/受击**：`uAlpha` 与所属单位同源（死亡淡出剑随人淡出）；hit 继承当前动作键，剑可见性随继承态（§4），无特判。

## 3. 标定口径

### 3.1 合成顺序（硬约束）与金标准

```
f      = 拳心(R_Hand) + (px,py,pz) × ch          （骨局部；拳心见 3.3）
Q      = q(+Y→+Z) · rotZ(rz) · rotY(ry) · rotX(rx)   （q(+Y→+Z) = 绕+X +90°）
M      = T(f) · R(Q) · S(k) · T(0, −gripY, 0)        k = lenRatio × ch
```

**顺序红线**：`T(0, −gripY, 0)` 必须在 `S(k)` **右侧**（平移量是武器模型单位、不乘 k）——写反即「插多/插少」一个 gripY。这条顺序同时**结构性保证 W4**：`M×握点 = f` 与 k 无关，任何 lenRatio 下握点精确落在拳心偏移点。

**金标准（composer 单测断言，我已逐位复核）**：以 `ch = modelHeight = 0.98107916…`、`lenRatio=0.75`（k=0.735809）、`f=(−0.013632, 0.041, −0.0146)`、`(rx,ry,rz)=(−25°,+80°,−90°)`、`gripY=0.1082` 代入，须在 ≤1e-4 内复现 A4 §3.4 参考矩阵（列主序 16 浮点），并复现四关键点自检：**握点→f 精确成立**、柄头/护手/剑尖三行逐位吻合（我已验算：各列模长 = k、`M·(0,0.1082,0) = f` 精确、剑尖映射与表一致）。**约定差异处理（A4 预警②）**：若我方 `worldV` 骨局部约定与 three.js 推导不同构，以「渲一帧对像素」实测为准修约定，不盲调数字——金标准矩阵用于隔离「合成错」与「约定错」两类问题。

### 3.2 每资产握点与结构化参数真源（W9/W3/W4）

- **真源 = 结构化参数，`localMatrix` = 派生物**：装配期由 composer 合成一次填入既有 `localMatrix` 字段；**禁**手工把 16 浮点写死进配置（金标准单测防回归）。`0.1082` 等**逐资产值只允许出现在武器资产条目**，渲染/加载文件零硬编码（测试做源码扫描）。
- **types.ts 契约扩展**（`CharacterAttachmentProfile` 增可选字段，向后兼容）：

```ts
export interface CharacterAttachmentProfile {
  bone: string;
  assetId: string;
  enabled: boolean;
  localMatrix: readonly number[];              // 派生物（装配期合成），仍是渲染消费面
  // —— T32 新增（武器类挂点）——
  gripLocal?: readonly [number, number, number]; // 握点（武器模型空间，逐资产实测值；W9）
  lenRatio?: number;                             // 0.50~1.20（§7-W4 判据域）
  poseDeg?: { rx: number; ry: number; rz: number }; // 联合定姿三轴（固定顺序 base·Rz·Ry·Rx；W3＝甲：非独立长轴自转轴，Leo 09-15 裁定，见 §7-W3）
  offsetLocal?: readonly [number, number, number];  // 骨局部 (px,py,pz)，×ch 后并入 f
  doubleSided?: boolean;                         // 资产属性留档（W8）
  tints?: { blade: string; guard: string; grip: string; pommel: string }; // #RRGGBB；缺省全白=原贴图
}
```

- **现役条目启用**：`HERO_3D_ATTACHMENTS['right-hand-blade']` 填 `assetId:'sword-3d-medieval'`、`gripLocal:[0,0.1082,0]`、`lenRatio:0.75`、`poseDeg:{rx:-25,ry:80,rz:-90}`、`offsetLocal:[-0.03,0,0]`、`doubleSided:true`、tints 缺省全白（Leo 已批对照图＝原贴图观感）。**校验门同步改**：现 `validateCharacter3DProfile` 对 `enabled:true` 一律报错（素材未过双门不得启用）——改为「enabled ⇒ assetId 非空 + 武器资产门常量齐 + 双门记录在案（Leo 审美=工单 seq=443 已过；规格/技术门=本方案＋Codex 复核）」，缺一仍报错。

### 3.3 「角色身高」定义口径（k 与 f 的 ch）

**`ch := profile.modelHeight`（0.98107916…，模型静止 bbox 高，模型单位）**——与观感台 `window.__charH` 同口径（A4 §三.4 预警①逐字采纳）。**禁用** `screenHeightPxAtReference`（那是像素、且已乘 `CHARACTER_3D_HERO_SCALE`；误用会把 k 放大两个数量级再叠缩放）。缩放应用次序：**屏幕缩放只发生在 placement 一次**（最外层），`k` 在武器模型单位空间，剑随角色同比缩放由矩阵链自然保证（placement 是最左因子），**无任何第二处缩放**（禁双算，写进易错点）。
推论——**未投影标称长**（A5 seq=448 修文字）：`lenRatio × screenHeightPxAtReference` 是把剑当作沿屏幕轴直立时的端点距（0.78 档下 0.75 档 = 0.75×96.096 = 72.07 逻辑像素，0.5/1.2 档 48.05/115.32）。该值**只作量级 sanity 与档位间比例参考，不是屏幕测长判据**——实际屏幕长度随当前姿态与投影变化（握持角、挥动、侧向都使端点投影偏离标称），三档长度验收按 §7-W4 的「同姿态投影端点比例线性」执行，禁拿任意屏幕 bbox 硬对 72.07px。

### 3.4 拳心（W2；变换口径 A5 已裁「取甲」）

沿观感台 `fistCenterLocal` 口径移植为装配期一次计算：蒙皮网格中「主骨（权重最大者）= R_Hand 且权重 > 0.5」的顶点重心，换算到 R_Hand 局部坐标——**现模型实测 551 顶点、局部 (0.0158, 0.041, −0.0146)**，绑定姿势下算一次缓存（rest 时几何=绑定姿势；实现上用 `resetPose+resolvePose` 的 rest 姿态取顶点，模式与 pass.ts 现有 restWorldT 装配期解析相同）。**禁用骨节点原点**（那是手腕）。**禁逐帧求**（装配期常量）。若换模型/换骨名，装配期 `jointNames.indexOf('R_Hand')` 找不到即 fail-fast，不静默空挂。
**变换公式（A5 seq=448 裁「取甲」）**：绑定顶点（模型空间）→ R_Hand 局部用**本管线的** `inv(handRestWorld)`（rest 世界阵求逆），不复刻观感台的 Armature 节点链换算；两者差值用独立公式对拍（实测 ≈0.04px，美术 PM 已接受该约定，不阻塞）。A4 同输入参考矩阵仍须**精确**复现（金标准不放宽）——不得以放宽容差掩盖约定差。

## 4. 状态与收剑（W6）——技术源裁定 + 一处拍板

**技术源（本方案裁定）**：可见性读 **`CharacterAnimController` 解析后的有效动作键**（`actionKey` getter，现成）——它已含轻功闩锁（jump move 期间快照 `animState='walk'`，**读快照必错**：剑会在轻功里画出来）与 hit 继承态。pass 在 `controller.update()` 之后、同一迭代内取键查规则表，规则表在 config（禁散落渲染文件）。`CharacterRenderCommand` 契约**零改动**。

**映射语义存在规格级两读，进拍板节（§9-拍板1），发实现卡前必须裁定**：W6 判据「run/jump 不可见；idle/atk/cast/walk 可见」写于观感台语境（walk 与 run 是两个动作）；现役游戏把 walk 槽位改播 run 资产（Leo 09-11 口径），两条字句不可同时满足——按 clip 名则走路也收剑（「walk 可见」失字面），按槽位键则移动持剑（「run 不可见」失字面）。本方案**推荐甲**（见 §9），实现卡在拍板前**不发**。

## 5. 换色/分段（W5）

- **切分**：装配期按三角形重心 Y 切 4 段（段界 = 离柄头端比例 **6% / 20% / 27%**：剑首｜柄｜护手｜剑身），4 个索引段共享同一 VBO（顶点零复制，仅索引重排——观感台 `splitSwordMesh` 逐点复制是 three.js 语境，本管线不需要）。
- **染色**：每段一次 draw，`uTint`（线性空间 vec3，#RRGGBB→线性）× 贴图基色，保留明暗只换色调——即观感台「材质色 × 贴图」语义；**不改 UV 区**（串色根因 A4 已述，易错点收录）。
- **默认无染色**：四段全白 ⇒ 合为 1 draw（索引合并、uTint=白），剑即 Leo 已批的原贴图观感；染色组是装备系统配置项（规格 §6 `WeaponSkin` 契约，本卡只实现能力 + W5 验收用一组测试配色，不动装备系统 UI）。
- **draw call 账**：无染色 1、染色 4（§2.1）。

## 6. 与既有系统的关系
