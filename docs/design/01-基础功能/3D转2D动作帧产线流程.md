# 3D→2D 动作帧产线流程（定稿）· 2026-09-11 · PM2

> 本文记录 **2026-09-11 当天打通的完整产线**：从 Tripo3D 生成 3D 文件 → 外部动作 → 渲染关键帧 → 成品 PNG。
> **定位**：这是**可复现的操作手册**。理论上跑通后**关键帧产出不需要人工介入**，但流程与命令仍完整落盘，供后续批产/交接/排障使用。

---

## 〇、一句话总览

```
[1] 图 → 3D 模型（Tripo 网页，Leo 手动）
[2] 3D 模型 + 动作文件 → 给我
[3] 重定向（把外部动作搬到我们的模型上）
[4] 渲染（4× 超采样，近平涂着色）
[5] 后处理（描边 + 调色板量化 + 去斑）
[6] 挑关键帧（5 帧）
[7] 导出 PNG（运行时命名）
        ↑ 全自动，0 积分
```

**分界线**：`[1]` 和 `[2]` 需要人（网页操作 / 下载动作）；**`[3]`~`[7]` 是脚本全自动，0 积分。**

## 一、准备素材（人工，两步）

### 1.1 生成 3D 模型（Leo 在 Tripo 网页操作）

| 要点 | 说明 |
|---|---|
| 输入图 | **正面站立全身图**（`assets/_trial_20260911/tripo_front_input*/` 有备好的） |
| 手臂 | **双手向外张开约 45°**（A-pose）——**这是硬要求**：手臂贴身体会导致绑骨失败 |
| 头部 | **造型尽量简化**（马尾缩短、发冠简洁、刘海去碎发）——复杂头发转 2D 后侧视会糊成一团 |
| 面数 | **5~10 万**即可（成品只有 144×256px，高面数在成品里看不出来） |
| 导出 | **GLB**（Tripo 网页 → 导出） |

> 实测结论：A-pose + 简化头部 → 模型的手臂能完全分离、侧视头型清晰。

### 1.2 下载动作（Leo 在 Mixamo 网页）

| 要点 | 说明 |
|---|---|
| 格式 | **优先 Collada (.dae)** → 其次 **FBX ASCII** → FBX Binary 也能用（但坑最多） |
| 设置 | 勾 **Without Skin**（只要骨架+动作，不要模型） |
| 给谁 | 把文件路径给 PM2 |

> **为什么优先 Collada**：它直接给「每骨骼每帧的 4×4 矩阵」，没有**欧拉角顺序、轴朝向、名称编码**这三类歧义（FBX Binary 三样全占，我踩过）。

### 1.3 ⚠️ 选源动作：必须量源自己的数，不能看名字（2026-09-12 立）

**成品站姿 = 源动作站姿**（重定向只做姿态搬运，不会"站得更直"）。而 Mixamo 里名字最像的那个往往不是要的那个：

| 源 | 名字像不像 | 源膝弯（左/右） | 大腿离垂直 | 源髋高 | 渲染后脚底 y |
|---|---|---|---|---|---|
| `Standing Idle` | **最像** | 48.0° / 57.2° | 48.4° / 32.5° | 82.1 | **296**（脚离地 11px） |
| `Orc Idle` | **最不像**（角色也不搭） | **31.9° / 30.5°** | **19.8° / 19.7°** | **93.4** | **306**（正确） |

> 源叫 "Orc" 不影响适配：Mixamo 动作与角色无关，**Without Skin** 只取骨架+动作。

**选源四判据（下单前先量，直立站立应满足）**：

1. **源膝弯 ≤ ~35°**（直立应 0~10°，但 Tripo 模型 rest 本身也有弯度，实测 30~35° 渲出来已接近 rest）
2. **左右对称**：左右膝弯差 ≤ ~3°（Standing Idle 差 9.2° = 歪着站）
3. **源髋高不异常低**（越低=蹲得越深）
4. **渲染后脚底 y 接近 rest 基准线 307**（差 ≤ 5px 为佳）——这条是最终判据，前三条是快速筛选

判据一次性成本极低：`.dae` 解析后算 `腿段夹角`，几秒钟出数。**不要靠"名字像"或"看起来应该行"下单。**

## 二、重定向（脚本，全自动）

**目的**：把外部骨架的动作，搬到我们模型的骨架上。

### 2.1 工具选择（按输入格式）

| 输入格式 | 工具 | 状态 |
|---|---|---|
| **Collada (.dae)** | `tools/glb2d/collada2anim.mjs` | ✅ 首选 |
| **FBX (.fbx)** | `tools/glb2d/fbx2anim.mjs` | ✅ 可用 |
| **BVH**（CMU 动捕库） | `tools/glb2d/retarget.mjs` | ✅ 可用 |

### 2.2 命令

```bash
# Collada（推荐）。默认 mode=aim3（2026-09-12 起；aim2 有缺陷，见 §2.3）
node tools/glb2d/collada2anim.mjs <模型.glb> <动作.dae> <输出.json> --fps 30 --root y

# FBX
node tools/glb2d/fbx2anim.mjs    <模型.glb> <动作.fbx> <输出.json> --fps 30 --root y

# BVH（CMU）
node tools/glb2d/retarget.mjs    <模型.glb> <动作.bvh> <输出.json> --frames 120 --fps 30 --root y
```

### 2.3 算法（两段式，`--mode aim3`，默认）

```
① 先用「源的完整世界旋转增量」 delta = Sa × Sr⁻¹
   → 得到带正确扭转的朝向
② 再做「最小旋转」把目标骨骼指向拧到源骨骼指向
   → 校正两套骨架的 rest 差异
```

**为什么不只用矩阵相对量**：Mixamo 骨架 rest 是 **T-pose**（上臂方向朝下），我们模型 rest 是 **A-pose**（手臂朝侧面），**两者差约 85°**，且**每根骨骼的局部轴朝向都不同**（差 15°~173°）。纯矩阵相对量公式全部失效。

**为什么不能只做方向匹配（纯 aim）**：那只约束「骨骼指向」，**绕骨骼自身轴的扭转是任意的** → 头朝向/脚尖朝向帧间乱跳。

#### ⚠️ aim2 vs aim3：唯一差别 = 「骨骼指向」的定义（09-12 修缺陷 BUG-13）

| | 源侧参照 | 目标侧参照 |
|---|---|---|
| **aim2（旧，已废）** | `子骨骼位置 − 自身位置` | `自身位置 − 父骨骼位置` |
| **aim3（现行）** | **骨骼自身世界 Y 轴** | **骨骼自身世界 Y 轴** |

aim2 两侧**不同源**，只在「子骨骼正好落在骨骼末端」时等价。实测 22 根映射骨里**有 5 根不等价**：`Head` 25.78°、`NeckTwist01` 16.92°、`Hip` 50.65°、`L_Hand` 71.72°、`R_Hand` 48.14°（其余 17 根 ≤0.06°）。两处具体病灶：

1. **Head**：Mixamo 的 `HeadTop_End` 不在头骨 Y 轴上（差约 26°），而模型 Head 是**叶子骨**、参照退化成「父→自身」＝头骨 Y 轴本身 → 头被**恒定多拧 25.78°**，画面表现＝**"莫名其妙低头"**（轻功同病，Leo 09-12 指出）。
2. **Hip**：`Waist − Hip` 实测长度 **0.0000**（Tripo 绑定里 Waist 与 Hip 同位置）→ 参照是零向量 → `hypot(curDir) > 1e-9` 的守卫**静默跳过修正**，Hip 保持自身 rest 朝向，身体整体偏 50.65°。

aim3 对**本来正确的 17 根骨零影响**（两定义等价时夹角为 0），改动面精确等于出问题的那 5 根。修后 idle 22/22 根骨残差 **0.00°**。

> **影响范围**：只有走 `collada2anim` 的产物受影响（idle、轻功）。`walk`/`run` 是模型自带动画（`preset:biped:*`，不经重定向）→ 不受影响；`retarget.mjs`(BVH) 与 `fbx2anim.mjs` 不含该 aim 逻辑 → 不受影响。
> **09-11 交付的轻功 30 帧带此缺陷**，已用 aim3 重渲（`assets/_trial_20260912/glb2d_jump/`）。

### 2.4 ⚠️ 必过的校验（**先看数，再看图**）

**① 逐骨朝向残差（09-12 新增，机械判据，最硬）**

对每根映射骨，量「重定向件某帧的世界 Y 轴」与「源同帧的世界 Y 轴」的夹角：

```
判据：22 根映射骨 全部 == 0.00°（容差 0.05°）
```

这是**唯一能直接抓 BUG-13 这类"某个参照取错"缺陷**的判据。帧 0 校验、火柴人对比图**都拦不住它**
（帧 0 校验只比源自己 rest vs 源自己帧 0；火柴人图上头 25° 的偏差被躯干四肢的大位移掩盖）。

**② 帧 0 必须等于模型自身的 rest（容差 5°）**——`collada2anim / fbx2anim` 自报。

**③ 火柴人对比图**（把源动作与重定向结果画成骨架并排，逐帧对齐）——
**每个动作交付前必看这张图**。用于快速发现「帧序错乱 / 头脚朝向错」。

> **教训（BUG-13）**：门检项必须覆盖**本次改动的目的项本身**。"姿态对不对"是重定向的唯一目的，
> 而旧门检查的却是「源自己 vs 源自己」「整体形状像不像」——于是全绿与达标完全脱钩。

### 2.5 已知边界

| 项 | 说明 |
|---|---|
| 手指 | **动不了**（模型无手指骨），手保持握拳 |
| 根位移 | 默认只取 **Y（上下）**；需要水平位移用 `--root xz`（注意会跑出画布） |
| 反关节 | 若源动作夸张（跳跃/翻滚），个别帧可能轻微反关节——需目验 |
| 比例 | 骨骼长度比例不同 → 姿态有 ~10° 残差，属正常 |

## 三、渲染（脚本，全自动）

### 3.1 命令（单帧）

```bash
node tools/glb2d/render.mjs <模型.glb> <输出.raw> <W> <H> \
     <动画序号|none> <时间秒> <着色模式> <贴图.raw> <texW> <texH> <yaw> [aux前缀] [动画JSON]
```

**关键参数**：

| 参数 | 取值 | 说明 |
|---|---|---|
| 宽高 | **960 1280**（= 目标 240×320 的 **4×**） | 必须超采样 |
| 着色 | **`flatcel`** | 近平涂（亮度压 0.86~1.00），画风才像手绘 |
| yaw | 见 §3.4 方向映射 | |
| aux前缀 | 给 `.depth` / `.normal` 落盘（后处理要用） | |
| 动画JSON | 留空则用模型自带动画；填路径则用重定向结果 | |

### 3.2 三条硬规则（都踩过坑）

| 规则 | 原因 |
|---|---|
| **必须 4× 超采样** | 直接渲 240×320 锯齿无法消除 |
| **贴图必须双线性** | 2048² 贴图渲到 256px 人物，最近邻会导致噪点/花斑/脏边 |
| **必须固定机位** | 每帧各自拟合包围盒会**把上下位移整个抵消**（跳跃完全看不出起跳） |

### 3.3 贴图提取（从 GLB 里抽）

```bash
# GLB 内嵌贴图 → 导出 baseColor → 转裸 RGBA
# 见当天脚本：解 GLB 的 images[].bufferView → 存 jpg → resize 2048 → tobytes()
```

### 3.4 方向映射（**实测确定，勿凭感觉**）

| 我们的方向 | yaw | 判据 |
|---|---|---|
| **左下 leftdown** | **225** | 脸心−发心 Δx = −17.6（对照我们帧 −17.1） |
| 右下 rightdown | 315 | 镜像 |
| 左 left | 270 | Δx = −22.4 |
| 右 right | 90 | Δx = +23.8 |
| 正下（正面） | 180 | Δx = −6.1、肤色最多 |
| 正上（背面） | 0 | 肤色最少 |

> **判据**：量「脸部肤色块质心 − 头发暗块质心」的横向偏移 Δx，脸偏画面左＝人朝左。
> **不要目测判断方向**——本项目已多次因此出错。

## 四、降采样（脚本，全自动）

```bash
node tools/glb2d/downsample.mjs <in.raw> <in.depth> <in.normal> <out前缀> <inW> <inH> <倍率>
# 例：... /tmp/r1 960 1280 4
```

**箱式滤波**：颜色按 alpha 加权（背景不污染边缘）、深度/法线一并降采样。

## 五、后处理（脚本，全自动）

```bash
node tools/glb2d/postprocess.mjs <in.raw> <in.depth> <in.normal> <out.raw> <W> <H> \
  --palette 16 --outline 1 --depth-thresh 0.08 --normal-thresh 0.95 \
  --chroma-blur 0 --speckle 1
```

### 参数含义与标定理由

| 参数 | 值 | 说明 |
|---|---|---|
| `--palette` | 16 | **k-means 调色板量化**（**不要用逐通道取整**——那样会改色相，棕变红） |
| `--outline` | 1 | 描边宽度（外轮廓可加粗、体内线条固定 1px） |
| `--depth-thresh` | 0.08 | **绝对深度差**（**不要用相对深度差**——深度跨零点时分母趋零，会把 86% 像素判成边缘、人物涂黑） |
| `--normal-thresh` | 0.95 | 法线突变阈值。**调高可避免把发丝/衣褶等细纹理也描出来**（否则头发呈"铁丝网"） |
| `--chroma-blur` | 0 | 色度降噪（如需可开 1） |
| `--speckle` | 1 | 去斑（清掉孤立彩色单像素） |

**边缘检测三源**：外轮廓（alpha 边界）+ 深度不连续 + 法线突变。

## 六、挑关键帧（脚本，全自动）

```bash
python3 tools/glb2d/select_keyframes.py <帧目录> <输出目录> <K>
```

**算法 = 贪心最远点采样**：
```
① 必留首帧与末帧
② 每次新增「到已选集合的最小距离」最大的那帧
距离 = alpha 形状差 + 0.35 × RGB 颜色差
```

**为什么不用「均匀每 N 帧取一张」**：会**漏掉极值帧**（下蹲最低点、腾空最高点）——恰好是动作最有表现力的两帧。

**实测覆盖度**（26 帧源）：K=3 → 8448 ｜ **K=5 → 6816** ｜ K=8 → 4359（越小覆盖越好）

## 八、批量导出脚本（一条命令跑全套）

```bash
# 方向 × 帧数 全套（渲染→降采样→后处理）
tools/glb2d/export_frames.sh <glb> <tex.raw> <texW> <texH> <outDir> \
                              <动画序号|none> <时长秒> <帧数> <超采样倍率> <yaw...>
```

> ⚠️ **脚本内部必须用 zsh 数组传后处理参数**（`PP=(--a 1 --b 2)` 而非 `PP="--a 1 --b 2"`）。
> zsh 默认不对未加引号的变量做词分割 → `$PP` 会被当成**一整个参数** → 脚本匹配不到 `--flag` → **静默用默认值**（本项目已踩：批跑产物带彩色噪点）。

## 九、规格定稿（Leo 09-11 拍板）

| 项 | 值 |
|---|---|
| **帧数** | **5 帧/动作**（每方向） |
| **播放速度** | **220 ms/帧**（总 1100ms） |
| 画布 | 240×320 RGBA（全游戏统一） |
| 方向 | 六向 |
| 相机 | 固定机位 |
| 包体 | 5 帧 ≈ 193KB；**PNG-8 可到 ~10KB/帧**（项目已定方案） |

**速度规范**：`每帧时长 = 源动作时长 ÷ 帧数`（等时长档），再按观感微调并记录理由。
> 理由：压帧后若不重算，会**偷偷快放**（实测：源 833ms 压 5 帧给 110ms/帧 = 550ms，等于快放 1.5 倍）。

## 十一、已知遗留

1. **本批 `Jumping Up` 源动作没有下降段**（髋高 96.9→55.5→153.7，停在最高点）→ 落地是重排凑的。**要真实下落需另找含落地的动作**（Mixamo `Falling`/`Landing`/`Jump`）。
2. **CMU 行走/剑术需用 aim2 重跑**（此前是纯 aim，有扭转偏差）。
3. **既有六方向/行走/跑步需重跑**（渲染器改固定机位后，旧产物含位移抵消问题）。
