# 3D→2D 动作帧产线流程（定稿）· 2026-09-11 · PM2

> 本文记录 **2026-09-11 当天打通的完整产线**：从 Tripo3D 生成 3D 文件 → 外部动作 → 渲染关键帧 → 成品 PNG。
> **定位**：这是**可复现的操作手册**。理论上跑通后**关键帧产出不需要人工介入**，但流程与命令仍完整落盘，供后续批产/交接/排障使用。

---

## 〇、一句话总览

```
[1] 图 → 3D 模型（Tripo 网页，Leo 手动）
[2] 3D 模型 + 动作文件 → 给我
[3] 重定向（把外部动作搬到我们的模型上）
[4] 渲染（4× 超采样，近平涂着色）
[5] 后处理（描边 + 调色板量化 + 去斑）
[6] 挑关键帧（5 帧）
[7] 导出 PNG（运行时命名）
        ↑ 全自动，0 积分
```

**分界线**：`[1]` 和 `[2]` 需要人（网页操作 / 下载动作）；**`[3]`~`[7]` 是脚本全自动，0 积分。**

## 一、准备素材（人工，两步）

### 1.1 生成 3D 模型（Leo 在 Tripo 网页操作）

| 要点 | 说明 |
|---|---|
| 输入图 | **正面站立全身图**（`assets/_trial_20260911/tripo_front_input*/` 有备好的） |
| 手臂 | **双手向外张开约 45°**（A-pose）——**这是硬要求**：手臂贴身体会导致绑骨失败 |
| 头部 | **造型尽量简化**（马尾缩短、发冠简洁、刘海去碎发）——复杂头发转 2D 后侧视会糊成一团 |
| 面数 | **5~10 万**即可（成品只有 144×256px，高面数在成品里看不出来） |
| 导出 | **GLB**（Tripo 网页 → 导出） |

> 实测结论：A-pose + 简化头部 → 模型的手臂能完全分离、侧视头型清晰。

### 1.2 下载动作（Leo 在 Mixamo 网页）

| 要点 | 说明 |
|---|---|
| 格式 | **优先 Collada (.dae)** → 其次 **FBX ASCII** → FBX Binary 也能用（但坑最多） |
| 设置 | 勾 **Without Skin**（只要骨架+动作，不要模型） |
| 给谁 | 把文件路径给 PM2 |

> **为什么优先 Collada**：它直接给「每骨骼每帧的 4×4 矩阵」，没有**欧拉角顺序、轴朝向、名称编码**这三类歧义（FBX Binary 三样全占，我踩过）。

### 1.3 ⚠️ 选源动作：必须量源自己的数，不能看名字（2026-09-12 立）

**成品站姿 = 源动作站姿**（重定向只做姿态搬运，不会"站得更直"）。而 Mixamo 里名字最像的那个往往不是要的那个：

| 源 | 名字像不像 | 源膝弯（左/右） | 大腿离垂直 | 源髋高 | 渲染后脚底 y |
|---|---|---|---|---|---|
| `Standing Idle` | **最像** | 48.0° / 57.2° | 48.4° / 32.5° | 82.1 | **296**（脚离地 11px） |
| `Orc Idle` | **最不像**（角色也不搭） | **31.9° / 30.5°** | **19.8° / 19.7°** | **93.4** | **306**（正确） |

> 源叫 "Orc" 不影响适配：Mixamo 动作与角色无关，**Without Skin** 只取骨架+动作。

**选源四判据（下单前先量，直立站立应满足）**：

1. **源膝弯 ≤ ~35°**（直立应 0~10°，但 Tripo 模型 rest 本身也有弯度，实测 30~35° 渲出来已接近 rest）
2. **左右对称**：左右膝弯差 ≤ ~3°（Standing Idle 差 9.2° = 歪着站）
3. **源髋高不异常低**（越低=蹲得越深）
4. **渲染后脚底 y 接近 rest 基准线 307**（差 ≤ 5px 为佳）——这条是最终判据，前三条是快速筛选

判据一次性成本极低：`.dae` 解析后算 `腿段夹角`，几秒钟出数。**不要靠"名字像"或"看起来应该行"下单。**

## 二、重定向（脚本，全自动）

**目的**：把外部骨架的动作，搬到我们模型的骨架上。

### 2.1 工具选择（按输入格式）

| 输入格式 | 工具 | 状态 |
|---|---|---|
| **Collada (.dae)** | `tools/glb2d/collada2anim.mjs` | ✅ 首选 |
| **FBX (.fbx)** | `tools/glb2d/fbx2anim.mjs` | ✅ 可用 |
| **BVH**（CMU 动捕库） | `tools/glb2d/retarget.mjs` | ✅ 可用 |

### 2.2 命令

```bash
# Collada（推荐）。默认 mode=aim4（2026-09-12 起；aim2/aim3 各有缺陷，见 §2.3）
node tools/glb2d/collada2anim.mjs <模型.glb> <动作.dae> <输出.json> --fps 30 --root y

# FBX
node tools/glb2d/fbx2anim.mjs    <模型.glb> <动作.fbx> <输出.json> --fps 30 --root y

# BVH（CMU）
node tools/glb2d/retarget.mjs    <模型.glb> <动作.bvh> <输出.json> --frames 120 --fps 30 --root y
```

### 2.3 算法（两段式，`--mode aim4`，默认）

```
① 先用「源的完整世界旋转增量」 delta = Sa × Sr⁻¹
   → 得到带正确扭转的朝向
② 再做「最小旋转」把目标骨骼指向拧到源骨骼指向
   → 校正两套骨架的 rest 差异
```

**为什么不只用矩阵相对量**：Mixamo 骨架 rest 是 **T-pose**（上臂方向朝下），我们模型 rest 是 **A-pose**（手臂朝侧面），**两者差约 85°**，且**每根骨骼的局部轴朝向都不同**（差 15°~173°）。纯矩阵相对量公式全部失效。

**为什么不能只做方向匹配（纯 aim）**：那只约束「骨骼指向」，**绕骨骼自身轴的扭转是任意的** → 头朝向/脚尖朝向帧间乱跳。

#### ⚠️ 三种模式 = 三种「骨骼指向」定义（09-12 修缺陷 BUG-13，两次迭代）

| 模式 | 源侧参照 | 目标侧参照 | 结论 |
|---|---|---|---|
| **aim2**（旧，废） | 非叶子骨：`子−自身`；叶子骨：`父→自身` | 非叶子骨：`子−自身`；叶子骨：`父→自身` | ❌ **Head 差 25.78°**（源用 `Head→HeadTop_End` 出向、目标用 `Neck→Head` 入向，指向**语义不同**）＋ **Hip 参照长度 0.0000** → 守卫静默跳过 |
| **aim3**（中间版，废） | 一律**骨骼自身 Y 轴** | 一律**骨骼自身 Y 轴** | ❌ **Neck 差 16.92°**——源 Mixamo 的 `Neck` 骨轴与它到 `Head` 的**实际位移**差 16.92°，只用 Y 轴会让**头关节多偏 16.9°** → 观感**「往后仰」**（Leo 09-12 二次目视发现） |
| **aim4**（现行） | 有非退化子骨骼位移 → `子−自身`；否则 → 自身 Y 轴 | **同左（同一根骨两侧必须同口径）** | ✅ 22/22 骨残差 **0.000°**（同一判据下 aim2 差 71.72°、aim3 差 16.92°） |

**判据「用子骨骼位移还是用 Y 轴」必须对同一根骨的两侧取同一个答案**，否则就回到 aim2 的老病。
退化有两种：①**叶子骨**（无子骨骼）②**子骨骼与自身同位置**（本项目 `Hip→Waist` 长度为 0.0000）。
两种情况都改用「骨骼自身 Y 轴」（那是骨骼朝向，也是叶子骨唯一能被自身旋转影响的方向）。

> **为什么不能只用 Y 轴（aim3 的教训）**：Y 轴是**骨骼朝向**，而关节**位置**由「子骨骼位移」决定。
> 源骨架若「骨轴 ≠ 子骨骼位移」（Mixamo 的 Neck 就差 16.92°），只用 Y 轴会让关节位置系统性偏掉——
> 位置偏差在画面上表现为**姿态怪**（本例＝头被拉后 → 看着往后仰），而不是"某根骨转错"。
> **两侧同口径 ≠ 一定对；还要选对「哪一个量」当口径。**

**影响范围**：只有走 `collada2anim` 的产物受影响（本项目＝idle、轻功）。`walk`/`run` 是模型自带动画
（`preset:biped:*`，不经重定向）→ 不受影响；`retarget.mjs`(BVH) 与 `fbx2anim.mjs` 不含该 aim 逻辑 → 不受影响。
**09-11 交付的轻功 30 帧、09-12 上午的 idle 都带缺陷**，均已用 aim4 重渲。

### 2.3b ⚠️ 渲染投影的左右手性（09-12 定案，BUG-16）

**重定向本身没有问题**；出问题的是**渲染器的投影是左右镜像的**。凡"左右不对称"的动作都会反
（攻击挥砍手上错侧、侧向视图其实把角色另一侧翻过来）。

**判据（一行数学，成本近乎零）**：相机右向量 = `forward × up`。

- 实测相机在**世界 −Z** 侧（`yaw=0` 只见后脑、`yaw=180` 见整张脸；深度缓冲证 +Z 是"远"）⇒
  相机右向量 = `(0,0,1)×(0,1,0) = (−1,0,0) = −X`
- 而原式 `screen_x = W/2 + (q[0]−cx)·scale` 用 **+X** ⇒ 屏幕右 = 相机的"左" ⇒ **镜像**

**修法（已落）**：`toScreen` 的 x 项**取负**；因侧向朝向跟着翻，**方向表 yaw 左右对调**
（`270↔90 / 225↔135 / 315↔45`）。修后 3D `left/right` 的朝向与 runtime 2D 素材**同向**。

> **校验口径**：拿 runtime 2D 帧当参照，量「脸心 − 体心」的横向符号，比左右向是否与 2D 一致。
> **对称动作（idle/jump 等）发现不了镜像——必须用不对称动作或与真值素材比。**

### 2.3c ⚠️ 源动作时长要与帧数匹配（09-12 立，施法连招事故）

**5 帧能完整表达的是「约 1~1.5s 的单一招式」。** 拿长动作去压 5 帧，动作信息量必然散架。

| 源 | 时长 | 5 帧相邻之间的姿势跳变（平均） | 结果 |
|---|---|---|---|
| Sword And Shield Slash（单招） | 1.50 s | 12 / 21 / 11 / 18° | ✅ 可用 |
| One Hand Sword Combo（**连招**）| **4.53 s** | **17 / 16 / 24 / 25°** | ❌ 目视「胸部明显扭屈」 |
| idle（长但几乎不动） | 6.63 s | 0.8 ~ 1.4° | ✅ 可用 |

**判据（下单前可算）**：`相邻采样帧的骨轴平均变化 ≤ ~20°`。超了就会出现"换帧时躯体在跳/扭"。
**做法**：①优先选**单一招式**（1~1.5s）的源；②若只有长动作，**只取其中一段**（如连招的第一段）采 5 帧；
③连招＝多个招式首尾相接，**不要整段压 5 帧**。

> 注意：这一项**门检抓不到**（逐骨朝向残差全绿、姿态也忠实），**只有播起来才看得出来**——
> 所以交付前要看 GIF，不能只看单帧。

### 2.4 ⚠️ 必过的校验（**先看数，再看图**）

**① 逐骨朝向残差（09-12 新增，机械判据，最硬）**

对每根映射骨，量「重定向件某帧的世界 Y 轴」与「源同帧的世界 Y 轴」的夹角：

```
判据：22 根映射骨 全部 == 0.00°（容差 0.5°）—— 口径与 aim4 一致（有子骨骼位移用位移、叶子骨用 Y 轴）
```

这是**唯一能直接抓 BUG-13 这类"参照取错"缺陷**的判据。帧 0 校验、火柴人对比图**都拦不住它**
（帧 0 校验只比源自己 rest vs 源自己帧 0；火柴人图上头 25° 的偏差被躯干四肢的大位移掩盖）。
工具：`node tools/glb2d/qa_retarget_bones.mjs <模型.glb> <源.dae> <retarget.json>`（退出码可当门）。

**② 帧 0 必须等于模型自身的 rest（容差 5°）**——`collada2anim / fbx2anim` 自报。

**③ 火柴人对比图**（把源动作与重定向结果画成骨架并排，逐帧对齐）——
**每个动作交付前必看这张图**。用于快速发现「帧序错乱 / 头脚朝向错」。

> **教训（BUG-13）**：门检项必须覆盖**本次改动的目的项本身**。"姿态对不对"是重定向的唯一目的，
> 而旧门检查的却是「源自己 vs 源自己」「整体形状像不像」——于是全绿与达标完全脱钩。

### 2.5 已知边界

| 项 | 说明 |
|---|---|
| 手指 | **动不了**（模型无手指骨），手保持握拳 |
| 根位移 | 默认只取 **Y（上下）**；需要水平位移用 `--root xz`（注意会跑出画布） |
| 反关节 | 若源动作夸张（跳跃/翻滚），个别帧可能轻微反关节——需目验 |
| 比例 | 骨骼长度比例不同 → 姿态有 ~10° 残差，属正常 |

## 三、渲染（脚本，全自动）

### 3.1 命令（单帧）

```bash
node tools/glb2d/render.mjs <模型.glb> <输出.raw> <W> <H> \
     <动画序号|none> <时间秒> <着色模式> <贴图.raw> <texW> <texH> <yaw> [aux前缀] [动画JSON]
```

**关键参数**：

| 参数 | 取值 | 说明 |
|---|---|---|
| 宽高 | **960 1280**（= 目标 240×320 的 **4×**） | 必须超采样 |
| 着色 | **`flatcel`** | 近平涂（亮度压 0.86~1.00），画风才像手绘 |
| yaw | 见 §3.4 方向映射 | |
| aux前缀 | 给 `.depth` / `.normal` 落盘（后处理要用） | |
| 动画JSON | 留空则用模型自带动画；填路径则用重定向结果 | |

### 3.2 三条硬规则（都踩过坑）

| 规则 | 原因 |
|---|---|
| **必须 4× 超采样** | 直接渲 240×320 锯齿无法消除 |
| **贴图必须双线性** | 2048² 贴图渲到 256px 人物，最近邻会导致噪点/花斑/脏边 |
| **必须固定机位** | 每帧各自拟合包围盒会**把上下位移整个抵消**（跳跃完全看不出起跳） |

### 3.3 贴图提取（从 GLB 里抽）

```bash
# GLB 内嵌贴图 → 导出 baseColor → 转裸 RGBA
# 见当天脚本：解 GLB 的 images[].bufferView → 存 jpg → resize 2048 → tobytes()
```

### 3.4 方向映射（**实测确定，勿凭感觉**）

| 我们的方向 | yaw | 判据 |
|---|---|---|
| **左下 leftdown** | **225** | 脸心−发心 Δx = −17.6（对照我们帧 −17.1） |
| 右下 rightdown | 315 | 镜像 |
| 左 left | 270 | Δx = −22.4 |
| 右 right | 90 | Δx = +23.8 |
| 正下（正面） | 180 | Δx = −6.1、肤色最多 |
| 正上（背面） | 0 | 肤色最少 |

> **判据**：量「脸部肤色块质心 − 头发暗块质心」的横向偏移 Δx，脸偏画面左＝人朝左。
> **不要目测判断方向**——本项目已多次因此出错。

### 3.5 ★ 地面锁定（09-12 立，Leo 叮嘱「注意身高问题」）

**问题**：渲染器把**髋关节钉在模型 rest 的髋高**上（为了固定机位，见 §3.2）——副作用是**腿一弯脚就抬起来**。
同一套重定向下实测：idle（直腿，源髋−踝 84.9）脚底在 **307**；攻击（屈膝，源髋−踝 64.8）脚底在 **298**。
而**游戏现行 61 张 hero 帧的末实体行全部是 299**（`assets/characters/hero/battle45/`；
与 `config/battle-hex.ts` 注释「battle45 y=300 同口径」一致）→ 不锁定就会**切动作时上下跳 8~20px**。

**判据**：**一个动作里脚底最深的那一帧 = 地面接触帧 = 该动作的地面**
（跳跃类同理：空中帧的"最低点"比接触帧高，取最深即取落地/蹲踞帧）。

```bash
# 先干跑看要平移多少，再实跑；然后必须重跑 PNG-8 编码
python3 tools/glb2d/ground_lock.py <帧目录> "<通配>.png" --target 299 --dry
python3 tools/glb2d/ground_lock.py <帧目录> "<通配>.png" --target 299
python3 tools/glb2d/png8_encode.py <帧目录> <帧目录>
```

**09-12 实测平移量**：idle **−8** ／ run **−20** ／ jump **−14** ／ atk **0**（本就在线上）。
平移是**整动作一个常数**（保动作内部的上下位移），不是逐帧对齐。

> ⚠️ `ground_lock.py` 会把 PNG 落成 RGBA → **必须紧跟一次 `png8_encode.py`**，否则包体会从 12KB/帧 涨回 28KB/帧。

node tools/glb2d/downsample.mjs <in.raw> <in.depth> <in.normal> <out前缀> <inW> <inH> <倍率>
# 例：... /tmp/r1 960 1280 4

**箱式滤波**：颜色按 alpha 加权（背景不污染边缘）、深度/法线一并降采样。

## 五、后处理（脚本，全自动）

```bash
node tools/glb2d/postprocess.mjs <in.raw> <in.depth> <in.normal> <out.raw> <W> <H> \
  --palette 16 --outline 1 --depth-thresh 0.08 --normal-thresh 0.95 \
  --chroma-blur 0 --speckle 1
```

### 参数含义与标定理由

| 参数 | 值 | 说明 |
|---|---|---|
| `--palette` | 16 | **k-means 调色板量化**（**不要用逐通道取整**——那样会改色相，棕变红） |
| `--outline` | 1 | 描边宽度（外轮廓可加粗、体内线条固定 1px） |
| `--depth-thresh` | 0.08 | **绝对深度差**（**不要用相对深度差**——深度跨零点时分母趋零，会把 86% 像素判成边缘、人物涂黑） |
| `--normal-thresh` | 0.95 | 法线突变阈值。**调高可避免把发丝/衣褶等细纹理也描出来**（否则头发呈"铁丝网"） |
| `--chroma-blur` | 0 | 色度降噪（如需可开 1） |
| `--speckle` | 1 | 去斑（清掉孤立彩色单像素） |

**边缘检测三源**：外轮廓（alpha 边界）+ 深度不连续 + 法线突变。

## 六、挑关键帧（脚本，全自动）

```bash
python3 tools/glb2d/select_keyframes.py <帧目录> <输出目录> <K>
```

**算法 = 贪心最远点采样**：
```
① 必留首帧与末帧
② 每次新增「到已选集合的最小距离」最大的那帧
距离 = alpha 形状差 + 0.35 × RGB 颜色差
```

**为什么不用「均匀每 N 帧取一张」**：会**漏掉极值帧**（下蹲最低点、腾空最高点）——恰好是动作最有表现力的两帧。

**实测覆盖度**（26 帧源）：K=3 → 8448 ｜ **K=5 → 6816** ｜ K=8 → 4359（越小覆盖越好）

## 十、贴图回填能力（2026-09-12 新增 · UVMAP 模式）

**用途**：走「AI 在 2D 渲染图上加细节 → 把颜色投回贴图 → 再用 3D 管线重渲」这条路。
细节由 AI 提供，**比例由 3D 管线 100% 保证**（几何/骨骼/相机都没动）。

**开关**：`UVMAP=1 node tools/glb2d/render.mjs ...`

- 主输出 `<outRaw>` 变成 **UV 预览图**（R=u，G=v）——人眼核对"哪块贴图对应身上哪个部位"
- 额外写出 `<outRaw>.uv`：W*H*2 个 Float32，每像素的贴图坐标，未命中为 `-1`
- **不开 UVMAP 时行为逐字节不变**（已用回归对照验证：同一帧渲染与改动前 `cmp` 一致）

**已知前提**：本项目模型的 UV 是 Tripo 自动展开的**大量小碎片**（见 UV 预览图），
一块面片只覆盖很小的 UV 区域 —— 回填时要按面积/朝向做**多角度加权融合**，单角度回填会在背面/侧面留下空洞。

### 十·补：多角度回填的实战口径（2026-09-12 首次跑通）

**流程**：3D 多角度渲染（带 UVMAP）→ 美术线 AI 在 2D 图上加细节 → PM2 配准回填 → 3D 管线重渲。
**细节由 AI 提供，比例 100% 由 3D 管线保证**（几何/骨骼/相机不动）。

| 环节 | 口径 |
|---|---|
| 角度采集 | 水平一圈 8 个（每 45°）+ 俯仰上 25° 8 个 + 俯仰下 20° 4 个。`PITCH=<度>` 环境变量 |
| 配准 | AI 输出**必然放大**（实测 8 张全为 6.4%，缩放 0.937~0.944）→ 按非背景掩膜 bbox 做等比缩放+平移 |
| 合成 | **必须用 `--mode best`**：每纹素只取"正对相机最强"的角度。加权平均会把不同角度的画法差异**平均成模糊**（实测 +4.9% → 择优 +13.1%，且有方向为负） |
| 打光 | 回填前必须**除掉每像素打光系数**（`<raw>.shade`），否则重渲会打第二遍光（实测未除时色差高达 75/255） |
| 覆盖率上限 | UV 岛只占图集 **59.52%**（其余是岛间空白）；20 角度回填 53.42% = **UV 可用面积的 89.8%**。余下是被遮挡内表面，外部视角永远采不到 |
| 门检 | 配准 IoU ≥0.85、**配色漂移用大半径模糊(r=10)量低频**（逐像素色差会把"加的细节"也算成色偏，口径错）、主体内部腐 3px 梯度 > 0 |

**★给美术线的两条硬约束（都踩过）**：
1. **只加细节，不许改形状/位置/缩放/配色/背景/画风** —— 生成的图会被回填成贴图，任何几何漂移都会让颜色写到错的纹素上
2. **不要做"混合回退"那一步** —— 某轮交付件自作主张按 `45% AI + 55% 源` 混合，把 AI 的 +47.6% 砍成 +4.8%。AI 原始输出直接交，配准由 PM2 做

### 十·补2：贴图是「皮肤」不是「姿势」——一套贴图全动作组共用（2026-09-12 实测）

**结论：贴图只需做一次，walk/run/jump/atk/cast 全部直接复用，不必每套动作重做。**

贴图（albedo）是模型的属性，不是姿势的属性。回填把细节写进贴图后，任何姿势复用同一批纹素都会带出这些细节。
**实测验证**：用 idle 采的细节贴图渲**攻击姿势**，主体内部梯度 0.8688 → 1.3494 = **+55.3%**，
衣摆织物、靴子结构、发丝、手臂结构都在，无违和。图：`assets/_trial_20260912/贴图回填验证/跨姿势验证_攻击姿势.png`

**两个需要知道的边界**：
1. 细节是在 **idle 姿势**下采的，覆盖 UV 可采面积的 89.8%。攻击/施法会露出极少数 idle 看不到的部位（腋下、手臂内侧）→ 那些纹素仍是原贴图的平色，不违和。
   真觉得缺，**补几张"极限姿势"渲染图丢进回填即可**——回填不关心输入图是"角度"还是"姿势"，只要那个表面在图上可见。（`--fill-from` 两趟法照用）
2. **衣褶是姿势相关的**：让 AI 在 idle 姿势图上画"褶皱线"，会把 idle 的褶皱烘进贴图，换姿势后这些线仍按表面走但不再对应新姿势的形变。
   所幸我们的 flatcel 光照区间很窄（0.86~1.00），且美术线被要求"克制"，实测攻击姿势下不违和。
   **若要更稳：后续批次在 prompt 里只要求"表面纹样"（发丝分缕、织物纹理、车线、绣纹、五官结构），不要求"衣褶/明暗"。**

**★新增门检项：跨姿势验证** —— 新贴图出好后，用一个非 idle 姿势（如 atk）渲染对比一次，确认细节能带过去且无违和。
