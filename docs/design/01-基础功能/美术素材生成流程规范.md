### 1.3 全局红线（所有类别通用）

1. **AI 稿禁文字**：正式素材一律无字，文字由代码叠（canvas 同像素系）。带字稿只允许作"整稿定视觉"中间产物。
2. **prompt 文件随素材入库**（`prompts/` 目录，可复用配方）；历史欠账（如 home_stage_v2 无 prompt 存档）不得再犯。
3. **坐标 / 尺寸 / 对齐一律程序化像素检测**（PIL 实测 / 脚本输出），禁看缩放预览图读坐标（目测三次翻车实录在案）。
4. **帧核验 = 拼图（contact sheet）同图对比 + 像素级测量双证据**，禁单帧目验下结论。
5. **抠图六红线**以《角色帧规范》§3 为准：检测门只报告不自动清除；白裤/白衣大块近白是设计不是残留；残留清除统一 mxai 接口白底处理（本地脚本清除已废止，见 §1.2）。
6. **暖白残留清除后必跑 `audit_warmwhite_blocks.py`，exit=0 才过门**；清除统一 mxai 接口白底处理（`clean_white_residue.py` / `surgical_clear.py` 已废止停用）。
7. **AI 影子**：prompt 声明"脚下无影子无光斑" + 底部带清除（管线内建固定参数，非手动脚本外科；y>84%，`140<min≤215 且饱和差<42`，白裤 min>210 保护），清后**程序化断言白裤保护域完好**（废止"人工核对"口径）。
8. **commit 用显式文件清单，禁 `git add -A`**（多窗口共用仓库，-A 会卷入其他窗口在途产物，09-02 实锤前例）。
9. **height 定尺**（画布等高 240×320、人物视觉高 256px、脚底基线 y=300、质心 x=120），禁 width 定尺；禁逐帧 bbox 裁切成品。
10. **right = left 镜像**（一张图翻转），不单独生成；AI 一次性直出多帧网格**禁令**（帧间形象漂移+布局降级，6+ 次实锤）。
11. **prompt 主客二分（Leo 2026-09-03）**：客观条款——参考素材、比例、大小、清晰度、画布、头身比、基线坐标等一切可数据化项——一经冻结**一律禁改**；主观条款可发挥，但发挥方向**先经 Leo 确认**。生成后按 prompt 客观条款逐项**二次复检**（可程序化项程序化检测，余项拼图对比），复检不过不得交付。
12. **质量评估只认数据化尺度（Leo 2026-09-03）**：代理侧只按清晰度/比例/规格等可量化指标设门评估；风格等主观因素不把控、不重摇，一律交 Leo 评估；重生成决定与提示词方向更新（主观相关）由 Leo 判，代理门失败即停上报。
13. **参照资产过门（2026-09-04 T45 实证新增）**：任何参照资产（Leo 提供图 / 白模 / 历史成品帧）**入库与引用前必须 Read 目验内容与预期一致**——文件名≠内容，尺寸与预期明显不符即红旗（存错 cast 图冒充五向转面图入库实锤：名称对、内容全错、下游真源带病）；不符立即停用上报重取，禁"先用了再说"。主会话交付候验前同样须对照参照图逐项目验（与代理画面逐项描述同标准），不许只报尺寸门数值。

## 2. 十二类 SOP

> 每类模板：① 适用资产与命名 / 落盘 ② 生成流程（命令级）③ 可靠度 + 依据 ④ 已知坑与红线 ⑤ 缺口与待办。
> 可靠度三级：✅ 已验证可靠（至少一个完整批次过验收，注明批次）/ ⚠️ 有已知风险（跑通但有不可根治问题或需人工判读）/ ❌ 未验证（有方案无实跑）。

### 类别 1 · 角色行走帧（八向 walk cycle）

**① 适用与落盘**
- 标准：《角色帧规范》v5——2.5 头身铃兰式、微俯视、自然站姿（禁笔直立正）；画布 240×320；八向 × {站 / 迈A / 迈B}；4 帧循环 [站, 迈A, 站, 迈B] 180ms/帧。
- 方向集：**实生成 5 向**（down / up / side / down_right / up_right），镜像派生 3 向（left←side、down_left←down_right、up_left←up_right）。
- 目录：`assets/characters/hero/<批次>/`，子目录 `raw/`（抠图后单帧）→ `cut/` → `frames/`（成品）+ `gen/` + `prompts/` + `surgical/` + `report.json` + `contact_sheet.png`。
- 命名：`frames/idle_{dir}.png`、`idle_{dir}_breath.png`、`walk_{dir}_{0..3}.png`。
- 现行批次 = `walk_q/`（48 帧全量）；`walk_v2/` = T13 四向版（20 帧，历史真源）；prompt 配方真源 = `assets/characters/hero/walk_v2/prompts/q_*.txt`（12 张逐姿势配方）。

**② 生成流程（命令级）**
1. 定锚：锚帧 Leo 目验通过（朝向完全正面对称 / 比例 2.5 头身）后开工；现行锚 = `walk_v2/raw/q_anchor_v5_clean.png`。
2. 逐姿势 img2img（每方向 3 张，2 分/张）：
   `python3 scripts/mxai_img2img.py <该向参照> raw/<dir>_<pose>.png --prompt-file <prompts/q_<dir>_<pose>.txt>`
   首姿势（stand）参照 = 定稿锚；同向 stepA/stepB 以该向 stand 为参照（保同向一致）。迈步 A=左腿向前、B=右腿向前，prompt 必须写明左右脚。
3. 抠图 + 合成 + 校验门：
   `python3 scripts/build_walk_frames.py --root assets/characters/hero/<批次> --dirs down up right down_right up_right`
   输出 frames/（含镜像向与呼吸帧）+ report.json + contact_sheet.png；校验门任一失败 exit 1，全过才入库。
4. 封闭白检测：`python3 scripts/triage_enclosed_white.py`（只报告）；residue 清除统一 mxai 接口白底处理（surgical 手挑点路线 2026-09-03 废止），处理后复跑审计门。
5. 影子核查：底部带米色光斑按红线 7 清除（管线内建），清后核对白裤完好。
6. 帧间一致度验收：contact sheet 同图对比 + report.json 量化（头部位移 / 高度 / 质心 / 脚底基线）双证据。

**③ 可靠度：✅ 已验证可靠**
- 依据：T13 批（`walk_v2/`，四向 20 帧，09-01 L 环 Leo 验收通过）；T14 P0 批（`walk_q/`，八向 48 帧全过校验门、硬失败 0，commit 7355867 09-02 12:47）。
- ⚠️ 附加约束：**跨批次体型漂移**——同角色必须单批次一次生成，禁跨批拼接。
- 注：任务书描述本类为"5×3 精灵表单次生成"路线；仓库实况 = 上述逐姿势路线产出了全部过验收帧（5×3 表仅存试验稿 `walk_v2/raw/spritesheet_5x3_v1.png`，无下游切帧产物，见拍板节 P-1）。

**④ 已知坑与红线**
