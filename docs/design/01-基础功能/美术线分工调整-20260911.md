---

## 一、调整后的分工（一句话）

| 角色 | 负责 |
|---|---|
| **美术线（Codex art）** | **纯生成类** —— 人物生成、立绘、UI（**凡需要 gpt-image-2 生图的**） |
| **PM2（ZCode 侧）** | **其他全部美术工作** |

---

## 二、边界怎么判（一句话判据）

**判据 = 「这件事的核心动作是不是"让 gpt-image-2 画一张图"？」**

- **是** → 派美术线
- **不是** → PM2 自己做

### 2.1 归美术线（纯生成）

| 类型 | 例子 |
|---|---|
| 人物生成 | 正面站立图、动作帧的 AI 生成（生图部分） |
| 立绘 | 角色立绘、头像 |
| UI | UI 组件、图标、面板底图 |
| 其他生图 | 任何「prompt → 图片」的产出 |

### 2.2 归 PM2（其他全部）

| 类型 | 例子 |
|---|---|
| **3D→2D 产线** | 重定向、渲染、后处理、挑关键帧、导出（**全本地脚本，不经生图**） |
| **素材加工** | 抠图、缩放、裁切、拼图、归一化、镜像 |
| **门检** | 机械门检（规格/尺寸/连通域/尺度）、溯源、contact sheet 目验 |
| **口径与规范** | 美术口径裁定、帧规范维护、素材盘点文档 |
| **放行与排产** | 试产/铺量放行、credits 记账监督 |
| **调研与评估** | 新工具/新路线的可行性验证（如今天的三条路线对比） |

---

## 三、对既有流程的影响

### 3.1 3D→2D 产线**不再经过美术线**

原来「派单美术线出正面站立图 → 等交付 → 门检」这条链，**其中"生图"环节仍归美术线，但后续全部归 PM2**：

```
正面站立图（美术线生图）→ 【PM2 全程】Tripo 建模 → 动作重定向 → 渲染 → 后处理 → 挑帧 → 导出
```

### 3.2 门检仍是 PM2（不变）

两道关卡不变：**第一道 = Leo 审美目验；第二道 = PM2 规格门检**。
美术线交付纯生成类素材后，**PM2 做门检**（与现行一致）。

### 3.3 素材落地纪律不变

交付 delivery 必须显式声明 runtime 落库状态；候选过门 24h 内集成或登记挂起原因；书面"已入库/已交付"必带 commit+路径实测证据。**这套纪律对两个角色同等适用。**
