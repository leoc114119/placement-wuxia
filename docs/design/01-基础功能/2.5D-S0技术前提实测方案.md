## 1. 结论与范围

### 1.1 渲染选型

S0 定版采用 raw WebGL2 手写最小蒙皮，不使用 three.js 或其它运行时依赖。

理由：

1. 被测对象就是“微信小游戏第二张离屏 canvas 取得 webgl2 → 41 骨 uniform 蒙皮 → drawImage 合成到第一张 2D canvas”的自研 A 路线。three.js + adapter 会把 three 的加载、状态管理和适配器兼容性混入结果。
2. 模型只有一个 primitive，S0 只播 idle，最小 GLB 子集和蒙皮 shader 可控；不需要完整引擎。
3. 若 raw 路线失败，错误可分到 canvas/context、shader/uniform、模型解析、合成拷贝四层，不会被引擎封装遮蔽。

S0 不证明正式 2.5D 架构完成；只产出：

- 数 1：安卓真机离屏 WebGL2 + 2D 合成是否可用。
- 数 2：现役 48k 模型在 1 / 5 / 10 / 20 单位档的帧率与分相耗时，主判 20 单位。

## 2. 最小 raw WebGL2 实现

### 2.1 GLB 子集

glb-loader 只支持本模型实际用到的固定子集，并 fail-fast：

- GLB v2 JSON/BIN chunk。
- bufferView / accessor。
- POSITION、NORMAL、TEXCOORD_0、JOINTS_0、WEIGHTS_0、indices。
- skin.joints、inverseBindMatrices、node hierarchy。
- 单 mesh、单 primitive、单材质和现有 3 张内嵌/关联贴图。
- 任一额外 primitive、稀疏 accessor、DRACO 或未识别 componentType 直接报错，不做猜测降级。

解析完成输出模型账：triangleCount、vertexCount、jointCount、primitiveCount、textureCount、bufferBytes，并与 README 基线核对。41 骨不一致直接 FAIL。

### 2.2 蒙皮与绘制

使用 GLSL ES 3.00。顶点 shader 声明 uniform mat4 uBones[41]，按 JOINTS_0/WEIGHTS_0 线性混合骨矩阵；每单位一次 drawElements。

每个单位每帧：

1. 从 idle_v4.json 按独立相位采样 41 骨 local TRS。
2. 沿 node hierarchy 求 world matrix。
3. skinMatrix = jointWorld × inverseBindMatrix。
4. 一次 uniformMatrix4fv 上传 41×16 float 的整块 palette。
5. 上传该单位 model matrix 并 drawElements。

重要纠正：41 骨不等于每单位 41 次 uniformMatrix4fv。S0 必须一次上传整个 mat4 数组，因此 20 单位约 20 次 palette 上传、20 次 draw call；禁止写成 820 次 API 调用后再用 UBO“优化”一个人为制造的问题。UBO、骨骼纹理、实例化均不进 S0 基线。

20 单位使用同一 VBO/IBO/纹理和 shader；只改变 model matrix、骨骼 palette 与动画相位。相位固定为 i×0.137s 取模 idle 时长，防止同相缓存把 JS 骨架开销测低。

## 3. Canvas 形态

1. 第一次 wx.createCanvas() 作为屏幕 canvas，获取 2d context。
2. 第二次 wx.createCanvas() 作为角色离屏 canvas，设置与屏幕相同 backbuffer 尺寸，获取 webgl2 context。
3. 上下文属性固定记录并用于 A2：alpha=true、antialias=true、premultipliedAlpha=true、preserveDrawingBuffer=true。
4. WebGL canvas 每帧先 clear 透明背景，再绘全部角色。
5. 2D 主 canvas 先画确定性棋盘/背景，再 drawImage(webglCanvas, 0, 0) 合成角色，最后画指标文字。
6. 禁在同一 canvas 混取 2d/webgl；webgl1 探测必须使用第三张全新 canvas。

A2 的 backbuffer 使用设备实际 windowWidth × windowHeight × min(pixelRatio, 3)，与现有战斗预览 DPR 上限一致；结果必须记录实际像素尺寸。不得偷偷降 renderScale 来过门。

## 4. A1：离屏 WebGL2 可用性

### 4.1 设备信息

启动时写入：

- brand、model、system、platform、version。
- SDKVersion、pixelRatio、screenWidth/Height、windowWidth/Height。
- benchmarkLevel。
- WebGL VERSION、SHADING_LANGUAGE_VERSION、VENDOR、RENDERER。
- MAX_VERTEX_UNIFORM_VECTORS、MAX_TEXTURE_SIZE、MAX_VERTEX_ATTRIBS。
- context attributes 与 backbuffer 尺寸。

SDKVersion 用整数分段的语义版本比较，禁止字符串字典序；小于 2.24.0 直接标 UNSUPPORTED，不参与 A 路线 PASS。

### 4.2 断言顺序

A1-01 Canvas 身份：
- 第一张 canvas 能取得 2d。
- 第二张对象与第一张不是同一对象，宽高可独立设置。

A1-02 WebGL2 context：
- 第二张 canvas 的 getContext('webgl2') 非 null。
- gl.isContextLost() 为 false，初始 gl.getError() 为 NO_ERROR。
- MAX_VERTEX_UNIFORM_VECTORS 至少 180。骨矩阵占 164 vec4，另给 view/projection/model 与少量参数留余量；最终以 shader compile/link 成功为硬判据。

A1-03 最小 shader：
- 编译/link 一个含 uBones[41] 的最小顶点 shader。
- 上传 41 个 identity 矩阵并绘确定性红绿三角形。
- gl.readPixels 读取中心 4×4 区域，非 clear 像素数大于 0，alpha 大于 0，gl.getError() 仍为 NO_ERROR。

A1-04 真实模型：
- 从普通分包加载 48k GLB 与 idle 动作。
- 渲一名角色并 readPixels；非透明像素计数大于 100，bbox 宽高均大于 10，且连续两帧像素摘要不同，证明真实蒙皮动画在动。

A1-05 合成：
- 把 WebGL 离屏 canvas drawImage 到 2D 主 canvas。
- 主画布固定区域绘一个 WebGL 生成的颜色校验块和当前 nonce。
- 若 2D getImageData 可用，则程序化核 RGBA；若平台不提供可靠主画布回读，则该项由截图 + 屏上 nonce + 人眼确认，结果标 visualProof=true，不能假写 readback PASS。
- drawImage 抛错、全透明、上下颠倒导致完全不可见均为 FAIL。

A1-06 冷启动稳定性：
- 同一设备完全杀微信/重新扫码，连续 3 次运行。
- 三次全部通过 A1-01..05、零 context lost、零 GL error 才算该设备 Device-PASS。

### 4.3 WebGL1 诊断

若离屏 webgl2 返回 null：

- 新建第三张 canvas，仅探测 webgl。
- 记录 webgl 是否可得、GL 版本和限制。
- WebGL1 结果只用于定位，不构成 runtime fallback，不允许继续 A2 或把 A 路线判 PASS。

另做主画布 WebGL2 正控工程模式：让第一张屏幕 canvas 直接取 webgl2 并画三角形。用于区分：

- 主画布 WebGL2 PASS、离屏 FAIL：双 canvas A 路线确定失败。
- 主画布与离屏均 FAIL：该设备/SDK 无 WebGL2，A、B 都不能直接成立。
- 离屏 WebGL2 PASS、drawImage FAIL：A 的合成链失败，B 仍可能成立。

### 4.4 A 路线总判定

Device-PASS 是单设备事实。S0 的 Architecture-PASS 要求：

- 至少 2 台安卓真机。
- 品牌或 GPU renderer 不同。
- 至少一台为当前可取得的较低 benchmarkLevel 档。
- 每台各 3 次冷启动全绿。

只有一台设备通过时记 PARTIAL_PASS，不得写“A 方案成立”。任何满足 SDKVersion≥2.24.0 的目标设备在排除 demo 编码错误后连续 2 次复现离屏 context/draw/read/composite 失败，Architecture-FAIL。

## 5. A2：20 单位蒙皮性能

A2 只在该设备 A1 Device-PASS 后运行。档位固定为 1 / 5 / 10 / 20；均使用 48,419 三角形、41 骨、idle 动作、独立相位，关闭视锥裁剪与单位休眠，确保每帧实际 draw call 等于档位数。

### 5.1 采样流程

- 每档预热 10 秒。
- 1 / 5 / 10 单位各采样 30 秒。
- 20 单位采样 60 秒。
- 档位间 clear 资源计数但复用 GPU buffer/texture，禁止重新解码模型污染稳态帧率。
- 每档至少 1800 个 rAF 样本或达到规定秒数，以先到者之外继续到另一个条件也满足。

### 5.2 指标

主指标：

- fpsMean、fpsMedian。
- frameMsMedian、frameMsP95、frameMsP99。
- onePercentLowFps。
- over33msRatio、over50msRatio。
- contextLostCount、glErrorCount。

分相指标：

- jsAnimMs：动作采样 + 41 骨 world/skin 矩阵。
- glSubmitMs：uniform 上传 + drawElements 的 CPU 提交时间。
- compositeCpuMs：2D drawImage 调用的 CPU 时间。
- gpuMs：仅当 EXT_disjoint_timer_query_webgl2 可用时填写；不可用则为 null，禁止用 draw call 前后 performance.now 冒充 GPU 时间。
- frameWallMs：完整 rAF 间隔，作为真实总成本。

A1 的 readPixels 不进入 A2 循环；readPixels 会强制同步并污染帧率。

### 5.3 性能 PASS

20 单位档必须同时满足：

- fpsMedian ≥ 30。
- frameMsP95 ≤ 33.3ms。
- frameMsP99 ≤ 50ms。
- over50msRatio ≤ 1%。
- contextLostCount = 0、glErrorCount = 0。
- 实际 drawCallsPerFrame = 20、skinPalettesPerFrame = 20。
- 屏上 20 个角色全部可见，无遮挡错位导致的假裁剪。

若 20 失败但 10 通过，结论为 A_COMPATIBLE_CAPACITY_FAIL：A1 架构仍成立，但“20 单位”目标未达。下一步先用 20k 智能低模做同口径 S0-R1；不得直接把 A 判死，也不得自行把同屏目标改为 10。

## 6. 包体策略

S0 使用普通分包，模型和 idle JSON 放 probe-model 分包；主包仅放代码、shader 和 2D 校验背景。选择分包而不是剥贴图：

- 4.04MB 模型原样测试，变量唯一。
- 剥贴图会改变纹理、解析和 GPU 上传量，测到的是另一个资产。
- 普通分包也能验证 wx.loadSubpackage → FileSystemManager 读取 GLB 的实际链。
- 生产口径仍是 CDN；S0 分包只是独立 probe 的可复现实验夹具，不构成 S1 资源方案。

分包加载时间、readFile 时间、GLB parse、纹理解码和首次 GPU upload 分别记录，但不并入稳态 A2 FPS。CDN 首启耗时另列 S1/S0b，不在本卡模拟。

## 7. 两段式预验证

认可“两段式”，但判定权分层：

1. 浏览器 + wx shim：
   - 跑 GLB 解析、shader、41 骨蒙皮、1/5/10/20 档、离屏 WebGL→2D 合成。
   - Playwright 自动截图和结果 JSON。
   - 只能证明核心代码通，不证明微信或安卓能力。
2. 微信开发者工具：
   - 核 project.config/game.json、分包加载、API 名称和日志。
   - 只能作为真机前置，不参与 Architecture-PASS。
3. 安卓真机：
   - A1/A2 唯一正式证据源。

浏览器或开发者工具失败必须先修到绿再上真机；两者通过后安卓失败仍按安卓事实判定，不得以 Chrome 证据覆盖。

## 8. 结果格式

每次运行同时：

- 屏上大字展示设备、A1 状态、单位档、实时/滚动 FPS、P95、JS/GPU/合成、GL error。
- console 输出单行 __WEBGL2_PROBE_RESULT__=<JSON>。
- 写 wx.env.USER_DATA_PATH/probe-result.json。
- 提供“复制结果”按钮调用 wx.setClipboardData。
- 输出每档截图，文件名含 deviceHash、SDKVersion、unitCount、runIndex。

JSON 最小结构：

## 9. 失败升级路径

A1 离屏链失败：

1. 先跑主画布 WebGL2 正控。
2. 主画布 PASS、离屏或 drawImage FAIL：A 路线判死，下一张卡只做 B 的主画布整体 WebGL 最小 spike；不开始游戏迁移。
3. 主画布也 FAIL：B 同时失去前提，直接提交 Cocos C 路线评估或由 Leo调整最低 SDK/设备覆盖范围。
4. webgl1 可用只记录，不启用 runtime fallback，符合 Leo“不降级 2D/不改蒙皮路线”的口径。
5. Architecture-FAIL 由主架构签字；转 B 还是 C 涉及重写成本和产品覆盖，由 Leo在主架构建议后拍板。

A2 性能失败：

- A1 PASS 但 20 单位未过：不判 A 死，先做 20k 模型同口径复测。
- 20k 仍失败：主架构提交容量/分辨率/骨骼上传优化建议；Leo决定是否调整 20 单位目标或转 B/C。
- 禁止在 S0 内偷偷降分辨率、减单位、休眠动画或用静态骨矩阵凑绿。

## 10. DoD 与验收分工

### 10.1 工程 DoD

- proto/webgl2_probe 独立可导入微信开发者工具，根游戏文件零 diff。
- 零 third-party runtime 依赖；three.js 不进入 probe。
- 模型/动作副本 SHA 与源一致；模型确为 48,419 三角形/41 骨。
- 浏览器自动化 PASS，截图与 JSON 在库。
- 微信开发者工具无编译/运行错误。
- 至少两台安卓满足 A1 设备矩阵，或明确给出 PARTIAL_PASS/FAIL，禁止证据不足写 PASS。
- A2 1/5/10/20 四档原始 JSON、屏幕截图、汇总表齐全。
- 20 单位 verdict 按 §5.3 自动生成。
- 文件清单、设备清单、失败日志、零游戏工程改动证明写入回执。

### 10.2 验收分工

- frontend 栈：实现 probe、跑浏览器/开发者工具、生成可扫码版本和结果导出。
- Leo：提供/扫码安卓真机并确认屏幕上合成可见；不负责计算技术 verdict。
- 研发 PM：核设备信息、原始 JSON、截图、重复运行和文件边界。
- 主架构：依据固定阈值签 A1 Architecture-PASS/FAIL 与 A2 Capacity-PASS/FAIL。
- 只有主架构签字后才能进入正式 2.5D 架构方案；S0 结果本身不授权改游戏。

预计施工 10 小时（高置信，不含等待第二台安卓和 Leo 扫码时间）。

## 11. 风险时间轴

现在最先爆的是“浏览器绿=安卓可用”的假证据，因此三层判定必须严格分开。接下来一个月的债是 CDN 首启、缓存与版本切换；S0 分包不替代生产资源方案。两到三个月后才是多角色资源驻留、骨骼 palette 管理、遮挡/阴影和 App 宿主；这些必须等 A1/A2 真机数出来后再设计，不能提前塞进 probe。
