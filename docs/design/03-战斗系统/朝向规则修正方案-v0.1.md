## §零 结论速览

1. FACE-1 本体 = **纯 session 行为面修正**（battle-session.ts 单文件 + 测试），零契约、零渲染、零后端、mock 零同步——建议单张 frontend 卡（§五）。

### 1.6 取证发现：faceToward 两处口径缺陷（FACE-1 必须顺带修正）

**A. 吸附度量错误**：现用 **axial 平面 2D 点积**（:325）——axial 基非正交，点积不度量对齐度。实证：目标在 axial (0,-1)（视觉左上）时，v=(0,-1) 与 dir (1,-1) 点积同为 1，dirs 序前者胜 → **hexFacing = (1,-1) 右上，朝错**。受影响方向 = {(0,-1), (0,1)} 两族（其余四向侥幸正确）；hex.ts `dirIndexOf` 的 cube 3D 点积对同输入判为 (0,-1) 正确。影响面：移动/攻击到竖向邻格后锥形轴错向 + FACE-1「朝最近敌」在竖向邻格朝错。
**B. faceLeft 判据不一致**：按 offset 列差符号（:332-334），奇偶行 (0,±1) 方向 Δcol=0 → 保持旧翻转值；而视觉水平分量恒有确定符号（像素 Δx ∝ Δq + Δr/2，奇偶行均非 0）——翻转与视觉左右不一致。

## §二 设计

### 2.1 faceTarget 选取算法（单一产生点 = resolveAoe）

```
faceTargetOf(actor, targets): Runner          // targets = all 数组序一次快照（禁 sort，SP-2 既有锁）
  dmin ← min(cubeDistance(actor.hex, t.hex))  // 单次遍历
  ties ← [t ∈ targets : dist == dmin]         // 保持 all 序
  ties.len == 1 → 取 ties[0]                   // rng 零消费
  ties.len ≥ 2 → idx = floor(rng() * ties.len) // rng 恰消费 1 次（seed 单流，纳入 SP-2）
  return ties[idx]
```

落点（**病灶②式收敛：决策单点**）：`resolveAoe`（:410-412）改为——入口先算 faceTarget（**rng 消费点固定在逐目标循环之前、即本次施放首次掷骰之前**），循环照旧（doAttack 内 F1 逐目标 faceToward 保持不动，中间态不可观测），**循环后 `faceToward(actor, faceTarget.hex)` 定版**。cast 有敌臂删除 :785 `faceToward(player, req.to)`；aiAct 出技臂（:489-491）零改动即获得同规则。

**与 tickCooldowns/resolveAoe 的先后顺序**（cast 全序）：四查 → `tickCooldowns(player)`（:781，无 rng）→ resolveAoe【tie rng（0/1 次）→ 逐目标掷骰（1~3 次/目标）→ faceToward(faceTarget)】→ commitTurn。AI 全序：planSkill（无 rng）→ tickCooldowns → resolveAoe（同上）。消费点选在循环前的理由：①消费序与演出序同构（先定向后出手）；②若未来循环内引入早退（施放者中途死亡等），入口消费计数恒定不受影响。

### 2.2 SP-2 rng 消费时序论证（为何不破坏「同 seed 同操作序列事件流全等」）

1. rng 为单流闭包（§一.4），输出序列由 seed 唯一决定；**消费次数与消费位置是程序控制流的确定函数**。
2. 程序状态轨迹（出生布局/hp/bar/冷却/位置）由 (seed, 操作序列) 唯一决定——SP-2 既有双场断言背书；ties 是否存在、ties 内容由 targets 快照与 cubeDistance 派生，同为状态确定函数。
3. 故插入「平局时恰 1 次」的消费点后，同 seed 同操作的两场 rng 消费轨迹**逐位全同** → 掷骰序列、事件流逐字节全等。FACE-1 不新增任何依赖实现细节的消费分叉（消费次数 = ties.len≥2 ? 1 : 0，纯状态函数）。
4. 异 seed：出生布局已不同（既有断言 events not equal）；tie 取值随流而变属既有确定性面；hexFacing **不入事件流**、faceLeft 只入快照——朝向差异除锥形武器后续合法性外无事件流可观测面。
5. 既有双场用例不红：全部用例即时构造、无跨版本金录（§一.4）；[五点②] 双场布点与平局结构相同 → 两场同掷同数 → 增量全等保持。
6. **边界备案**：跨版本（FACE-1 前后）同 seed 事件流不保证逐字节相等——平局场多消费 1 次使后续掷骰序列整体位移。当前无金录依赖故无涟漪；若未来引入回放/录像对账，按 FACE-1 版本号分段（§六-5 告知）。

### 2.3 六向吸附判定放哪层（建议 + 方案对比）

**建议：留在 session（现状形态直接沿用），本次零契约变更。** 理由：
1. faceToward 现参数形态 = `HexPos 目标格`，session 内部落定 `hexFacing: HexPos`（六向枚举）——FACE-1 只改「朝哪个敌」（faceTarget）与「吸附度量」（§二.4），**现形态完全表达得了六向，无需任何新字段**。
2. 六向语义的两个消费点（锥形轴）都在 session；朝向是逻辑态，产生点必须与消费点同层。
3. 「存目标格坐标、渲染层吸附」被否：快照不携带朝向目标格；渲染层从 renderPos 差分推朝向在静止态无信号，且违反「快照真值，禁渲染启发式猜」既有教训（isJump 验收 F1 前科）。

### 2.4 faceToward 两处口径修正（随卡落，FACE-1 必要组成）

- **A. 吸附度量**：axial 2D 点积 → **cube 3D 点积**（同 hex.ts dirIndexOf 度量；整数精确）。实现 = faceToward 内 ~6 行局部改写，session 自持——**不引 hex.ts 导出**（hex 零改动红线保持；备选「dirIndexOf 加 export」（抽取导出级，T15/Q2 先例）因红线预期保持而弃）。
- **B. faceLeft 判据**：offset 列差 → 像素水平分量符号 `sign(2Δq + Δr)`（整数精确；推导：场内 r≥0 时像素 x/W = q + floor(r/2) + (r mod 2)/2 = q + r/2 **恒等**，故 Δx 符号 = sign(Δq + Δr/2) = sign(2Δq+Δr)）。消除奇偶行 (0,±1) 方向的「保持旧值」错误；无抖动风险（faceToward 每行动调一次，非逐帧调用——T06 防抖针对的是逐帧 lerp 场景，不适用此处）。
- 影响面：锥形武器（鞭/刀）在竖向邻格方向后的锥轴/高亮**正确化**（Q4 批复「锥形轴=六向 facing」语义）；现无 session 级锥形用例，零断言涟漪（§四-6 提醒施工时按修正后口径写新用例）。
- **吸附度量定版口径**：cube 点积 vs 规格原文「世界向量吸附六向（取夹角最小者）」的关系——本棋盘像素投影（config/battle-hex.ts:10-16/29-32，压扁错位网格）下，六轴 向量与世界六向**一一对应且逐行奇偶不变**（已核）；cube 点积与世界夹角在**单位邻格及全部近中距向量上一致**，分歧仅出现在极端远角向量（枚举核得 (7,-4)、(9,-5) 及其旋转/镜像族，cube 距离 7/9——仅暗器满档射程 9 边缘可达，且分歧带内两解均为相邻视觉方向）。**建议定版 = hex cube 度量**：与投影表现常数解耦（TILE_SPEC 曾随 L 环改版 62→88，语义不应随表现漂移）、整数精确。方向边界平局（如 (2,-1)、(4,-2) 族向量恰在两向等分点）以 HEX_DIRS 序首胜——已核世界夹角侧同判（如 (2,-1) 世界角 −19.3° 偏 E 侧，cube 平局亦取 E）。**候裁 §六-3**。

### 2.5 「转向完成后再播帧」的演出落法

**取证结论：渲染层零改动即达成。** 机制证据：
1. cast/ATK-1/ATK-2 路径：faceToward 与 setAnim 在 submit **同一同步块**内完成（:372/:785 邻近 setAnim），快照每帧重建、facing 与 animState **同一快照原子携带**——billboard 翻转与新帧组同帧切换，不存在「未转向先播帧」的中间态。
2. ATK-3 路径：**既有结构已显式满足**——quiet && walk 时攻击帧记 pendingAnim 延后（:367-371），faceToward 即时（转向发生在移动演出中），移动演出结束后才补播攻击帧（:582-585）。「转向完成→再播攻击帧」的顺序由 pendingAnim 机制结构保证。

## §四 易错点（从用例长出，与取证对照）

1. **rng 消费纪律**：必须「平局才掷、恰掷 1 次」。掷成「每次 AOE 都掷」或「每个平局敌各掷」——[五点②]/SP-2 双场仍绿（两场对称），但异 seed 行为与规格③不符且浪费流位。锁法 = 用例②的异 seed 分臂（tie 取值变化）+ 平局/非平局对照布点；rng 消费次数无直接观测通道（makeRng 闭包），以双 seed 取值分歧为间接证据，seed 对施工时实证选定。
2. **修复必须有回归锚**：§一.6-A 的吸附错误若不加 ③b，修正无断言背书——日后回退无人察觉（规格③「实现反向污染用例」教训的反向应用：实现改对，用例必须写对方向）。
3. **决策单点勿复裂**：faceTarget 只在 resolveAoe 产生；**勿删 doAttack 内 F1 faceToward**（ATK-1/ATK-3/AI 普攻共用），也勿在 cast 分支重复调用（否则再现「同一决策多点公式」病灶结构）。
4. **:612-625 断言与④联动**：空放朝向断言改动唯一合法依据 = FACE-1④ 复核结论（规格变更），禁施工侧自行改写。
5. **targets 禁 sort**：faceTarget 用单次遍历求 min + 保序 ties；**勿复用 pickTarget**（其含 hp 次键且 sort 破坏 all 序——SP-2 目标序锁）。
6. **锥形武器正确化涟漪**：§二.4 修正改变竖向邻格后的锥轴 → 后续 ATK-1 合法性/锥形高亮可能翻转（正确化方向）。现无 session 级锥形用例；施工若补锥形用例，**按修正后口径写**，禁按旧实现自反推断言（规格 §一③ 根因教训）。
7. **跨版本事件流不等是预期**：FACE-1 落地后，含平局 AOE 的同 seed 场事件流与旧版不逐字节相等（掷骰序列位移）——这不是回归；回归判定基准 = 本档 §三 走向表 + SP-2 双场（同版本内）全等。
