## 三、N1 修复设计（P-1 推荐 + P-5 最小切口）

### 3.1 P-1 三选项权衡（推荐 C：A 变体主修 + 回退轨防御）

| 选项 | 改动面 | 收益 | 风险/代价 | 结论 |
|---|---|---|---|---|
| A：session 保留 walk 可见窗口 | session ~10 行 | 消灭本例触发断点；FE 零改动；事件序/确定性零变化 | 只修触发，不修回退轨穿人（BE4 crossed 仍红） | **采为主修（A 变体，§3.2）** |
| B：FE 演出改事件驱动 | updateView 签名加 events 游标 + 全单位演出启动/释放/moveDone 重设计 + move 事件需扩 isJump 字段（动确定性契约形状） | 消灭"状态推断"整类断点（复盘 §5.2） | 改动面大，直接威胁 D-04/D-05 既有修复（左闪右闪/闪烁三轮才修稳）；与 Q1 批复"最小"冲突 | **不做，列为完整 P-5 收敛的候选方向**（后续窗口另出方案） |
| C：一侧主修 + 另一侧防御 | A 变体 + §3.3 | 触发断点修复 + 即使未来任何同栈覆写再吞演出，回退轨也不再穿人（N1 表现面被结构兜住） | session 侧两处小改 | ✅ **推荐 = C** |

### 3.2 主修：ATK-3 不覆写 walk——演出写入延后（session 侧）

- `Runner` 新增字段 `pendingAnim: SnapshotActor['animState'] | null`（mk() 初始化 null）。
- `doAttack`（battle-session.ts:348-354）：`outcome.kind !== 'blocked'` 时，若 `quiet && actor.animState === 'walk'`（即 ATK-3 路径，doMove 同栈必然 walk）→ **不调 setAnim**，改记 `pendingAnim = skill ? 'charge' : 'basic'`；否则照旧 setAnim。faceToward 不变。
- `tick` 动画倒计时分支（battle-session.ts:527-538）：`animLeftMs ≤ 0` 时优先级 = charge→strike（不变）→ **有 pendingAnim 则 setAnim(pendingAnim) 并清空** → 否则 idle。
- **明确不变**：resolveAction 结算与事件 emit 仍同步（行为套件绿锁"move 事件后跟 basic 事件"同步断言保住）；仅"演出状态写入"延后 ~300ms，攻击演出（basic 帧组 + slash FX）在移动演出结束后照常播出（FE anim 钟检测 walk→basic 跳变推 FX，renderPos 此时已到终点，FX 位置正确）。
- 附带收益：AI 位移后接 `basicIfAdjacent` 走同一路径——敌方相邻位移同样此前被吞演出，本修一并生效（同一机制，零额外代码）。

### 3.3 防御：P-5 最小切口——session 回退轨改沿合法路径插值（session + hex.ts）

- `systems/hex.ts` 新增纯函数 `movePathCells(from, to, occupied: HexPos[], inBounds?: BoundsFn): HexPos[]`：6 邻 BFS（复用 `HEX_DIRS`，方向序固定→确定性），起点格不作阻挡、其余 occupied 格不可借道，限 inBounds；返回 `[from, …, to]`；BFS 失败防御回退 `[from, to]`（= 现几何，不劣化）。
- `Runner` 新增字段 `movePath: HexPos[]`；`doMove`（在改 hex 前计算）：walk → `movePathCells(旧格, to, occupied(), inField)`；jump → 恒 `[旧格, to]` 直线（凌空可穿，语义不变）。
- `tick` 位移插值（battle-session.ts:522-526）改为**沿 movePath 分段等时插值**：`segs = movePath.length-1; f = moveT*segs; i=⌊f⌋; lp=f-i; renderQ/R = path[i]→path[i+1] 线性`。moveT=1 时落点恒等于 path 末位=hex（FE 释放条件 `settled` 依赖的 `renderPos==pos` 保持成立）。
- 效果：walk 期间快照 renderPos 恒不进入他方占格 → **BE4 crossed=false**；且未来任何"演出未启动"情形下，回退绘制轨也是绕行轨——N1 的穿人观感被结构性兜住。
- 148 套件回归面：battle-session.test.ts 无任何 renderPos 插值形状断言（grep 实证 0 命中）；事件/pos/结算零变化。
- 与 FE 的路径双计算点说明：FE `computeMovePath`（演出轨）与本函数（回退轨）是**两个展示层决策点**，允许绕行选路不同（二者都保证不穿占格，且任一时刻只有一轨上屏）；几何知识仍归 hex.ts/渲染层各自模块，session 不 import ui（分层红线）。

## 四、N2 机制②修复设计（Q3 定版：演出位不可点）

### 4.1 语义定版（依据 §2.4-2 的断言证据）

- **拦截面**：点击格命中某存活敌方棋子的**移动演出位**（可见位 ≠ 其逻辑格）→ 不派发任何请求（不施放/不取消/不移动）、选中保持、`onBlocked('目标移动中')` 可观测反馈。
- **保持面（不得误伤）**：① 点击移动中敌的**逻辑格**照常受理（D-06 绿锁 :337）；② SEL-5② 攻击技选中点无效格=取消（:331-334）；③ 敌静止时一切既有路径不变；④ 点绿格/金格移动意图优先（敌影恰飘在绿/金格上时，移动/跳跃语义赢——见 §4.3 分支序）。

### 4.2 「移动中」判定 = 双通道

```
moving(a) = (a.renderPos.q !== a.pos.q || a.renderPos.r !== a.pos.r)   // session 位移窗（300ms）
         || view.moveAnims.has(a.id)                                   // FE 演出窗（0.3s×dist，含尾段）
```
只查 session 轨会漏 FE 长演出尾段（§2.4-3）；只查 FE 轨会漏无演出回退态。输入层持有 view 引用（现签名已传），不新增契约字段。

### 4.3 `ui/battle-input.ts up()` 修改（单点插入，既有分支零改写）

- 新增可视位量化：`visCellOf(a) = worldToHex(hexToWorld(a.renderPos.q, a.renderPos.r))`——与绘制链（drawPieces 按 `hexToWorld(renderPos)` 落像素）和点击量化（worldToHex）**同函数链对称**，禁止自造 Math.round 启发式（错位网格奇偶行半格偏差）；input 需从 config/battle-hex 增 import `hexToWorld`（同模块既有 import，无新依赖类）。
- **分支顺序（关键）**：弧钮/ctrl/plaque → 出界取消 → **pos 命中=普攻/施放（既有，D-06）** → 轻功金格移动（既有）→ 无选中绿格移动（既有）→ **【新增】`moving(a) && visCellOf(a)==cell` → `hooks.onBlocked?.('目标移动中'); return`** → `skill && !inAttack` 取消（既有）。
- 该顺序天然保证：逻辑格点击（pos 分支在前）照常受理；绿格/金格意图优先于演出位反馈；只有"点在演出位、且该格不是合法移动格"才走新分支。

### 4.4 转绿推演

- 行为套件 N2-②（点演出位：cancelSkill=0 且选中保持 te）：新分支 return 于 cancel 之前，零派发 → 绿。
- BE3（点演出位选中保持 jue）：同上 → 绿；`expectRed` 翻转 + 文件头登记（§八）。
- 不误伤实证：BE1（静止敌施放，placeFoe 后 renderPos==pos 且 animState=idle）不走新分支；:337（逻辑格）pos 分支在前；:331-334（无效格无演出位命中）直达取消分支。
- N2-①（空红格）不受影响保持登记红：新分支仅命中"移动中敌演出位"，纯空红格仍静默（机制①属二批 P-2）。

## 九、易错点清单（铁律 7 · 供子代理对照；领单后仍须由自己的用例清单另行总结，两份互补）

**N1 / session 侧**
1. ATK-3 的 basic **事件必须仍同步**紧跟 move（行为套件绿锁同步断言）——只延后演出写入，绝不延后结算/事件。
2. pendingAnim 分支仅限 `quiet && animState==='walk'`；非 quiet（AI 主动攻击/玩家普攻施放）路径零变化。
3. 行为套件 `place()` 测试基建需同步重置 Runner 新增字段（pendingAnim/movePath），否则用例间状态泄漏造成假红/假绿。
4. 路径 BFS：起点格不作阻挡（自身旧格在 occupied() 内，须排除）；终点格已由 legalMoveCells 校验为空，不须再判。
5. jump 恒直线（凌空可穿是 MV-2 语义，勿给 jump 也套绕行）；walk 才走 movePathCells。
