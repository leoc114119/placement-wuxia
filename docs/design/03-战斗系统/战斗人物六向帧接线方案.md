## 0. 定版主张

1. **快照新增名义六向字段 `facingHex`，旧 `facing` 保留。** `facingHex` 由 session 已有 `Runner.hexFacing` 单点导出；渲染层不根据坐标、目标或旧左右字段猜方向。
2. **资源配置改为“sprite profile + 语义 clip”，渲染只消费解析结果。** hero 使用 directional profile；第一段敌型继续 legacy profile。敌型 `charge/strike → atk` 写在 profile 的状态映射中，禁止在 `frameOf` 写 `actor.side` 特判。
3. **六向全部消费独立 PNG，运行时零镜像。** 左系由美术管线确定性派生并作为成品交付；身体帧、武器贴图和锚点都不在运行时镜像。
4. **`PIECE.heightPerTile` 第一段维持 `2.0`。** 渲染高度由 `TILE_H × 系数` 决定，与源图 240×320 的像素尺寸无关；新帧视觉高占画布 `256/320=0.8`，故当前系数对应约 `1.6` 格视觉高，符合《角色帧规范》“约 1.5 格”。不得仅因源画布变大盲调。
5. **seq=51 只进入第二段。** 山贼身体帧为空手，朴刀为独立六向武器层；`weapon_anchor` 常量表扩 enemy 域。第一段不等山贼、不引入半成品武器逻辑。

## 2. 契约

### 2.1 类型

```ts
export type BattleFacingHex =
  | 'right'
  | 'rightup'
  | 'leftup'
  | 'left'
  | 'leftdown'
  | 'rightdown';

export interface WeaponAnchor {
  x: number;      // 身体源画布坐标，当前基准 240×320
  y: number;
  angle: number;  // 角度单位须由需求真源固定；技术建议使用 degree
}

export interface SnapshotActor {
  // 既有字段不删
  facing: BattleFacing;
  facingHex: BattleFacingHex;
}
```

`BattleFacingHex` 用受限字符串而非任意 `HexPos`，使渲染、路径表和测试都能穷举。`WeaponAnchor` 进入 `types.ts`，但锚点值进入 `config/battle-frames-meta.ts`，符合 ADR-004 的只读展示参数边界。

### 2.2 六向映射（唯一出口）

按当前 `hexToWorld` 投影与 `HEX_DIRS`：

| `Runner.hexFacing` | `SnapshotActor.facingHex` |
|---|---|
| `{q:1,r:0}` | `right` |
| `{q:1,r:-1}` | `rightup` |
| `{q:0,r:-1}` | `leftup` |
| `{q:-1,r:0}` | `left` |
| `{q:-1,r:1}` | `leftdown` |
| `{q:0,r:1}` | `rightdown` |

在 `battle-session.ts` 用一个穷举函数导出；未知值 fail-fast，不回退到 `facing`。`facing` 继续供 legacy profile 和旧消费者使用。session 的转向、射程、rng、结算和动画状态语义零改动。

## 3. 资源与选帧结构

### 3.1 profile 而非渲染分支

建议在 `config/battle-hex.ts` 定义两类 profile：

```ts
type BattleClip = 'idle' | 'walk' | 'jump' | 'atk' | 'cast' | 'die';

type BattleSpriteProfile =
  | { mode: 'legacy'; frameCount: number; frameSrc(i: number): string }
  | {
      mode: 'directional';
      clipCounts: Readonly<Record<BattleClip, number>>;
      frameSrc(clip: BattleClip, facing: BattleFacingHex, ordinal: number): string;
      sharedSrc?: Readonly<Partial<Record<BattleClip, string>>>;
      stateMap: DirectionalStateMap;
    };
```

- `hero` 第一段切为 directional；`npc-shanzei` 暂保留 legacy，保证山贼产线不阻塞主角。
- loader 按 profile 预解码；`die_common` 以 `sharedSrc` 只解码一次。
- `BattleHexAssets.frames` 改为与 profile 对应的判别联合资源库；配置负责“有哪些 clip/路径”，渲染负责“按时钟取 clip 内第几帧”。
- 缺任一声明资源时沿现有 `null → 剪影占位` 防崩，但资源完整性测试必须失败，禁止把占位当通过。

### 3.2 hero 状态语义

| session/表现态 | hero clip | 帧序 |
|---|---|---|
| `idle` | `idle` | 1，保持 |
| 地面移动 | `walk` | 1↔2 循环，沿 `PIECE.walkFrameMs` |
| `isJump` 移动 | `jump` | 1=起跳段，2=腾空至落地；进度阈值放 config，建议 `0.35` |
| `basic` | `atk` | 1→2，播至尾帧保持 |
| `charge` | `cast` | 第 1 帧 |
| `strike` | `cast` | 第 2→3 帧 |
| `dead` | `die_common` | 1，沿既有压扁淡出表现 |
| `hit` | `idle` | 现为休眠态，无专用素材；保现有受击事件 FX，不激活新行为 |

`frameOf` 应升级为“先解析语义 clip，再按对应时钟取 ordinal”。跳跃取 `moveAnim.t / duration`，不能复用 `animState` 的 clock 判同逻辑，否则 `jump` 不是 session 状态而会永远卡第 1 帧。

### 3.3 敌型 cast→atk（seq=47）

第二段 enemy directional profile 定义：

- `charge → atk[0]`
- `strike → atk[1]`（若该敌只有 1 帧则夹到尾帧）
- hero profile 仍为 `charge/strike → cast`，不受此降级影响。

映射落 config profile，不落 `frameOf`。这样将来某敌型补齐 cast，只改该 profile；session 的 `charge → strike` 语义链、时序和事件流不变。

## 4. 渲染与武器层

### 4.1 人物层

`drawPieces` 先从 `spriteKey` 取 profile，再以 `facingHex + clip + ordinal` 取身体帧。directional profile 禁执行旧的 `ctx.scale(-1,1)`；legacy profile 继续消费 `facing` 并保留当前翻转，直至该 sprite 完成迁移。

`PIECE.heightPerTile=2.0` 首段不改：`TILE_H=61.6`，画布渲染高 `123.2px`，人物视觉高约 `123.2×256/320=98.6px≈1.6格`。若三档截图证明 HUD 遮挡或脚底比例不合格，只允许 PM/Leo 按目验结果改这一个展示常量，不改素材或散落缩放公式。

### 4.2 enemy 武器层（seq=51，第二段）

绘制顺序为身体后叠武器；MVP 采用“武器始终前景层”。如 PM 要求按方向穿插身体前后，属于新增遮挡规格，须先扩 manifest，不在实现中猜。

`config/battle-frames-meta.ts` 结构建议：

```ts
export const WEAPON_ANCHORS = {
  'enemy/shanzei_a': { /* facing → clip → ordinal → {x,y,angle} */ },
  'enemy/shanzei_b': { /* 同上 */ },
} satisfies Readonly<Record<string, ...>>;
```

- key 必须区分 `shanzei_a` / `shanzei_b`；当前 demo 两只敌人都用 `spriteKey='npc-shanzei'`，第二段需由资源配置明确变体分派，不能按 actor 数组序在 render 临时猜。建议快照 `spriteKey` 直接输出稳定变体键；变体选择规则须先由 PM 写入需求。
- 身体源矩形为 `(left, top, w, h)` 时，锚点屏幕坐标为 `left + x×h/320`、`top + y×h/320`；武器自身 handle pivot 由武器资源 meta 定义。禁止写第二套比例。
- 朴刀右/右上/右下和镜像左系均为独立成品图；锚点表也逐向给成品值，运行时不做 `x'=W-x` 或 angle 镜像。
- 锚点缺失时只画空手身体并记开发诊断；完整性测试必须红，不得静默通过交付门。

## 9. 第二段主架构补充：battle45/cut 映射、敌型 profile 与死亡白骨

> **补充日期：2026-09-08 · 只补充第二段发卡口径，不改写前 1~8 节已签定结论。**
> 本节将“素材目录是什么”和“运行时状态消费什么”拆开：`battle45/` 是运行时消费面，`cut/` 是抠图/质检中间面；同一单位不得在两套目录之间逐帧混用。

### 9.1 两套目录到动画状态的唯一映射

#### 9.1.1 battle45：运行时 directional profile

所有 battle45 成品均为 240×320 RGBA、六向独立 PNG。`{f}` 只取 `right/rightup/rightdown/left/leftup/leftdown`；渲染器不再做水平翻转。

| 目录/文件模板 | 运行时语义状态 | 帧计划 | 适用与备注 |
|---|---|---|---|
| `battle_idle_{f}.png` | `idle` | 1 帧保持 | hero、`npc-shanzei-a/b` 均消费 |
| `walk_{f}_1.png`、`walk_{f}_2.png` | `walk` | 1↔2 循环 | 沿 `PIECE.walkFrameMs`，不读 `cut/walk_*` |
| `jump_{f}_2.png` | `jump` | hero 当前生产口径 1 帧恒腾空 | `jump_{f}_1.png` 仅作存量备用；敌人不宣告 jump 能力 |
| `atk_{f}_1.png`、`atk_{f}_2.png` | `basic` | 1→2，尾帧保持 | enemy 的 `charge/strike` 降级也从此 clip 取帧 |
| `cast_{f}_1..3.png` | hero `charge/strike` | `charge=1`；`strike=2→3` | 仅 hero profile；enemy 不读 cast 目录 |
| `die_common.png` | `dead` | 1 帧静态 | 无方向、无武器锚；见 §9.3。目标 hero/甲/乙三处文件 SHA 必须一致 |

敌型 `shanzei_a` / `shanzei_b` 的 **runtime 目标目录各为 31 张**：`idle 6 + walk 12 + atk 12 + die_common 1`。这与 §8 的“36 张”是两个统计面：36 张指甲/乙各 3 个右系方向、每向 6 张的**生成基线**（`6×3×2=36`），运行时再由左系确定性镜像展开为每变体 30 张定向帧，并与 1 张共享死亡帧合计 31 张；不得用统计口径差异掩盖缺帧。当前仓库若只落有右系候选，仍按待补齐处理，不能把候选目录写成 runtime 完成。profile 以 `charge→atk_1`、`strike→atk_2` 实现“敌人无 cast 成品”的表现降级；这是 profile 数据映射，不得写成 `frameOf` 内的 `actor.side` 分支。

#### 9.1.2 cut：源素材/质检中间面，不是第二套运行时

当前敌型 `assets/characters/enemy/shanzei_a|b/cut/` 各含 `idle_down/side`、`walk_down/side_1..2`、`atk_down/side_1..3`、`hit_1..2`、`die_1..3` 等 17 张大画布切图；hero 的 `battle_q/cut/` 遵循同一中间面语义。它们只用于选帧、抠图、锚点和 QA，不能被资源 loader 直接预载。

| cut 文件模板 | 对应源语义 | battle45 落地关系 | 运行时 |
|---|---|---|---|
| `idle_down.png` / `idle_side.png` | 待机锚/姿势参考 | 选定后生成/整理为六向 `battle_idle_{f}.png` | 禁止直接消费 |
| `walk_{down|side}_1..2.png` | 行走两相 | 对应 `walk_{f}_1..2` 的源姿势族 | 禁止直接消费 |
| `atk_{down|side}_1..3.png` | 攻击候选三相 | 当前 battle45 最终只落 `atk_{f}_1..2`；第 3 相不自动带入 | 禁止直接消费 |
| `hit_1..2.png` | 受击候选 | 受击表现沿代码震动/掉血 FX；无 `hit` clip 时不接线 | 禁止直接消费 |
| `die_1..3.png` | 旧死亡候选/抠图源 | 不映射为 battle45 多帧死亡；统一收口到 `die_common.png` | 禁止直接消费 |

硬约束：`cut/` 不得成为 battle45 缺帧时的运行时 fallback；不得把 down/side 当作六向方向；不得把 `die_1..3` 当成“白骨动画”接入。

### 9.2 enemy profile 切换策略

#### 9.2.1 稳定键与 profile 表

敌方定义在生成/装配阶段直接写稳定变体键，快照原样导出：

| 稳定 `spriteKey` | `baseDir` | `mode` | `stateMap` 要点 |
|---|---|---|---|
| `npc-shanzei-a` | `assets/characters/enemy/shanzei_a/battle45/` | `directional` | `idle→idle_1`；`walk→walk_1..2`；`basic→atk_1..2`；`charge→atk_1`；`strike→atk_2`；`dead→die_common` |
| `npc-shanzei-b` | `assets/characters/enemy/shanzei_b/battle45/` | `directional` | 与甲同形，路径和锚点键不同；不得复用甲变体 |
| `npc-shanzei-legacy`（迁移回退） | `assets/ui/frames/battle/spr_shanzei/` | `legacy` | 仅旧存档/回滚预览；不作为新敌人定义的默认键 |

禁止在渲染层用 `actor.side`、敌人数组序号、显示名 `name` 或当前帧缺失来猜甲/乙。武器锚点（另卡）也必须以同一稳定键分派；不存在“身体取甲、武器取乙”的组合。

#### 9.2.2 一次性切换与失败处置

profile 在对局建立/资源预载阶段解析一次，随后整局固定；不在 `idle/walk/atk/dead` 之间热切换目录，也不在某一帧从 `battle45` 借帧到 `cut`。

1. **预检**：对 `npc-shanzei-a/b` 逐向逐 clip 检查 manifest、文件名、尺寸、RGBA、SHA；当前敌型期望集合为每变体 31 张。
2. **切换**：预检通过后，session 从敌人定义得到 `spriteKey=npc-shanzei-a|b`，loader 按 directional profile 预载；渲染只消费解析后的 profile。
3. **失败**：预检失败在 CI/开发启动面明确报红；预览可显式指定 `npc-shanzei-legacy` 做回滚诊断，但不得静默混用两套目录，也不得把回退宣称为正式通过。
4. **收口**：稳定键、profile、loader、渲染、demo 和测试同一提交切换；全量回归通过后才移除旧 `npc-shanzei` 默认引用。

敌人没有轻功和独立 cast 成品是已定 MVP 口径：session 不应给 enemy 产生 `isJump`，`charge/strike` 仅由 profile 映射到 `atk`。若未来敌型补齐专用 cast/jump，只新增该 profile 的资源与映射，不改 session 状态链。

### 9.3 死亡白骨帧口径

- **唯一运行时语义**：`animState === 'dead'` 立即覆盖移动/普攻/施法/受击表现，取 profile 的 `dead → die_common`，一张静态躺平白骨帧；不按 `facingHex` 选图、不循环、不镜像。
- **唯一资产形态**：资产交付 commit `b938aba8` 提供 `assets/characters/hero/battle45/die_common.png`、`enemy/shanzei_a/battle45/die_common.png`、`enemy/shanzei_b/battle45/die_common.png` 三处相同字节的基线（SHA-256=`ae5a6ac7b147531042ec7baf29dd63b3e97f9ed6a0d3d637857562eda1088a24`），画布 240×320，alpha bbox `(45,157)-(195,300)`，脚底 `y=300`；实现卡必须以该资产 commit（或后续等价替代）为输入，不能把缺失文件视为已完成。
- **渲染口径**：沿既有 `PIECE.deadAlpha` 和倒地压扁表现绘制；落点仍由格心/脚底基线决定。死亡帧不挂武器锚、不叠武器层、不进棋子 HUD；死亡状态优先级高于移动演出。
- **cut 禁接线**：`cut/die_1..3.png` 是旧大画布源/候选，不是死亡动画帧；禁止把其三帧顺序接入 runtime，禁止为六向复制出 `die_{f}`。
- **完整性门**：三处 `die_common` 必须逐字节一致、透明边界/脚底基线通过；任一缺失只可在开发面报红并显示占位，不得悄悄改取 `cut/die_*`。
