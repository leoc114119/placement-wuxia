## 0. 方案总纲（一屏版）

- **复用不动**：`battle-core.ts`（headless 引擎，14 用例背书）——其 `resolveAction` 等导出已被 A2-T06 打好接口桩，本方案**零改动**消费
- **新建三层**：`hex.ts`（六边形数学，纯函数）→ `battle-session.ts`（对局编排，backend 卡核心）→ `battle-hex-render.ts + battle-input.ts`（渲染与输入，frontend 卡）
- **数据流单向**：core（结算）→ session（编排+快照）→ render（只读快照绘制）；input → session（提交行动）→ core。渲染层**禁止 import battle-core**
- **射程换轨零改 core 的关键**：session 在调 `resolveAction` 前用 hex 距离预筛目标（cube 距离 ≤ `skillRange` 半径），core 内部曼哈顿 blocked 分支自然不触发——度量换轨在适配层完成，引擎行为不变

### 1.2 模块职责与数据流

```
┌────────────────────────── 数据流（单向） ──────────────────────────┐
│                                                                    │
│  battle-core.ts（结算真值：resolveAction/fillRate/skillRange/...）   │
│        ▲ 只读调用              │ ActionOutcome                     │
│  battle-session.ts（对局编排：行动条 tick/轮转/预算/AI/托管）          │
│        ▲ submit*()            │ BattleSnapshot + BattleUiEvent[]  │
│  battle-hex-render.ts（只读快照绘制）  battle-input.ts（输入翻译）     │
│                                    │ ActionRequest                  │
└────────────────────────────────────────────────────────────────────┘
```

**battle-session 职责**（本次新增的关键层，吸取旧 T06 教训——旧 `battle-ui.ts` 把对局编排与演出状态混在一个文件）：

1. **对局生命周期**：deploy（部署位）→ fighting → 结算（won/lost/fled）
2. **行动条驱动**：每帧 `bar += fillRate(actor) × dt`（fillRate 从 core 导入）；满 100 → 进入该 actor 行动回合
3. **行动预算**：按已拍板口径执行（⚠️ 二选一 vs 移动+出招各 1 存在文档冲突，见 §5-O1，session 做成**配置开关**，两种口径同一实现可切）
4. **移动结算**：调 hex.ts 可达搜索 → 更新位置（纯表现位移，不进 core）
5. **出招结算**：hex 距离预筛目标 → 调 core `resolveAction` → 回写结果、生成事件
6. **AI/托管**：B2 五级优先表（集火→技能→普攻→位移→莽）；敌方 AI 同构
7. **快照与事件流**：每帧产出 `BattleSnapshot`（渲染只读）；结算类动作追加 `BattleUiEvent`（确定性回放口径，node 断言同 seed 全等——旧 T06 已验证此机制）

## 2. 六边形渲染器设计

### 2.1 坐标系统

- **存储坐标 = axial (q, r)**（96 号定 cube 系；axial 是 cube 的二维投影，s=-q-r 按需计算）——与 96 号"cube 系"一致且省一字段
- **地图存储 = offset odd-r**（行×列，每行 6-7 格由奇偶行决定，视觉骨架"每行 6-7 格参数化"）：地图 16×16（MVP），可移动区固定 8×8 居中
- 换算：`q = col - floor(row/2)`，`r = row`（odd-r 左移奇数行）

```ts
// types.ts 追加
export interface HexPos { q: number; r: number }
```

### 2.2 像素定位公式（平顶 flat-top，s=31 → 格 62×54pt，96 号定值）

```
中心点：
  px = HEX_S × 1.5 × q + camOffsetX          // s×3/2
  py = HEX_S × √3 × (r + q/2) + camOffsetY   // s×√3×(r+q/2)
六顶点（平顶：顶点在左右，flat 顶边在上下）：
  vertex_k = center + s × (cos(60°·k), sin(60°·k)), k=0..5
```

- `config/battle-hex.ts`：`HEX_S=31`（96 号），三档缩放 s=31/24/16（MVP 先只做 31 单档，缩放档位留常量）
- **底图对位**：`battle_board_base.png` 为无格纯环境图——格子代码层几何真源自对齐（棋盘中心 = 底图台面中心，常量锚点 `BOARD_CENTER` 可调，吸取旧 T06"AI 画板与代码投影两套几何必错位"的教训：**底图零几何契约**，只有氛围）

### 2.3 绘制分层（每帧顺序）

| 层 | 内容 | 来源 |
|---|---|---|
| L0 | 环境底图（屏幕空间静态，不随镜头平移——只拖棋盘不动景） | battle_board_base.png |
| L1 | **格子层**：平顶六边形立体瓦片（顶面草地绿/土黄交替高光 + 侧面深色土层 + 边缘高光描边），仅绘**视口内**格子 | 代码绘制 |
| L2 | **高亮层**：移动范围（绿）/攻击范围（红）/选中格（金）/路径预览 | 代码绘制（数据来自快照） |
| L3 | **棋子层**：立绘 billboard（竖直、y 排序遮挡、朝向翻转、阵亡变灰）；移动 lerp ~0.3s / 轻功抛物线跳跃 | 帧表（T14 Q 版帧，接口可替换） |
| L4 | **棋子 HUD**：头顶三件套（名字牌我方淡绿/敌方淡红字 → 绿行动条 → 红血条，敌我同构）；主角行动条满时头顶弧形弹出特/绝/轻/毒四圆钮 | 代码绘制 |
| L5 | **定稿组件**：topbar.png（头像+双条+状态图标槽×4，叠加代码压暗层）+ plaque_l.png（装备/武功木牌挂串）+ ctrl_r.png（托管/加速/逃跑） | v8 定稿三组件 |
| L6 | 特效层：武功光影（纯代码 fx，四段时序模板沿用旧 T06 已验体系） | 代码绘制 |

### 2.4 视口与镜头

- **7×7 视口**（96 号）：以镜头中心 hex 为准，视口外格子不绘制（性能 + 构图）
- **镜头模式**：手动模式=拖动平移（>8px 判定拖动 vs 点选，旧 T06 已验证）+ clamp 于棋盘包围盒+边距；自动模式=镜头跟随当前行动者（96 号"镜头主权"）
- **包围盒自动取景**（96 号）：战斗双方+主角保证在屏——MVP 简化为主角中心即可，三档取景后置

## 3. 接口契约

### 3.1 battle-core 消费最小面（全部已导出，零改动）

| 导出 | session 用途 |
|---|---|
| `makeInitialPlayer()` / `makeEnemy()` / `rollEnemyCount()` | 开局组装阵容 |
| `fillRate(c)` | 行动条每帧推进 |
| `skillRange(skill)` / `rangeTier(level)` | 射程半径（**数字半径与度量无关**——session 用 hex cube 距离比较，即完成 96 号换轨且 core 不动） |
| `resolveAction(actor, target, skill, rng)` | 出招结算（命中/伤害/扣内力/冷却，唯一真值） |
| `stepManualTimeout(state, dt)` | 托管双阈值 |
| `makeRng(seed)` | 确定性 |

**若开发中发现需要 core 改动**：只允许"抽取导出"级零行为变更（A2-T06 先例），diff 审计 + 既有 14 用例全绿放行；规则/数值/AI 逻辑一行不碰。

### 3.2 BattleSnapshot（session → render，每帧产出，渲染只读）

```ts
export interface SnapshotActor {
  id: string;
  side: 'player' | 'enemy';
  name: string;
  pos: HexPos;              // 逻辑格
  renderPos: { q: number; r: number };  // 渲染格（lerp 追 pos，移动表现）
  hp: number; maxHp: number;
  neili: number; maxNeili: number;
  actionBar: number;        // 0~100
  facing: 'left' | 'right';
  animState: 'idle' | 'walk' | 'charge' | 'strike' | 'basic' | 'hit' | 'dead';
  statusIcons: string[];    // 顶栏四槽数据源（中毒/流血/内伤…）
  isBoss: boolean;
  spriteKey: string;        // 帧表资源键（走资源管理器）
}
export interface BattleSnapshot {
  phase: 'deploy' | 'fighting' | 'won' | 'lost' | 'fled';
  turnActorId: string | null;        // 当前行动者
  pendingInput: boolean;             // 等待主角输入（行动条满+手动模式）
  moveCells: HexPos[];               // 可移动高亮（绿）
  attackCells: HexPos[];             // 攻击范围高亮（红，激活技能后）
  selectedSkill: string | null;      // 已激活待施放的技能 id
  actors: SnapshotActor[];
  cameraTargetId: string;            // 镜头跟随目标（自动模式）
}
```

### 3.3 ActionRequest（input → session）

```ts
export type ActionRequest =
  | { type: 'move'; to: HexPos }
  | { type: 'attack'; targetId: string; skillId: string | null }  // null=普攻
  | { type: 'selectSkill'; skillId: string }                       // 激活特/绝/轻/毒（进入攻击范围显示态）
  | { type: 'cancelSkill' }
  | { type: 'setMode'; mode: 'auto' | 'manual' }
  | { type: 'toggleSpeed' }
  | { type: 'flee' };
```

session 校验（合法性：行动预算/距离/内力/冷却）→ 执行 → 快照与事件流更新；非法请求静默拒绝（返回 boolean 供输入层反馈）。

### 3.4 事件流（确定性口径）

`BattleUiEvent`（沿用旧 T06 已验证结构：t/type/actorId/targetId/damage…）；同 seed + 同操作序列 → 事件流全等（node 断言，作为 backend 卡 DoD 硬项）。
