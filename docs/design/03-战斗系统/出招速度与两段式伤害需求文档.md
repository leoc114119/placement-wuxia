## 一、机制总述

**出招速度**是战斗基础数值：决定招式时长（速度快=时长短）。其衍生表现=**两段式伤害**：技能伤害拆两段落、两次扣血、两跳数字——出招快者两跳密集，出招慢者两跳拉开，速度由此获得手感表达。**无打断机制**（出招不可被中断）；**无内伤**（两段均为外伤，走血条）。

| # | 口径 | 备注 |
|---|---|---|

## 三、行为规格（草案条目，编号暂 AS-1 起，定稿后并入交互规格 v2.5）

| 编号 | 规格 |
|---|---|
| AS-1 | **招式时长公式（v1.2 Leo 定版 · 09-07 勘误：本行 v1.1 乘法残留作废，以 9081e29 加法模型为准）**：`时长(ms) = 3000 ÷ min(6, 武功出招系数 + 内功加成速度)`——加法合成；**和封顶 ≤6 → 最快 500ms**（封顶在加成侧，时长零特判、无第二道 clamp）。**武功出招系数**=castSpeed 个体差异属性（初始 0.8；轻招可<1、绝学可 2；随武功等级↑，20/40/60 档持续提升——等级影响经由系数数值体现，成长曲线归 C 案数值域，schema v0.2）；**内功加成速度**=internalCastSpeed（初始 0.2，随内功等级↑，归内功系统 schema；session 只读成长域快照值，禁读 level 反推）。**人物属性不影响出招**（身法类只管闪避）。普攻不消费此公式（独立常量=1s） |
| AS-2 | **出招段（09-07 二次修订）**：时长=招式时长（AS-1），施法帧**整套循环播放至时长结束**；**循环帧周期独立常量=280ms/帧**（09-07 Leo L 环反馈"太快一直在甩"，与行走帧时钟 140ms 解耦——蓄力挥砍观感，一套 3 帧约 0.84s）；期间行动条/回合推进语义不变更（BAR-3 清零仍在提交时） |
| AS-3 | **第一段伤害（09-07 Leo 终裁=出招时结算，取代"出招时长结束点"旧案）**：技能提交时刻（t0）**即时结算**——与命中帧演出同步，50% 伤害独立判定；目标=t0 时刻 rangeShape 范围内存活敌（即时范围判定，**出手必中**——范围内者无法躲避第一段） |
| AS-4 | **第二段伤害（09-07 Leo 终裁=收招时结算）**：施法帧循环结束时刻（t1=t0+招式时长）结算——50% 伤害独立判定；**两段间隔=整个出招时长**（3s 招两跳隔 3s，0.5s 快招两跳近乎连击）；目标按 AS-6 动态追踪在 t1 重搜（**走位可躲第二段**）；两段 miss 独立（可一中一闪）；旧"收招窗 300ms"独立结算概念取消（循环末帧即收势，结算后回站立） |
| AS-5 | 事件流：两段各发一条结算事件（skill|miss ×2，各带 targetId/damage）——**每段一条**（段1 时刻=t0，段2 时刻=t1），契约形状沿用（零新增类型） |
| AS-6 | **目标语义（09-07 Leo 终裁=动态追踪；同日二次修订适配新两段时序）**：**第一段=t0 提交即时范围判定**（现行 AOE 语义：此刻 rangeShape 范围内存活敌按 all 序取成员——**出手必中**，范围内者无法躲避第一段）；**第二段=t1 循环结束时刻重搜**——以提交时施放格为锚（施法期间不可移动，锚稳定）、按该技能 rangeShape 重算范围、存活敌按 all 顺序取成员；施法期间走位可走出/走入范围（**慢招收招可躲/快招难躲=出招速度的博弈维度**）；死者自然不进集合、不消费 RNG；**第二段重搜为空=仅第二段不发**（第一段已在 t0 结算，无退款无补偿事件）；确定性不降级=重搜规则写死（锚格/形状/顺序），SP-2 全等语义不变 |
| AS-6b | **施法者死亡语义（09-07 Leo 终裁=A 消散）**：第一段已随 t0 提交即时结算；施法者死亡=招式消散——**pending 第二段撤销，t1 零结算零事件**；"无打断"边界=**活体**施法不可被伤害中断（六点⑥不变），致死=施法源消失；AI/玩家同规则 |
| AS-7 | AI 出手同规则（敌方同规则，v2.2 五点⑤延续；动态追踪重搜 AI/玩家同一条代码路径） |
| AS-8 | 演出牵连（09-07 二次修订）：冒字两跳（T21 队列天然支持，同位错位防重叠）——**第一跳与提交/命中帧同步（t0），第二跳与循环结束同步（t1）**；血条两次下移；施法循环帧周期 280ms/帧（AS-2）；循环结束结算后回站立 |
| AS-9 | **终局语义（09-07 Leo 裁）**：某段结算使一方胜利→立即终局，未到时段不再结算伤害（**终局后零新增伤害事件**；新时序下=段1 t0 致胜则段2 不结算）；施法**表现帧由 FE 继续播完**（纯动画，不写血量/不发结算事件） |

## 四、影响面与流程定位

- **语义级变更**（需主架构方案+Leo 拍板）：session 结算时序从"提交瞬间一次结清"扩展为"两段错时结算"（第二段锚在收招终点）——涉 tick 驱动/事件流/快照 hp 时序；T21 冒字与斩击弧时序对齐；e2e 时序断言配套
- **数值域**：出招速度入 C 案数值体系（新 R-xx/F-xx 编号挂靠武功 schema v0.1 的 movBonus 同层）；MVP 只落常量+挂点，完整数值框架（武功速度值/内功加成）随成长线后置
- **规格归并**：定稿后并入《战斗交互行为规格》v2.5（AS-* 条目+矩阵行）

## 五、开放点（09-06 二轮 Leo 全裁）

| # | 裁定 |
|---|---|
| ① 循环 | **循环时长=出招时长本身**：出招时间多长施放帧就循环多久（整套循环），不单独锚定出招帧/收招帧 |
| ② 两段落点 | 出招时长结束=招式落地（**第一段**）；随后收尾窗口终点=**第二段**（收尾窗时长=表现常量，施工定默认值） |
| ③ 普攻 | **延长至 1 秒**（节奏感） |
| ④ 数值（补裁） | 技能出招**基准 3s**；人物属性×武功速度×内功加成收窄，**下限 0.5s**。MVP=3s 基准+0.5s clamp+速度挂点，完整数值框架随成长线 |
