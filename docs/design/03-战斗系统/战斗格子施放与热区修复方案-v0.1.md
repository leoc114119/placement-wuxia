## 三、P-2=c 格子施放设计

### 3.1 契约：ActionRequest 新增 cast 变体（types.ts 唯一变更，BE 卡 DoR 冻结）

```ts
| { type: 'cast'; to: HexPos; skillId: string }   // 对格施放（ATK-2/6/7 v2.0）：to=目标格（axial），skillId=选中攻击技
```

- attack 变体**原样不动**（单位目标：普攻 + 直接 submit 的兼容入口，保 §2.5 前三条绿锁）。
- 空放**事件**表达：复用 `skill` 事件——`{type:'skill', actorId, skillId}`，**无 targetId 无 damage** 即空放（字段本就可选，零新增）；对敌格 cast 走 doAttack 照常带 targetId/damage。
- **快照零改动**；`BattleUiEvent` 零改动。

### 3.2 session cast 分支（BE 卡本体 · 单点插入 submit，既有分支零改写）

```ts
if (req.type === 'cast') {
  if (!pendingInputNow()) { emit rejected(bar); return false; }                    // 与 move/attack 同门
  if (!selection || selection.kind !== 'attack' || selection.skillId !== req.skillId) {
    emit rejected(invalid); return false;                                          // 无选中/qing 态/陈旧 skillId
  }
  const s = player.skills.find(x => x.id === req.skillId);
  if (!s) { emit rejected(invalid); return false; }
  if ((s.weapon !== null && s.weapon !== player.weapon) ||                         // R-05
      (player.cooldowns.get(s.id) ?? 0) > 0 ||                                     // R-08
      player.neili < NEILI_COST_PER_CAST) { emit rejected(invalid); return false; } // R-09（提交时重查，防激活后漂移）
  const inRange = hexEq(req.to, player.hex) ||                                     // Q2：自己格=可施放格（特判，不入 legalCells）
    selection.legalCells.some(p => hexEq(p, req.to));                              // 射程与快照同源（病灶③：显示=校验）
  if (!inRange) { emit rejected(range); return false; }                            // 射程外（input 层应走 cancel；直接 cast=非法，SP-3）
  const target = alive().find(x => x.side !== player.side && hexEq(x.hex, req.to));// ATK-7：提交瞬间按逻辑位查格上敌
  tickCooldowns(player);                                                           // 读后递减，与 attack 分支同位
  if (target) {
    doAttack(player, target, s);        // 既有路径：resolveAction（R-09/R-08 副作用）+ skill/miss 事件 + charge 演出
  } else {
    // ATK-6 空放：resolveAction 不调（battle-core 零改动），session 逐字段镜像资源
    player.neili -= NEILI_COST_PER_CAST;                                           // R-09 镜像（skillView 同值，禁用 SkillDef.neiliCost）
    if (s.cooldownTurns > 0) player.cooldowns.set(s.id, s.cooldownTurns);          // R-08 镜像 core:246 条件式
    setAnim(player, 'charge');                                                     // Q3：施放演出照播（charge→strike 既有 anim 链，无受击 FX）
    faceToward(player, req.to);                                                    // 朝目标格出招
    emit({ type: 'skill', actorId: player.id, skillId: s.id });                    // 空放事件=skill 无 targetId 无 damage
  }
  commitTurn(player);                                                              // BAR-3 清零 + SEL-3 选中清除
  return true;
}
```

- **四查射程源 = `selection.legalCells`**（快照 attackCells 同一产生点，activate 时已算）——cast 与显示零漂移。
- attack(skillId≠null) 分支**保留不动**：行为套件 ATK-2 绿锁（直接 submit attack）与 mock/旧调用兼容；input 层不再派发它（§3.3），属「兼容保留」而非决策点（cast 是 input 唯一新路径；两分支语义同源 ATK-2 四查）。
- 空放与对敌施放的**资源终态必须全等**（内力/冷却/bar/选中四项）——用例逐项锁（§七-1）。

### 3.3 input 统一 cast 派发（FE 卡本体 · 方案 B：skill 态点格一律 cast）

`ui/battle-input.ts up()` 改两处，分支序不变：

```
① target 命中分支（点敌逻辑格）改写：
   qing → return（ATK-4，不变）
   skill（特/绝）→ dispatch({type:'cast', to: cell, skillId: skill})   // ATK-7「点逻辑格照常 ATK-2」=格上有敌的 cast
   !skill → dispatch({type:'attack', targetId, skillId: null})          // ATK-1 普攻，不变
② 尾分支 `skill && !inAttack → cancelSkill` 改写为 skill 态（特/绝）点非敌格：
   const me = snapshot.actors.find(a => a.side === 'player')            // MVP 单人；禁用本地状态
   castable = inAttack || sameCell(cell, me.pos)                        // 射程内格 ∪ 自己格（Q2）
   castable → dispatch({type:'cast', to: cell, skillId: skill})         // 空格/演出位格统一受理（ATK-6/ATK-7）
   否则 → dispatch({type:'cancelSkill'})                                // SEL-5②：射程外=取消
```

- 其余分支零改动：弧钮/ctrl/plaque/出界取消/qing 金格/无选中绿格/T19 普攻态演出位拦截（`!skill` 段与 skill 段互斥，顺序无冲突）。
- **方案 B 理由**（§九-2 背书项）：保留「点敌格→attack、点空格→cast」双派发 = 射程判定双决策点（attack 走 targetInRange 逻辑位、cast 走 legalCells），敌人移动中两口径可分叉——正是 N1N2 病灶框架警告的漂移结构；统一 cast 后 input 对「skill 态点格」只有一个决策点，ATK-7 的演出位/空格/敌格三情形自然归一。代价 = battle-hex-render.test.ts:339 请求形状断言随卡重写（§2.5 已列，规格依据 ATK-2 v2.0）。

### 3.4 ATK-7 实现面（零专门代码 · Q6 确认）

格子目标化后 ATK-7 是 cast 的**自然推论**，无需 input 识别「这是某敌的演出位」：玩家点可见位 → worldToHex 量化为某格 → ∈ attackCells 则 cast(该格)；session 提交瞬间按逻辑位查格上敌——有敌结算、无敌空放。点击格恰为**另一敌**逻辑格 = 正常对敌结算（ATK-2，非歧义）。

## 四、D-13 热区设计（HIT-1 落地 · 几何标定）

### 4.1 判定模型

- 热区 = **每可点部件的实际图形标定矩形 + 容差**：ctrl = 三钮各一矩形（art 坐标）；plaque = 两牌各一矩形。**装饰件（plaque 横杆/挂绳/流苏、art 边缘光晕）不设热区**——HIT-1「组件实际图形」收窄解释为「**可点部件**的实际图形」（挂件装饰非按钮，点了无动作，吞棋盘格点击反而有害；此解释列入 §九-5 背书）。
- 判定顺序不变（HIT-1：组件图形内命中仍高于棋盘格）：弧钮 → ctrl（逐钮矩形）→ plaque（逐牌矩形）→ 棋盘格。图形外一律 fall-through 到棋盘。
- 容差：矩形四边外扩 `短边 × tolRatio`，`tolRatio=0.15`（对齐弧钮 1.3 半径容差的折算精度；config 展示参数，preview 手感可调）。

### 4.2 标定值与 config 落点

- **方法**：临时脚本量 alpha>240 实体 bbox/最长连续实体行（复用 `proto/battle_demo/cutout/png_codec.mjs` 零依赖解码；本方案 §2.4 数据即出自该法）——FE 卡施工时复跑核定落库值，建议脚本入库 `cutout/measure_hotzones.mjs` 供素材迭代复用。
- **参考值（当前素材）**：ctrl 钮1 `{x:5,y:2,w:216,h:128}` / 钮2 `{x:5,y:163,w:213,h:126}` / 钮3 `{x:5,y:319,w:213,h:127}`（行宽下限 202 收安全边）；plaque 牌1/牌2 `{x:26,w:273,h:143}`（y 沿牌体实体带，FE 卡核定）。落 `config/battle-hex.ts`：扩展 `CTRL_BUTTONS` 行结构增 `x/w` 字段 + `PLAQUE_BUTTONS` 增 `xRatio/wRatio` + 新增 `HIT_TOL = { ratio: 0.15 }`；input 侧新增纯函数 `pickCtrlButton(view,x,y)` / `pickPlaqueButton(view,x,y)`（导出供用例，对齐 `pickSkillButton` 先例），替换 up() ②③ 段的外接矩形判定。art→屏换算沿用 ctrlRect/plaqueRect 现式（ay 同式，加 ax）。

### 4.3 用例对表（HIT-1 矩阵行落地）

- 新增：ctrl 外接矩形内、钮间隙/边缘的棋盘格点击 → fall-through 棋盘受理（不被组件吞）；plaque 左右透明边同理；图形内 → 组件命中优先。点击点必须取「外接矩形内、标定矩形外」的**棋盘格中心**（取点错=测的旧热区，§七-19）。
- 对表：battle-hex-render.test.ts:441-450 ctrl 三钮行命中——既有点击点均在行带实体内，预计保持绿；FE 卡逐点核对，落新矩形外者按 HIT-1 配套改写并注明依据。

## 七、易错点清单（铁律 7 · 从本方案用例长出，与 N1N2 §九 18 条互补不重复）

**BE 侧（session cast）**
1. 空放资源四项与对敌施放**终态全等**：neili 扣 `NEILI_COST_PER_CAST`（=1，skillView 同值；**禁用 SkillDef.neiliCost** 20/35）、冷却镜像 core:246 条件式（`cooldownTurns>0` 才写、写初值不写 −1）、bar=0（commitTurn）、选中清（commitTurn）——新用例逐项断言，防镜像漂移。
2. tickCooldowns 调用位=四查后、doAttack/空放前（与 attack 分支同位）——错位=读后递减乱序，SEL-3 冷却用例必红。
3. cast 射程外 → `rejected(reason='range')`（非静默、非 invalid）——SP-3 拒绝序列确定性，用例锁。
4. 空放事件=skill 且**无 targetId 无 damage**——断言以 targetId 有无区分空放/对敌；写漏 skillId 则 FE 演出无法区分。
5. 空放 `setAnim('charge')` + `faceToward(req.to)`；**不得**走 basicIfAdjacent（非移动行动）。
6. Q2 自己格特判=与 legalCells 查询**并联**（`hexEq(to, player.hex) || …`）——不得并入 legalCells/attackCells（快照高亮不含自己格是验收口径，rangeCells 冻结不动）。
7. 选中态门：qing 态/无选中/`skillId !== selection.skillId`（陈旧 id）→ rejected(invalid)；cast 不得激活技能（激活只走 selectSkill）。
8. attack 分支（skillId≠null）**一行不动**——行为套件 ATK-2 绿锁直接 submit attack，动了即改写已验收行为。
9. 新例造冷却态注意：`place()` 基建**不重置 cooldowns**——冷却用例用全新 session 或手动清，防跨用例泄漏假红。
10. 主套件新例命名带条目编号（`[ATK-6]` 等，沿 battle-session.test.ts 惯例），红名单外新增用例走「先红后修」不适用——本批为规格新增行为，直接绿例对号。
