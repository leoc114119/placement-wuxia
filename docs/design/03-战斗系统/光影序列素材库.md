## 2. 拆分规律（Leo 实证 + 全量普查验证）

1. **纵向胶带**：每张 BMP = 一条自上而下逐帧播放的动画长条。
2. **正方形帧（核心规律）**：`帧高 = 帧宽`。KF1 全量普查 149/154 服从，且每条内部切割线±1 行最大亮度 ≤55（切在纯黑帧间隙）。
3. **帧数不限于 6~13**：高÷宽即帧数，实测 1~31 帧都有（如 102-1=31 帧莲花、114-1=25 帧）。
4. **宽≠高个案（scan）**：少数文件帧高≠帧宽（如 KF1/15-1=320×2160 → 9 帧×240）。判定法：扫全部整除候选（帧高≥宽/2），取**切割线全暗候选中帧高最小者**（大帧高会把多帧连成一块仍全暗，故取最小）。五目录 scan 个案 59 张，切线均全暗。
5. **质检口径**：每条内部切割线 ±1 行最大亮度 ≤55 = PASS；>55 标 `suspicious`（多为白雾/火光溢出，切法通常仍正确，须目验）。五目录 suspicious 合计 14 张。
6. **空帧剔除**：alpha 最大值 ≤2 的帧判空不存出（动画首尾全黑帧）。
7. **一条带可含多段动画**（如 114-1 前 13 帧绿弧+后 12 帧紫爆）：**Leo 定案 09-08——一个文件=一个序列，保持不拆**，归类时备注即可。

## 3. 工具与库结构

```bash
# 切帧（按目录）
python3 scripts/fx_slice.py assets/_trial_20260907/wangjin_fx_raw/<KF> assets/_trial_20260907/wangjin_fx_units --kf-label <KF>
# 重跑前必须先删旧 units/<label>/（旧帧文件不自动清理，防残留混帧）
```

- `scripts/fx_slice.py` v2：正方形帧判定 + scan 扫描 + 黑底转 alpha + 空帧剔除 + contact 分页
- 产出：`assets/_trial_20260907/wangjin_fx_units/units/<kf小写>/`
  - 帧 PNG：`<源文件名>_fNN.png`（NN=播放顺序，01 起，空帧跳号）
  - `manifest.json`：逐序列登记 size/frames/frame_h/detect/cut_max/status/empty_frames
- contact：`wangjin_fx_units/<kf>_contact_pN.png`，每行=一条序列完整帧序（中灰底+每帧描边框），行首标 `文件名 帧数f 帧高h [状态]`

## 4. 透明背景验证结论（09-08 全量程序化检查）

- 6540 帧全部 **RGBA**，PNG；alpha = max(R,G,B)（黑底加色光效 → 黑底全透明、光效本体不透明、边缘软过渡）
- 全量含全透明像素；唯一特例 kf6/17-1_f05、f06（350×350 暗雾铺满整帧，最低 alpha≈3%，渲染无碍）
- 约 5% 帧为动画末尾渐隐余晖帧（无 >200 的不透明像素），正常
- **可直接用于游戏渲染**；建议发光体叠加用加色合成（Canvas `globalCompositeOperation='lighter'`）防暗边、光效更透亮

## 6. 武功配方结构（Leo 口径：每武功 ≈ 3~5 序列叠放组合）

配方 = 按时间轴叠放 3~5 个序列，各序列可独立指定缩放/角度/色相/起止时刻。示例（序列号见附录）：

- **特功·单体爆发**（如"三花聚顶"）：聚气 `kf3/27-1`(蓝点聚刺爆) → 主体爆 `kf1/14-1`(刺环+金爆 22f) → 余韵 `kf1/125-1`(橙月牙)
- **绝功·灵兽大招**（如"金蛇狂舞"）：施法圈 `kf7/15-1`(紫环收缩+绿粒子) → 主体 `kf3/40-1`(金龙盘绕) → 落地环 `kf1/69-1`(橙扁环升) → 散雾 `kf7/69-1`(白云爆)
- **字效名条**（WF-2 配套）：汉字 `kf1/146-1~154-1`(佛/武/金/柔/風/雪/絕/劍/雲 单帧) + 背光 `kf1/61-1`(白光柱+涟漪盘)
- **轻功身法**：冲刺 `kf3/12-1`(蓝人形残影) + 脚下环 `kf6/70-1`(蓝扁环扩)

## 7. 组合后台（形态选型呈报，待 Leo 拍板立项）

Leo 已点名"要弄一个后台来组合帧配置成不同的武功特效"。PM 建议形态：

- **推荐：本地 Web 工具页**（preview/ 同级，浏览器打开）——加载 units/ PNG 库 + manifest，时间轴/图层式叠加预览（缩放/角度/色相/时序），调好后导出**配方 JSON**；游戏内 runtime 按 JSON 叠放播放。优点：零游戏内侵入、PM 和美术都能用、迭代不占小游戏包体。
- 备选：游戏内开发者面板——优点所见即所得，缺点占包体、要跟随发版、非程序员不好维护。
- 共同前提：runtime 需要一个"配方播放器"模块（读 JSON + 叠放 sprite + 加色合成），属战斗前端小卡，可与工具页拆两期。
