# WF-2 武功名条技术方案

> 分类：03-战斗系统 · 性质：研发施工蓝图（本文件不含代码实现）<br>
> 方案版本：v0.1 · 2026-09-08 · 基座：`task/fx-trial-01@96dcaca`<br>
> 需求真源：《武功名弹出与施法特效需求文档》v1.2 的 WF-1/WF-2/WF-3/WF-5/WF-6/WF-10；seq=155 勘误覆盖 seq=154 的路线<br>
> 状态：🟡 待 PM 发卡

## 1. 目标与边界

特技或绝学被接受施放时，在施法者头顶显示 `SkillDef.name` 的动态文字，和 T25 光影在同一个 `t0` 开始。名条是纯 Canvas 代码字：不把 glyph 单字素材当文字主体，不加音效，不改伤害、范围、行动条、RNG、结算事件或战斗时钟。

本方案只负责 WF-2 名条的文字、动画、可读性和接线；T25 的光影配方、素材帧和播放器仍由其方案负责。glyph 光效若未来通过素材门，只能作为文字背后的可选背光，默认关闭，不能成为名条预载依赖。

## 2. 已裁决的总方案

| 项目 | 方案 | 取舍理由 |
|---|---|---|
| 渲染归属 | 新建 `ui/wf-banner.ts`，由 `battle-hex-render.ts` 在世界裁剪恢复后、`drawComponents` 前调用 | 名条是屏幕空间演出；独立模块可单测时钟/曲线/生命周期，避免把文字状态塞进棋子 HUD，也不复制格心公式 |
| 锚点 | `t0` 快照的施法者头顶世界锚点；每帧用当前 camera 投影到屏幕。逻辑锚定、不跟随后续 `renderPos`；R1 施法不可移动，镜头拖动时仍不与棋盘脱节 | 明确采用“定格于施法者头顶”，不采用跟随移动；角色死亡/终局也继续把已接受的名条播完 1s |
| 主体文字 | `ctx.strokeText` 先描边、`ctx.fillText` 后填充；文本原样为宿主传入的 `SkillDef.name` | 多字动态文本不能用素材逐字拼接；渲染层不反查技能配置、不改名、不截断 |
| 字体 | 首选既有 `FONT_STACK`（宋体族）加粗 700，并用字距、描边和金/红填充形成书法感；不强依赖额外字体文件 | 微信小游戏系统字体可用性和授权不稳定；统一战斗代码字栈优先于新增字体依赖。若未来有已授权字体，`wx.loadFontFace` 只作可选首选，失败/超时立即回退 `FONT_STACK`，不得阻塞战斗 |
| 可读性 | 深墨圆角描边 + 轻墨投影，默认无不透明底板；禁止把名条做成厚重胶囊遮住角色/FX | 在草地、土路、光影上保留轮廓；描边与投影已覆盖需求的“背景或描边”可读性处理 |
| 触发 | 复用 T25 的 accepted-cast `t0` 单次触发门，由同一个 fan-out 同时调用 `fx.start` 和 `wfBanner.start` | 不另订名条事件，不监听命中/伤害；一次施放一次名条 |
| 适用技能 | `SkillDef.kind === 'special'` 用特技色；`kind === 'ultimate'` 用绝学色。`qingGong`、普攻、暗器、外功、`rejected` 一律不弹 | 与 WF-5 及现有 `SkillKind` 对齐，避免用按钮标签或 grade 猜品阶 |

## 3. 数据流与接线

### 3.1 文字来源（无契约新增）

宿主在 accepted cast 门已拿到 `actorId + skillId + t0 + 施法者快照`。宿主侧的 `SkillDef` 注册表（demo 为 `DEMO_SKILLS`，正式服为既有技能装配）解析出 `name` 和 `kind`，然后将最小展示包交给播放器：

```text
{ text: SkillDef.name, tier: 'special' | 'ultimate',
  anchorWorld: casterCellCenterAtT0, startedAtSec: presentationClock }
```

`wf-banner.ts` 只接受字符串和已判定的 `tier`，不 import `battle-core`/`battle-session`，不从 `skillId` 自查配置。技能缺失或 `name` 为空时记录一次告警并跳过，不显示假名字、不回退成“特/绝”。不新增 `BattleUiEvent.skillName` 字段，避免契约变更。

### 3.2 与 T25 同刻触发

把当前 T25 的 accepted-cast 处理收敛为一个只执行一次的演出 fan-out：

```text
accepted cast t0
  └─ startCastPresentation(cast, skillDef, casterAnchor)
       ├─ fxPlayer.start(...)       // T25，时长 T = castDurationMs
       └─ wfBanner.start(...)       // WF-2，时长固定 1.0s
```

名条不以 `e.type === 'skill'` 的命中事件为唯一入口。全闪避（只有 `miss`）、空放、t0 致死终局都必须能走同一个 accepted-cast 门；`skill`/`miss` 目标事件若仍作为现有演示的观测入口，必须共用 `(actorId,t0)` 去重。`rejected` 没有 accepted cast，不触发任何一层演出。此项是 T25 触发缺陷的明确前置修复，WF-2 不复制一份较弱的事件监听器。

敌方 AI 施放同样走此 fan-out：从敌方自己的 `SkillDef` 取名和 tier，锚定敌方 t0 头顶，颜色仍按 tier 而不是按阵营改变。

### 3.3 屏幕层绘制顺序

`drawFrame` 保持现有世界层顺序（棋子 → T25 `fxWorld` → 棋子 HUD → 既有伤害/提示 FX）。在 `ctx.restore()` 后调用 `wfBanner.draw(ctx, width, height, camera)`，再画 `drawComponents`，最后画结算遮罩：

```text
world clip: cells → pieces → fxWorld → piece HUD → damage FX
screen overlay: WF-2 name banners → top/side components → phase overlay
```

播放器保存 t0 世界锚点和头顶偏移；绘制时只做 `world - camera + screenCenter`，禁止在 `wf-banner.ts` 重新实现 `hexToWorld`。屏幕坐标层不使用 `globalCompositeOperation='lighter'`，避免把 T25 加色状态泄漏到 HUD。

## 4. 视觉参数与动画

以下均为 `config/battle-hex.ts` 的只读展示参数组 `WF_BANNER`；渲染器不得散落硬编码，也不写入 `config/numbers.ts`。

### 4.1 字号、色值与可读性

- 基准字号沿用既有伤害数字的屏高定尺：`baseDamagePx = round(H × DMG.fontPerH)`，名条字号 `round(baseDamagePx × 1.5)`。倍率固定为 1.5，不随 `castDurationMs`、技能等级、镜头或伤害数值改变。
- 特技填充色：`PALETTE.gold`（`#D4AF37`）；绝学填充采用金红纵向渐变 `#FFD66B → PALETTE.cinnabar`（`#E2574C`）。渐变只改变视觉，不表达数值。
- 两种 tier 都用墨色描边 `#2B2B2B`，线宽 `max(2, round(fontPx × 0.12))`，`lineJoin='round'`；投影为 `rgba(43,43,43,.45)`，偏移 `(0,2)`、模糊 4px。绘制顺序固定为投影 → 描边 → 填充。
- 名条默认不画实心底板，以免遮住角色和 T25 光影；若 L 环证明复杂背景仍不可读，只能在本参数组新增低 alpha 宣纸底板并走一次目验，不能在渲染器临时加黑块。
- 文字过长时保持垂直字号不变，仅按 `maxWidth = min(0.82 × W, W - 2 × safePx)` 做 `scaleX ≤ 1` 压缩，居中绘制，禁止静默截字或换成省略号。

### 4.2 固定 1s 浮起淡出

名条寿命为 **1.000s 的演出时钟**，不读取、不乘、不除 `T`。演出时钟沿用现有 `view.time`：x1/x2 只改变演出钟推进速度，因此 x2 下墙上时间会减半，但逻辑寿命仍是 1.000s；它不因快招/慢招再做第二次缩放。

设 `p = clamp((now - startedAtSec) / 1.0, 0, 1)`：

- 上浮：`y = baseY - risePx × easeOutCubic(p)`，`risePx = 24`；
- 淡入：`0 ≤ p < 0.10` 用 smoothstep 从 0 到 1；
- 保持后淡出：`0.10 ≤ p < 0.65` 保持不透明；`0.65 ≤ p ≤ 1` 用 smoothstep 从 1 到 0；
- `p ≥ 1` 移除实例。t0 立即创建实例，首帧不等待命中、伤害或 t1。

同一画面最多保留不同施法者各一条；同一 actor 因去重门不会重叠生成。对局重置、逃跑或 session 重建调用 `clearAll`；正常死亡、胜负终局不截断已接受且未到 1s 的名条。

## 5. 字体加载与平台兜底

1. MVP 不新增字体资产：Canvas 直接使用 `FONT_STACK`，微信端按系统可用字体顺序回退到 `serif`。这条路径不需要异步预载，不会因字体加载阻塞首个演出。
2. 若后续引入**已授权**书法字体，战斗入口可调用 `wx.loadFontFace` 并以字体名插在 `FONT_STACK` 前；加载成功只改善字形，加载失败、超时或缺字都回退既有栈。不得把字体下载、网络可用性或字体成功率写入战斗结果。
3. 浏览器预览沿同一 CSS 字体名执行；`preview/game-preview.html` 的 `FILES` 只需增加 `dist/ui/wf-banner.js` 及直接依赖，不引入字体下载地址。截图验收要在“自定义字体不可用”的回退环境也通过。

## 6. glyph 背光装饰（可选、非主体）

`assets/ui/fx` 中的单字 glyph 不参与文字排版，也不按多字名条逐字拼接。若未来有通过 PM 素材门的背光件，可在 `ctx` 中先画一个低 alpha、短寿命的单层 halo，再画代码字；没有背光件时完全跳过，文字仍必须独立可读。WF-2 的运行时预载、SHA 清单和 DoD 不包含 glyph；任何候选素材不得标成“已入库/已过门”。

## 7. 文件面与禁碰区

| 类型 | 文件 | WF-2 动作 |
|---|---|---|
| 播放器 | `ui/wf-banner.ts` | 新建；纯 view 状态、t0 锚点、1s 曲线、Canvas 文字绘制、清理 |
| 战场接线 | `ui/battle-hex-render.ts` | 增加 view 持有物和屏幕层 hook；不复制几何公式、不改既有 HUD/DMG 语义 |
| 展示参数 | `config/battle-hex.ts` | 新增 `WF_BANNER`（字号倍率、色值、描边/投影、时长、上浮量、字体栈）；只读展示值 |
| 触发宿主 | `proto/battle_demo/main.ts`（正式宿主沿用同一 fan-out） | 复用 T25 accepted-cast 门，解析 `SkillDef.name/kind`，一次调用 FX+名条；不新增事件字段 |
| 预览 | `preview/game-preview.html` | `FILES` 加入 `dist/ui/wf-banner.js` 及直接依赖，确认 file:// 预览可加载 |
| 测试 | `tests/wf-banner.test.ts`；必要时补 demo 触发测试 | 曲线/字号/颜色/去重/清理/敌我/技能白名单/全闪避与空放入口 |

明确禁碰：`cloudfunctions/settle/core.js`、`systems/battle-core.ts`、`systems/battle-session.ts`、`types.ts`（本卡不加事件字段）、结算相关逻辑、`config/numbers.ts`、T25 光影素材与配方、音效。禁止把 glyph 当名条主体，禁止渲染层 import 战斗核心或自行查技能配置。

## 9. 单卡拆分建议

建议 **WF-2 一张前端纵向切片单卡**：`wf-banner` 纯逻辑 → 参数组 → `drawFrame` 屏幕层 → accepted-cast fan-out → 预览 FILES → 六档截图/单测，所有环节共享同一 `startedAtSec` 和文字快照，避免“能画字但触发不同刻”的半成品。

T25 当前已知的 accepted-cast 触发门缺陷（仅监听 `skill` 会漏全闪避/终局）和预载 reject 收敛应作为**独立前置修复/依赖**明确落卡；WF-2 不悄悄改写 T25 播放器，也不以弱化后的 `skill` 分支另起一套名条入口。若 PM 选择将两者合并，须在任务卡需求表显式扩大范围并把两套回归 DoD 一并列出。
