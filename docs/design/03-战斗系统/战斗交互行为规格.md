## 一、缺陷复盘（T15/T16 三轮移动语义失控 · 主架构视角验证与修正 PM 四层根因）

| PM 根因 | 验证/修正 |
|---|---|
| ① 方案层：契约 moveCells/attackCells 二分支表达不了移动型技能 | ✅ **成立且为主源头**（F1：轻功激活后 moveCells 置空、点格无响应）。已修：契约补 `moveKind: 'walk'\|'jump'` 与 `SnapshotActor.isJump` 真值 |
| ② 需求层：「规则→UI 交互」行为规格中间层不存在 | ✅ 成立，**修正一处**：backend 并非无依据地反推——它参照了**错误的原型**（旧 T06 battle-session，其时代 A3 跳跃规则尚未诞生）。三轮补丁是往过时原型语义上叠加，而非从 A3 独立推导 |
| ③ 测试层：用例自反推自写，无独立真源 | ✅ 成立，**补充一条更深的**：不仅缺真源，**既有用例还被实现反向污染**——错误实现落地后，用例被改写去匹配（如 jumpMinCells=1.5 启发式断言把"猜"固化成"真值"）。规格→用例的推导方向必须单向：规格改，用例跟着改；实现错，用例不动 |
| ④ 修复层：三轮补丁互相破坏 | ✅ 成立；**机理补充**：无规格时修复是「症状级局部补丁」（jumpOnly 分支），补丁间共享的隐含前提（moveCells 语义/isJump 来源）无人看守，破坏必然跨补丁发生 |
| **⑤（主架构补充）架构层：快照契约表达力不足** | moveCells/attackCells 二元结构 + isJump 缺失 + moveKind 缺失——即使行为写对，契约也承载不了「移动型技能」「跳跃表现」「金绿互斥」的语义。F1 修复已补 moveKind/isJump，本规格将其与其他交互语义正式定版 |

**结论**：五层（方案/需求/测试/修复/架构）合力造成失控；本档堵 ②（行为规格真源）与 ⑤（契约表达力），③由 §五测试矩阵堵，①④由 backend 重构按本档执行堵。

## 三、移动可达语义规格表（定版三态 · 精化）

> 三态互斥，同一时刻快照只呈现其中一种 moveCells（contract: `moveKind`）。

### MV-0 地图与格基准

- 存储 offset odd-r（16×16）；可动区 = offset 列/行 ∈ [2,13]；一切移动/落点/射程格不得出可动区。

### MV-1 普通移动态（未激活技能）

- **进入条件**：我方行动条满进入输入态，且无选中技能。
- **格集合**：从当前格 BFS，步数 ≤ F-06 移动力（基础 2 + 装配轻功加成 + ⌊最高轻功等级/5⌋）；**不可进入、不可借道**任何单位格（友/敌同判）；限可动区。
- **表现**：绿色高亮（`moveKind='walk'`）。
- **提交**：点集合内格 → 位移（贴地 lerp，`isJump=false`）→ 触发 ATK-3 自动普攻特例 → 行动结算（BAR-3/SEL-3/CD-1）。
- **拒绝**：点集合外格 → `rejected(reason='invalid')`，无位移。

### MV-2 轻功跳跃态（轻功激活）

- **进入条件**：输入态下点 [轻] 钮（toggle 激活，SEL-2）；仅二阶及以上轻功可用（⌊F-06/2⌋ ≥ 1，一阶点钮置灰）。
- **格集合**：以当前格为圆心，**cube 距离 ≤ ⌊F-06 移动力/2⌋** 的全部可动区**空格**（**可穿越**任何单位——无需连通路径；落点不可为单位格、不含自身格）。
- **表现**：金色高亮（`moveKind='jump'`）；攻击范围高亮（attackCells）**必须为空**。
- **提交**：点金格 → 位移（**抛物线 hop**，`isJump=true`）→ ATK-3 特例 → 行动结算。
- **拒绝**：点金格集合外任何格（含敌格、非金空格）→ `rejected(reason='invalid')`，**且不取消轻功激活**（仍停留金格态）。

### MV-3 无跳跃基线（兜底语义）

- 一阶轻功（⌊power/2⌋=0）或未激活状态：跳跃格集合恒为空；[轻] 钮置灰或激活后零金格。
- **规格锚**：任何「轻功跳不了/跳太远」的缺陷，先对照本条与 MV-2 的集合算法，再查实现。

## 四、技能交互状态机（特/绝/轻/毒 + 普攻）

### 4.1 状态定义（玩家输入态子机）

```
[无选中] ──点特/绝钮──▶ [攻击技选中: te|jue]      （红色射程高亮）
[无选中] ──点轻钮────▶ [轻功选中: qing]           （金色跳跃格高亮）
[无选中] ──点毒钮─────▶ （预留：MVP 置灰不可激活）
[攻击技选中] ──点射程内敌──▶ 施放并结算 → 回[无选中]（行动消耗）
[攻击技选中] ──再点同钮/点无效格──▶ 取消回[无选中]
[轻功选中] ──点金格──▶ 跳跃位移并结算 → 回[无选中]（行动消耗）
[轻功选中] ──点敌/点非金格──▶ 无操作（不取消、不攻击，Q4）
[任意选中] ──再点其他技能钮──▶ 切换选中（互斥，BASE-5）
[任意选中] ──行动提交/条<100/逃跑/终局──▶ 清除选中（SEL-3/4）
```

### 4.2 状态机规格条目

| 编号 | 规格 |
|---|---|
| SEL-1 | **进入输入态**：我方行动条 ≥100 且手动模式且我方存活 → 头顶弧形弹出 特/绝/轻/毒 四钮（一次性 `bar-max` 事件；等待期不重复发）；自动/托管模式**无输入态、无弹出钮** |
| SEL-2 | **激活与互斥**：点钮激活（toggle：再点同钮=取消）；激活新钮自动取消旧选中（BASE-5）。激活不消耗行动预算 |
| SEL-3 | **消耗时机**：提交行动（移动或出招）瞬间 → 行动条**清零**（BAR-3）+ 选中清除 + 本技能进入 R-08 冷却（若技能有冷却）+ 冷却整体递减 1（CD-1，读后递减镜像 core） |
| SEL-4 | **自动清除**：条 <100（提交后必然、或任何原因回落）→ 输入态退出、四钮收回、高亮全清；重新涨满重新弹出（重新走 SEL-1） |
| SEL-5 | **取消路径**：①再点同钮 ②攻击技激活后点无效格/棋盘外 ③（轻功态无此路径——点非金格=无操作，见 ATK-4） |
| SEL-6 | **置灰**：特/绝 = 内力不足或冷却中置灰（点=blocked 反馈无消耗）；轻 = ⌊power/2⌋=0 或内力 <10 置灰；毒 = MVP 恒置灰（BASE-9） |
| SEL-7 | **模式切换/逃跑/终局**：切自动（选中清除并由 AI 代行当前回合）、逃跑、胜负 → 输入态立即退出、选中清除 |

### 4.3 攻击行为规格条目

| 编号 | 规格 |
|---|---|
| ATK-1 | **普攻（无选中）**：点敌棋子 = 普攻。合法性：cube 距离 ≤ basicRange 且（锥形武器时）目标在 facing 扇区。合法 → 结算提交；非法 → `rejected(reason='invalid')` |
| ATK-2 | **技能施放（特/绝选中）**：点射程格上的敌棋子 = 施放选中技能。合法性：R-05 武器匹配 + 冷却 0 + 内力足 + 目标格 ∈ 射程形态格。合法 → 结算提交（含 R-09 扣内力、R-08 写冷却） |
| ATK-3 | **移动附带普攻特例**：移动提交后，最近敌 ∈ 普攻射程 → 自动普攻一次（不另耗行动、不回退移动）；射程外静默无操作。**本特例是移动行动的附带结算，移动行动本身已消耗回合（BASE-2 不冲突）** |
| ATK-4 | **轻功态点敌 = 无操作**（Q4）：不普攻、不施放、不取消轻功；轻功只能以「点金格跳跃」终结，或按 SEL-5 取消 |
| ATK-5 | **点空格（无选中/攻击技选中且不在射程格）**：无操作（不移动不取消——移动必须点绿格；取消见 SEL-5②） |

### 4.4 行动条与回合规格条目

| 编号 | 规格 |
|---|---|
| BAR-1 | 行动条 clamp 100 封顶（tick 溢出丢弃，不累计） |
| BAR-2 | bar ≥100 → 进入该单位行动回合（发 `bar-max` 一次）；轮转排序 = bar 高 → fillRate 快 → 玩家先 |
| BAR-3 | 行动提交 → **bar = 0 清零重置**（BASE-6；速度优势 = 重新积满更快） |
| BAR-4 | 手动等待玩家输入期间：90s 总时钟冻结（防死循环不烧思考时间）；托管 idleSec 独立累计（90s→AI 代行发 `trust`，再 90s→切自动发 `switch-auto`） |
| BAR-5 | 90s 总时长未分胜负 → 存活 hp 总量高者胜，同量判玩家负（`timeout-hp`） |

### 4.5 出生与确定性规格条目

| 编号 | 规格 |
|---|---|
| SP-1 | 出生锚：我方 = 可动区左下极格 offset(2,13)，敌方 = 右上极格 offset(13,2)；出生格 = 各锚 **hex 距离 ≤3** 的可动区格内 rng 随机（Q1）；双方半径区天然不相交（锚距 >6） |
| SP-2 | 确定性：单 rng 流由 seed 派生、消费顺序固定（我方出生 → 敌方出生 → 战斗掷骰）；同 seed + 同操作序列 → 布局与事件流全等 |
| SP-3 | 非法输入发 `rejected` 事件（reason ∈ bar/invalid/…），**拒绝序列纳入确定性范围** |

## 五、规格条目 → 测试推导矩阵（backend 重构验收矩阵）

| BAR-2 | `轮转排序` | 同帧多单位满条：bar 高→fillRate 快→玩家先 |

| SP-2 | `同 seed 全等` | 自动/手动双场事件流 JSON 全等；异 seed 不同 |
| SP-3 | `rejected 确定性` | 同操作序列含非法输入 → 拒绝序列全等 |
