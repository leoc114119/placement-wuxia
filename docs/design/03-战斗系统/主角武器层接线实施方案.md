## 1. 定版结论与边界

**建议定版：运行时取独立剑模型，按每行标定数据绕模型握点旋转，再把握点对齐身体拳心；剑层允许越出身体 240×320 矩形，不做身体矩形 clip。**

有效素材只有：

    hero_sword_model_right.png
    hero_sword_model_left.png
    48 行 frame calibration
    对应 body-space occlusion masks

逐帧差异只有身体帧、握点/拳心、角度、层序和遮罩；剑的几何本体使用两个全局模型：

    right / rightup / rightdown → hero_sword_model_right.png
    left / leftup / leftdown    → hero_sword_model_left.png

运行时禁止镜像；左右模型分别加载、分别校验、分别绘制。当前卡只服务 hero，NPC/敌人不建立独立武器 overlay。

剑模已完成 Leo 选型与 PM 机械门检，specGate 可按本次扫描结果记为 PASS；runtimeRelease 仍须由研发卡导入正式路径后单独判定。第二批 manifest 的模板整合、frame15 补标和对照归档只影响来源证据，不改变本卡接口；研发卡以统一 48 行 runtime projection 为唯一输入。

## 2. 三件套落库与契约

### 2.1 正式 runtime 路径

候选 _trial/ 只用于导入和审计，production loader 不得引用。施工卡必须把真实产物复制到正式路径并同提交包含索引与 SHA：

    assets/characters/hero/weapon45/
      models/hero_sword_model_right.png   # 88×80 RGBA
      models/hero_sword_model_left.png    # 88×80 RGBA
      masks/<frameId>.png                 # T28 转换产物或第二批 mask
      manifest.runtime.v2.json            # 48 行 runtime 投影
      SHA256SUMS

T28 已并 main 的 26 张预摆剑层不作为新渲染输入，不进入 production index、loader、默认预检集合或 bundle；历史文件只作审计/归档引用，不能被新卡重新接线。

### 2.2 Manifest 关联裁决

PM 锁定的第一批 14 字段和第二批锁定模板分别作为来源证据；施工卡生成一个统一的 48 行 runtime projection，不把独立模型路径复制 48 次：

    interface HeroWeaponRuntimeRow {
      frameId: string;
      bodyFrame: string;
      weaponModelKey: 'hero-sword-right' | 'hero-sword-left';
      modelSha256: string;
      gripPointPx: readonly [number, number];
      fistCenterPx: readonly [number, number];
      angleDeg: number; // screen angle: 0=right, +Y down, clockwise-positive
      layerOrder: 'weapon_front' | 'body_front';
      maskPath?: string;
      maskSha256?: string;
      status: 'runtime-release';
    }

模型握点放在 models/manifest.json，作为全局模型元数据：

    interface WeaponModelMeta {
      src: string;
      sha256: string;
      canvasPx: readonly [88, 80];
      gripPointModelPx: readonly [23, 57];
      angleDefinition: 'screen-clockwise-positive-y-down';
    }

seq=252 已给出模型握点 [23,57]；旋转中心固定为模型握点，不是 bbox 中心。gripPointPx 是身体源 240×320 坐标，不能与模型握点混用。frame15 gripPoint 补标到达后只更新对应 runtime row，不改接口。

## 3. 导入期校验与失败策略

新增 tools/preflight_hero_weapon_model.mjs，默认只检查两张 model、48 行 runtime projection 和正式路径：

1. 48 行 frameId/bodyFrame 唯一，第一批与第二批来源 SHA 可追溯；左右方向只能关联对应模型。
2. 两个 model 均为 88×80 RGBA，模型 SHA 与 models/manifest.json 一致，alpha 不为空，模型握点在画布内。
3. 每行 gripPointPx、fistCenterPx、angleDeg、layerOrder、mask 路径/SHA 合法；angleDefinition 必须统一为 screen 坐标（0°向右、+Y 向下、顺时针为正）。
4. mask 存在时校验转换后的 RGBA/alpha、SHA 和对应 bodyFrame；没有 mask 的 body_front 行不得借邻帧 mask。
5. 按该行角度、握点、模型外接框计算旋转后 bounds，断言可越出身体矩形但不得越出 preview 主画布；负例必须对错模型、错 SHA、角色矩形 clip 非零退出。

预览/真机运行时不做 getImageData 或逐像素 SHA；图片加载失败只降级为空手并写 hero-weapon-missing:<frameId>，但预检失败不能判绿。运行时不依赖任何逐帧预摆剑层文件；缺失诊断只针对 model、mask 或标定行。

## 4. 运行时合成管线

### 4.1 坐标与旋转

身体按既有 drawPieces 计算 left/top/w/h，身体源为 240×320，比例 s = h / 320：

    fistX = left + fistCenterPx.x * s
    fistY = top  + fistCenterPx.y * s

模型层绘制使用同一 scale：

    save()
    translate(fistX, fistY)
    rotate(angleDeg * Math.PI / 180)
    drawImage(model, -modelGrip.x * s, -modelGrip.y * s, 88 * s, 80 * s)
    restore()

Canvas 角度必须锁死为：屏幕 0° 向右、-40° 右上、+Y 向下；不得用数学坐标的 atan2 口径替换。左右模型不再做运行时 mirror/scale(-1,1)。

### 4.2 越界绘制保障

不能把剑画在身体 240×320 临时画布后再贴回。每个角色创建/复用按旋转后 bounds 动态扩展的离屏 layer：

    body rect + rotated sword bounds + 2px safety margin

离屏原点由 bounds 左上角决定，身体与 mask 在该 layer 中按相同 source scale 偏移；剑自然越出身体矩形。最终以 (layerLeft, layerTop) source-over 到主 canvas。主场景只保留屏幕边界 clip，不添加角色矩形 clip。

### 4.3 层序与遮罩

    body_front:  weapon layer → body → HUD/FX
    weapon_front: body → weapon layer（mask 挖拳）→ HUD/FX

weapon_front 的 mask 只在离屏 layer 上执行：先 source-over 绘制旋转后 sword，再以 globalCompositeOperation='destination-out' 绘制 body-space mask，最后贴到主 canvas。这样拳部洞口露出已画好的身体；destination-in 禁用。

body_front 先画 sword、再画完整 body；层序由 manifest 细粒度决定，不能强锁为单一 weapon_front。全局顺序保持：棋盘/环境 → 按 y 排序 actor 内部 body+weapon → piece HUD → T25 world FX → UI 组件。weapon layer 不改 T27 directional 选帧、移动插值、dead/jump 语义或 FX 时序。

## 5. 48 行状态覆盖

| 状态 | 覆盖 | 规则 |
|---|---:|---|
| idle | 6 向 | 第一批 6 行右系+左系 |
| walk | 12 向帧 | 第一批 10 行 + 第二批补 walk_rightdown_2± |
| atk | 12 向帧 | 第一批 10 行 + 第二批补 atk_right_1± |
| cast | 18 帧 | 第二批 cast_right/rightup/rightdown × 3 及左右系 |
| jump | 0 | 显式无武器，保持身体 jump |
| die | 0 | 显式无武器，保持 die_common |

48 行整合完成后，idle/walk/atk/cast 消费帧均不得无剑；jump/die 不查询 overlay。任何逐帧预摆剑层都不出现在状态映射。

## 6. T28 旧路线退役

保留既有预摆剑层、旧 manifest 和 QA 作为审计材料，但不删除、不重新导入、不进入新 bundle。旧 HERO_WEAPON_FRAMES 及“同矩形绘制/不旋转”入口从 production config 移除；历史预检移入 archive，仅供溯源。

新 loader 只允许 weaponModelKey + calibration row；单测扫描 production source，确保无 _trial/、旧预摆 png、旧 map 和非授权第二入口。对照功能只消费运行时合成截图。

## 8. DoD 与 Leo 验收

1. 两张 model、mask、runtime manifest 三套 SHA 与路径全通过；48/48 行可加载，左右模型零运行时镜像。
2. 单测锁定：modelGripPoint 绕点旋转、screen angle、fist 对齐、bounds 扩展、weapon_front/body_front、destination-out 仅在离屏层、无角色矩形 clip、jump/die 无武器、旧 26 路线无 production 引用。
3. 负例：模型错配、mask 错配、SHA 错、旋转后 bounds 被 body clip、旧预摆路径引用均非零退出。
4. 三档预览 375×667、560×700、900×560：idle、walk、atk、cast 各至少一张；atk 长剑完整显示，不在身体 240×320 边缘平切；body_front 帧可验证剑在身体后。对照截图由合成图生成。
5. 真机 Leo 重点看：出招长剑完整长度、握点不漂、右/左六向方向正确、拳部遮挡自然、HUD/FX/脚底不回归。
6. typecheck/lint/build、battle 全量、behavior 全绿；battle-core.ts diff=0；提交必须含真实 runtime 产物和实测证据，不得回执式提交。

## 9. 风险时间轴

当前最先爆的是“模型/标定/遮罩不同步”与越界绘制被新 clip 截回去；bounds、model SHA 和负例门必须同卡锁住。接下来一个月的债是 cast/atk 资产扩展导致 runtime index 漂移；保持全局模型 + 逐帧标定单一关联。两到三个月后的债才是模型预加载、分包与 LRU；本卡只实现按场景预载，不扩大通用资源系统。
