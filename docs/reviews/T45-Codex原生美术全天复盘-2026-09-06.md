## 2. 工作过程与关键转折

### 2.1 主角右上：小批动作闭环证明有效

右上按行走双帧、跳跃双帧、施法三帧逐动作推进。每个动作都先生成候选和 contact，Leo 目验后才进入正式路径并交研发线规格门。施法第二帧首次出现手位错误，第二次只修“角色自身方向向左下甩”这一项；第一、三帧的头发、肩部和拳头边缘残留随后用确定性清理解决。

这一段验证了“小批生成 → 单动作目验 → 文件固化 → PM 门检 → 下一动作”的节奏。相比一次铺满整方向，它让动作错误在 2～3 帧内暴露，返工没有扩散到其他动作。

### 2.2 主角右下：文字左右失效，改用角色解剖语义和实际候选

右下普攻第二帧连续出现出手臂错误。最初以“画面左/右”描述角色自身右手，三分之四视角下产生冲突；即使追加“交换当前出拳手”，模型仍重复错误。流程在第 5 次后停止，登记 Q1/A1；Leo 随后把验收口径修订为“角色自身右手出拳”，不再用画面左右作最终语义。Leo 提供的候选经过归一和规格确认后成为正式第二帧。

右下施法又暴露了相邻帧动作趋同的问题。Leo 提供新第二帧，只替换中间格做 1→2→3 连贯预览；视觉确认后才固化。第 2 帧发尾的白边限定在 ROI 内做两遍确定性清理，共移除 93 个白/灰边缘像素，没有重绘人物。

这段说明，涉及左右手和三分之四转面时，文字方位不是可靠真源。后续应优先使用角色解剖语义、姿势图或真实目标帧，并把用户替换图仍按候选走完文件门。

### 2.3 主角正式目录卫生与左系镜像

右下普攻门检后，按明确授权清理旧 `atk_rightdown_3.png`、旧左向镜像、`atk_right_3.png`、`atk_rightup_3.png` 和重复的 `die_down.png`；12 张 down 向旧素材移入 backup。清理与正式替换分开记录，避免把历史残留误当现行帧集。

左系 30 张只由已验收的右系 30 张水平镜像派生，`die_common` 不重复。机械门逐张验证 `ImageOps.mirror(source)==output`、240×320 RGBA、alpha bbox 对称和命名。这里采用确定性变换，消除了重新生成带来的身份、动作和比例漂移。

### 2.4 山贼锚第一阶段：批量复用导致比例、风格和手形漂移

山贼甲乙六张最初按批量方式生产，经历以下连续问题：

1. 首次请求遇 ImageGen 额度限制，已生成的甲右又因棋盘背景和方向错误被拒，形成可恢复停点；
2. 六张空手锚的开放手形不利于独立武器层挂接，统一改成空手闭合握拳；
3. 首列两张体宽修正过头，机械比例降到 0.367/0.371，说明数值变窄不等于视觉比例正确；
4. 甲乙多张头身比修正视觉变化不足，随后乙系又出现头部大小在三向间漂移；
5. 乙右虽然风格正确，但相对主角明显过矮，单角色内部对照无法发现跨角色总体量级问题。

有效突破来自职责分离的双参考：乙右高分辨率图只锁身份、脸、红巾、棕衣、握拳和画风，主角右向待机图只锁总高与比例量级。生成结果再按同脚底基线对照，乙右由此得到 Leo 确认。

### 2.5 山贼锚第二阶段：由六张批改切换为逐张闭环

总览复看仍发现甲右/右上白边、乙右上/右下头部偏小。批量修正继续传播漂移，因此流程改为单帧串行：

1. 先选定某 NPC 的 `right` 主锚，冻结身份、色板、线条、服装与比例；
2. 只生成 `rightup`，归一、文件检查、与主锚对照、Leo 目验；
3. 前一帧选定后才启动 `rightdown`；
4. 三帧均选定后才聚合六张总览和统一 manifest。

山贼甲右下首稿仍被读成纯右向。第二次没有继续堆文字，而是新增旧甲右下成帧，只授权它负责前向三分之四姿势与前后层次；新甲右继续作为身份、比例和画风唯一真源。第二次方向清晰，证明“身份锚 + 真实目标姿势参考”的职责拆分优于反复改方位词。

山贼乙右下两次输出曾因粗黑线、头巾/头/拳头过大和肌肉化被执行侧判为身份门失败并停止。Leo 复看后明确选用第二次输出，说明执行侧可以严格筛选，但审美定稿仍由 Leo 决定；被拒原稿不得自行删除或擅自晋级。

### 2.6 六张聚合、复核与正式门禁

最终六张候选集中到 `t45_batch2a_anchor_selection_v2_singleframe`。本地统一复核检查了 240×320、RGBA、真实 alpha、四边透明、单主体连通、视觉高、脚底、中心和 manifest SHA，当时报 6/6 PASS。

研发线 PM 随后用全分辨率逐像素 `alpha > 32` 口径复扫，判定 5/6 PASS；报告中的 bbox left=59、质心 x=105.8 与旧批次 `t45_batch2a_codex_native/normalized/shanzei_a_right.png` 精确相符。该 job 的 `job.json` 已写明被后续握拳/逐张候选 supersede，因此 seq=72 实际扫到的不是统一 manifest 当前入口。旧文件已按整改单右移 14 px，复测为 bbox left=73、质心 x=119.8211、脚底 y=300、alpha 极值 0/255；没有改动最终选定的逐张候选。

Leo 的“可入阵”确认完成了视觉门；PM 的 5/6 结果暴露出交接入口与实际扫描路径不一致。当前隔离分支为 `codex/t45-shanzei-idle-anchor-candidates`，初次 delivery `seq=65`，门检答复为 `seq=72`。旧批次修正证据在 `assets/_trial_20260906/t45_batch2a_codex_native/qa/recenter_seq72_qa.json`；最终仍须按统一 manifest 对六张逐张候选复扫，在 6/6 PM PASS 前不写 `assets/characters/enemy/*/battle45/`。

## 4. 下次执行的标准流程

### 4.1 生图前

1. 写清单帧目标、不可变化项、两次尝试上限和停止条件。
2. 逐张打开参考图，在 `refs.json` 写实际路径、内容核验、允许职责、禁止职责和冲突优先级。
3. NPC 先确定 `right` 身份主锚；目标方向使用真实同向姿势图，白模只作粗方向提示。
4. 跨角色比例有要求时，增加主角同基线对照，但禁止主角图接管 NPC 身份或画风。

### 4.2 每张候选

```text
raw 原生输出
→ 读取模式/alpha/四角/可见框
→ 允许范围内的确定性扣图与等比归一
→ 复核 RGBA、alpha 0/255、四边透明、单主体连通、尺寸/脚底
→ 全分辨率逐像素 alpha>32 计算前景质心并与门槛比较
→ 单帧与身份主锚/目标姿势并排
→ Leo 目验
→ selected 后才启动依赖它的下一帧
```

第 2 次只修一个已观察缺陷。方向失败时更换或补充真实姿势参照；身份失败时回到身份锚；文件失败时只做确定性处理。两次仍失败就停该帧，保留原稿和 QA，等待 Leo 决定。

### 4.3 聚合与交接

1. 单帧全部选定后才生成 contact sheet；contact 不作为后续 ImageGen 输入。
2. manifest 记录来源、处理、SHA-256、视觉状态和规格状态。
3. Leo 目验只更新 `visualReview=selected`；PM PASS 才更新 `specGate=pass` 和 `artifactStage=release`。
4. 提交前检查共享工作区，只提交本任务显式路径；delivery 带 commit、artifact paths、manifest 版本和当前停点。
5. 等待 ACK 时允许完成复盘、技能更新和只读核验，不提前接入运行时。

## 7. 2026-09-07 条件性动作帧回退增补

Leo 针对手部、脚部和动作异常明确授权了一个窄范围回退：同一单帧的同一异常连续三次由 Codex 原生处理仍失败时，允许用 mxai API 的精确模型 slug `seedream-5.0-pro`（Seedream 5 Pro）做一次单图修正，固定 6 积分。其他 Seedream 变体或厂商模型均禁用；该授权不改变默认的 Codex 原生路线，也不把失败帧扩成批量换源。

执行时保留三次原生 raw、prompt 和 QA，在 `credits.json` 记录 provider、model、cost、触发帧、失败次数、异常说明和输入输出 SHA；回退图重新走透明、尺寸、主体连通、脚底、质心和命名门。回退只处理已登记的手/脚/动作问题，不改身份、服装、比例或方向；失败或 API 不可用即停。Leo 目验和 PM 规格门仍是独立状态，未双门通过前不写 runtime。
