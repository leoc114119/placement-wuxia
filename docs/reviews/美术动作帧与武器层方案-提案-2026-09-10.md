# 美术：动作帧与武器层方案提案（2026-09-10）· PM2 起草

**问题**（Leo 提出）：美术管线里最麻烦的两块＝①人物的动作帧 ②合并武器的位置与遮罩。

**本文档回答"有没有更好的方案"。**

---

## 一、根因：两个麻烦是同一个病

| | 现在的做法 | 后果 |
|---|---|---|
| 动作帧 | **每一帧都是一张独立生成的整图**（img2img + 锚） | 一致性只能**事后测量再纠**——三锁就是缓解措施。测量贵、且会静默失败（实测 7+ 种测法全未通过自验证） |
| 武器层 | **把武器当成"每帧一张美术件"来做** | 逐帧标定锚点（48 行 manifest）、逐帧做遮罩、逐向定 layerOrder → 工作量与帧数线性挂钩，且每加一批就重来 |

一句话：**一致性今天靠"测量"，而测量既贵又不可靠；应该让一致性"结构性成立"。**

下面两条分别给"结构性成立"的具体做法。

---

## 二、武器层：这条立刻可做，且你们已经证明过路线

**现状成本**：48 行锚点表 + 逐帧遮罩资产 + 逐向 layerOrder。

**提议三步拆解**：

### ① 锚点：派生，不标定
- 锚点 = **拳心**（T29 已在用"握点旋转 + 拳心对齐"）。
- 拳在"握持友好拳型"约定下是**干净的肤色圆块**（规范 v1.7 已把该拳型定为动作帧 SOP）→ **可自动检测**：肤色掩码 → 连通域 → 取"近圆、尺寸在预期带内、距脸部足够远"的那个。
- **作者工作量：48 行 → 0 行**；人工只核检测失败的例外帧。

### ② 遮罩：D 方案下**这类资产可以直接取消**
- 09-10 已定 D ＝ **裸刀 + 原拳遮挡**。既然拳头本身（属于身体帧）就该挡住刀柄，那么"遮住剑柄"根本不需要一张额外的遮罩图——**把剑层画在身体层之下，重叠部分自然被身体像素挡住**。
- 真正需要"遮挡资产"的只有一种情况：剑被身体挡住的部分**不是**由拳头完成的（如刀身横过躯干）。此时用身体帧自身的 alpha 即可，也不需要新资产。
- **结论：遮罩资产类从管线里消失**，只留"图层序"一个概念。

### ③ 层序：按"向"定，不按帧定
- 层序的真实语义 = **该帧持械手是近侧手还是远侧手**。同一朝向、同一持械手，这个关系是固定的 → **6 个方向的 6 个决定**，而不是 48 行逐帧数据。
- 可进一步由朝向 + 持械手推导（右手持械 + 右向 ≈ 近侧）；推导不成立时回落为"每向一个常量"。
- **跨向、跨动作、跨换装全部复用**。

**收益**：武器层从「每帧一张美术件 + 48 行数据 + 遮罩资产」变成「**1 个剑模 + 1 条锚点检测规则 + 6 个层序决定**」，**成本与帧数解耦**。换装（换武器）自动继承这条链。

**风险**：拳心自动检测在少数帧（手被身体挡住/被刀柄姿态遮挡）会失败 → 设"检测不确定即人工核"的例外通道，而不是退回全人工。

---

## 三、动作帧：四条路，按"是否改渲染架构"排序

### 路 A — 减少独立帧数（不改渲染，立刻减痛）
- 你们已经在普攻上收敛成 **2 帧 + 代码动效**（帧账目 v1.3）。把它**推广到所有动作**：每个动作只保留 **2 个关键姿势**，运动感交给 runtime（位移/旋转/挤压/特效）。
- 逻辑：独立决策数从 10 降到 2 → 一致性失败面缩小 5 倍，返工成本同比例下降。
- 代价：动作的"过程细节"变少，靠 runtime 补。对 240×320 的战斗小人是可接受的（普攻已证明）。

### 路 B — 视频/序列生成替代逐帧独立生成（算力换一致性，**最值得先试**）
- **时间一致性正是视频模型的强项**：用现有锚帧做首帧图生视频 → 生成 2~3 秒动作片段 → 抽帧。
- **同一被跟踪主体 → 头身比、服饰、身份按构造一致，不靠测量**。这一条正好打掉三锁要解决的问题本身。
- 抽帧后下采样到 240×320（**下采样还提升质量**），逐帧隔离抠底（纯程序，已有）。
- **未验证**，需一次便宜试点确认三件事：①对"国风像素/水墨"画风的保持 ②姿势可控度（能否按要求出招） ③纯色底隔离是否可用。
- 成本：视频模型多为单独计费，单位成本需实测（你们现有 mxai/gpt-image-2 计费不覆盖）。

### 路 C — 2D 切件骨骼装配（结构性根治，改架构）
- 一个方向生成**一张基图** → 切成头/躯干/上下臂/手/腿/尾 → **摆骨骼出姿势**。
- **一致性结构成立**（同一套件），武器挂手骨（锚点问题消失），遮挡=图层序（遮罩问题消失），**第二节三项全部自动成立**。
- **代价：战斗渲染层要从"画 PNG 帧"改成"播放骨骼"**——架构变更，且现有帧资产要重做。这是要不要投的问题，不是能不能做的问题。
- 风险：手绘风切件动画容易出"纸片人感"，需要试点目验。

### 路 D — 3D 模型 + 卡通渲染（战略级，一次全解）
- 六向、全部动作、武器挂点、遮挡（**深度缓冲，根本不需要遮罩**）**一次全解**。
- 风险：①画风匹配（你们是手绘 2D，3D 渲成国风像素的观感是最大未知）②美术管线整体替换 ③成本最高。
- 仅作战略选项列出，不建议短期启动。

## 四、建议

**并行做两件去风险的小事，都不需要改渲染**：

1. **武器层拆解（第二节）**：收益确定、与现有 T29 运行时合成链直接衔接、不用碰渲染架构。建议**立刻做**。
2. **动作帧路 B 试点**：**1 个动作、1 段视频、抽样对比**。成了就把动作帧主力移到视频（顺带解决跨帧一致性）；不成就走路 A。

**中期**：路 C（骨骼）要不要上，是"改不改渲染架构"的决定 → 属架构决策，应经主架构线评估，PM2 不出架构结论。

**同时成立的边界**：
- 路 B/C/D 都不解决**审美**——好不好看仍是 Leo 判定；
- 都要求先有**唯一身份/比例锚帧**（这一步已经在做，不动）；
- 现有 v2 三锁在路 A 下继续有效，在路 B/C 成功后大部分成为冗余（一致性已结构成立）。

# 附录：用 T28 的 26 行人工标定做的实证（2026-09-10 实测，含对本文档第②③点的修正）

**数据源**：`git show c16ba433:config/hero-weapon-layer.ts`（T28 武器层 26 行，人工标定的 `fistCenterPx/gripPointPx/angleDeg/layerOrder/occlusion`）。

## 发现 1：layerOrder 与遮罩是「向」的纯函数（**本文档第③点被证实，且更强**）

26 行实测分布，**零反例**：

| 向 | layerOrder | 遮罩 |
|---|---|---|
| rightup / leftup（5+5 行） | `body_front`（剑在身体之下） | **无** |
| right / left / rightdown / leftdown（16 行） | `weapon_front`（剑在身体之上） | 有（拳区挖孔） |

→ **26 行逐帧数据可压缩为 6 个方向值**。这不是推测，是 26/26 一致。

## 发现 2：左系 = 右系精确镜像（复核确认）

13 组镜像对的 `fistCenterPx` 满足 `x_left = 240 − x_right ±1`（如 idle 右 102 ↔ 左 137；walk_1 右 84 ↔ 左 155），且自动检测的误差在左右两侧**逐帧完全相同**。

## 发现 3：grip 在部分族里可由 fist 派生

侧视族（right/left）实测 `grip − fist` 长度恒为 **~14.5px**、方向 ≈ `angleDeg`：
`walk_right_1` Δ(+14.49,−0.41) vs angle 0°；`walk_right_2` Δ角 −17.0° vs angle −15°；`atk_right_2` Δ角 −41.4° vs angle −40°。
→ **该族 grip 可由 fist + angle 推导，不必单独标定**。但 rightup/rightdown 族该关系不成立（长度 0.4~18 不等），**不能全族推广**。

## 发现 4 ⚠️ 对本文档第①点的**修正**：拳心自动检测"能做但不理想"

我用这 26 行人工值当标准答案，实测自动检测（肤色掩码 → 连通域 → 排脸 → 取紧凑块）：

| 指标 | 结果 |
|---|---|
| 规则命中（误差 ≤5px） | **18/26 = 69%** |
| 中位误差 | 2.25px |
| **理论天花板**（若挑对块） | **中位 1.72px、最大 8.10px** |
| 失败的 8 例 | 集中在 rightup / rightdown 两族（拳被身体或刀柄姿态遮挡 → 块被切碎/合并） |

**诚实结论（修正原提案）**：

1. **块测量本身极可靠**（挑对时 1~2px）——`fistCenterPx` 这个量是可测的；
2. **瓶颈是"哪个块是拳头"的判别**，不是测量——脸、耳、脚踝也是肤色，且脸常是最大块（首次天真实现中位误差 67px，就是取到了脸）；
3. **失败按方向系统性分布** → 每向单独调判别通道仍可提升，但**目前不足以全自动**；
4. **可用的形态是"半自动"**：工具自动标 + 置信度标记，**人工只核低置信帧**（≈8/26 待核），不是回到全人工。

## 发现 5：锚点与遮罩**是同一个原语**

- 锚点需要的是**拳的位置**；
- 遮罩需要的是**拳的轮廓**（用来在剑层之上把拳挖回来）；
- 两者都来自同一件事：**拳的像素块**。

→ **不必建两类资产、两套流程**，只建**一个"拳块检测器"**，同时产出位置（锚点）与轮廓（遮罩）。这是本文档第二节最实质的简化：**不是"取消遮罩"，而是"遮罩与锚点合并为一个原语"**。
