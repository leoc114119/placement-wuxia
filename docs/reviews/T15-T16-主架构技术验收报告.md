## 三、问题清单

### F1【阻塞 · 进 Leo 终验前必须修】轻功交互链在真 session 下断裂

**证据链**（battle-session.ts `snapshot()` L589-597 + battle-input.ts L139-149）：

1. `selectSkill` 激活轻功后，快照走 `if (selectedSkill)` 分支 → `attackCells = rangeCells(...轻功 SkillDef...)`、`moveCells = []`
2. 轻功 SkillDef 的 `weapon` 为 null → `rangeShapeOf(player.weapon)`（**武器**射程形态）+ `skillRange(轻功)`（fist 档数字）——输出的红圈既不是轻功跳跃范围，语义也是「攻击范围」
3. 输入侧：`skill === 'qing' && inMove` 中 `inMove` 读 `moveCells`（**空**）→ 恒 false → **点格无反应，轻功跳跃位移不可达**
4. 108 用例未覆盖此路径（selectSkill 用例只测了攻击型技能的 attackCells）

**为什么是我方案的锅**：§3.2 快照设计的 `moveCells/attackCells` 二选一分支没考虑「移动型技能」——轻功既是技能（走 selectSkill 激活）又是移动（吃可达格），契约语义缺一角。

**修法建议**（session 侧 ~10 行 + 用例 1 条）：snapshot 分支加轻功判断——`selectedSkill` 为轻功（kind='qingGong'）时 `moveCells = jumpReachable(...)`（金色高亮可另加快照字段 `moveKind: 'walk'|'jump'` 供渲染换色）；input 侧现有 `qing && inMove` 路径即自然复活。顺带把 `isJump` 从「渲染猜」（jumpMinCells=1.5 启发式，普通移动 2 格会误触发抛物线）转为快照真值。

### F2【P1 · 契约债】heroSkills 不在冻结契约，靠 BattleSnapshotExt 过渡

弧形四钮置灰数据源（内力/冷却）是**会话真值**，长期由 mock/Ext 供给 = 渲染读假数据的结构债。T16 的过渡处理本身克制（可选消费、登记在案），**方向可接受**，但 M4 正式接入前必须补：session `snapshot()` 产出 `heroSkills`（SkillButtonInfo[]，~10 行），Ext 降级删除。建议随 F1 同一小工单。

### F3【P1 · 粒度】spriteKey 仅 'hero'|'mob' 两值，多敌型不可区分

快照丢失了敌型身份（旧 T06 有 configId）。MVP 敌方含山贼/野狼/狼王（T14 帧表按型），正式接入时 `spriteKey` 需 per-actor——修法：`HexBattleOptions.enemies` 的 CombatantInput 已有 `name`，建议快照 actor 增加 `configId`（或约定 spriteKey = configId），config 侧 BATTLE_HEX_RES.spriteKinds 对齐。随 F1/F2 同单修。

### F4【P2 · 观察】非阻塞项

- input.ts L99 `artH = 448` 硬编码像素高（ctrl 切图标系魔数）——应引用 config 常量
- mock_session 手抄了一份 reachable（「同式」注释）——对切后 mock 弃用，漂移窗口可控
- `statusIcons: []` / `isBoss: false` 占位——回执已声明归属后续卡，自洽
- 玩家等待期间 bar 溢出保留（consume 只减 100）——与 core 行为镜像一致，非问题，记录口径
