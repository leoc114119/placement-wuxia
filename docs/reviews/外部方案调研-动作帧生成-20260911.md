# 外部方案调研：AI 生成连续动作帧（2026-09-11）

**问题**：AI 生图每次只画"更靠观者的那只手出拳"，5 种方法全败（链式/示意图/绝对锚/双格同图/独立生成）。
**调研方向**：外部**专用工具/MCP/API** + **连续帧序列的关键词与技术**。

# 二、关键词/技术路线全景（回答"连续帧序列的关键词"）

## 2.1 按"控制强度"排序的技术路线

| 路线 | 关键词 | 能控制什么 | 适用性 |
|---|---|---|---|
| **1. 骨骼/关键点控制** | `ControlNet`, `OpenPose`, `DWPose`, `pose skeleton`, `keypoint conditioning` | **精确控制四肢位置**（含哪只手在前） | ⭐ 最对症，ComfyUI 可做 |
| **2. 动画专用模型** | `advanced animation`, `start-frame animation`, `sprite animation`, `frame interpolation` | 动作由模型生成（含时序理解） | ⭐ Retro Diffusion 可做 |
| **3. 视频模型抽帧** | `image-to-video`, `first-frame/last-frame`, `keyframe conditioning` | 运动连贯性最好 | ⭐ 我们平台有 19 个视频模型（含 4 个支持**首尾帧**：seedance-2.0/2.5/-fast/-mini） |
| **4. 局部重绘** | `inpainting`, `mask`, `region-locked edit`, `soft_inpaint` | **只改指定区域，其余锁定** | ⭐ 换手可"只重绘手臂" |
| **5. 角色一致性** | `reference_images`, `character reference`, `custom style training`, `up to 9 refs` | 锁定角色外观 | 辅助 |

## 2.2 我们已试过、且**确定无效**的（避免重复）

- ❌ 纯 prompt 描述（left/right hand、位置坐标）→ **5 次全败**
- ❌ 链式 edit（上一帧当输入）→ 不动 / 方向错 / 同图 / 同一只手
- ❌ 双格同图（同图内两种姿势）→ 不换手
- ❌ 独立生成 → 不换手
- ❌ 姿势示意图（火柴人）→ 无效

**失败共性**：这些都是"**让模型自己理解姿势**"。而有效路线 1/2/4 的共同点是"**把姿势作为显式输入/约束**"。

## 2.3 平台内已有但未用足的能力

**mxai 上 4 个视频模型支持"首尾帧图生视频"**（`supports_end_frame`）：`seedance-2.0` / `seedance-2.5` / `seedance-2.0-fast` / `seedance-2.0-mini`
→ **原理**：给"这只手出拳"的首帧 + "另一只手出拳"的尾帧，让视频模型生成**中间过渡帧**——**交替动作是视频模型的强项**（时序建模）。
→ **成本参考**：seedance-2.5 5秒约 **155 积分**（≈77 倍于单图 2 分），**贵**；但**视频模型天然理解"换手"**，是最可能一次成功的。

# 三、PM2 建议：分两步验证（成本极低）

## 第一步（本周内，成本 ≈ $0）——**验证 Retro Diffusion 画风能否用**

1. 注册 retrodiffusion.ai（**送免费 starter credits**）；
2. 拿**一张现有英雄帧**喂 `rd_advanced_animation__attack` 或 `__custom_action`；
3. **只验一件事**：**输出画风能不能用**（像素风 vs 我们的手绘水墨风）。
   - **能用** → 转正式试点（动作交替 + 一致性一起验）
   - **不能用** → 排除方案 1，走第二步

**判据**：画风可接受 → 通过。**用 1 次调用 + 免费报价即可判定，不烧钱。**

## 第二步（视第一步结果）——**二选一**

- **若要求"精确控制姿势"** → 走 **ComfyUI + 官方 Comfy MCP + ControlNet/OpenPose**（本地免费，但需搭建）；
- **若认为"视频模型生成过渡"更实用** → 走我们**平台内的首尾帧视频**（seedance-2.x，贵但最可能一次成功）。

## 不建议

- **Scenario**：未确认姿势控制，且需付费订阅——**排在后面**；
- **继续在现有生图接口上加 prompt**：**已 5 次证明无效**。

# 四、给"工程管理系统"的输入

**"姿势"应当是一等公民的资产输入**（不是 prompt 里的形容词）：
- 每个动作定义 = **姿势规格**（骨骼/关键点）+ **角色外观引用** + **输出规格**；
- 门检要能验证"**指定肢体是否到达指定区域**"（本轮已实现雏形：C1 前伸区判定）；
- 这一轮 5 次失败的根本教训：**把"姿势"交给自然语言描述，是把确定性的东西交给概率模型。**
