## 〇、三句话结论

1. **我们一期的整包硬顶是 20MB，不是 30MB** —— 30MB 只对「已开通虚拟支付」的小游戏开放（微信官方 2023-10-09 公告），而我们一期走 IAA 先行、版号未下，**拿不到那 10MB**。
2. **主包 4MB 是真瓶颈** —— 首屏之前必须下载完，超出即启动失败。引擎核心 + 首屏 UI + 主角帧表 + 主场景，全要塞进 4MB。
3. **两个隐形吞包大户：中文字体 与 音频** —— 二者加起来可以轻松吃掉 5-10MB，必须在设计阶段就定策略，否则后期返工代价极大。

## 一、平台硬约束（微信小游戏 · 一手来源）

| 项 | 限制 | 来源 |
|---|---|---|
| 主包 | **≤ 4MB** | 微信官方分包文档 |
| 整包（主包+所有分包） | **≤ 20MB**；**已开通虚拟支付 → ≤ 30MB** | 微信开放社区官方公告 2023-10-09 |
| 单个普通分包 | 不限制大小 | 同上 |
| 单个独立分包 | ≤ 4MB | 同上 |
| 开放数据域目录 | 不可设为分包 | 官方分包文档 |

**一手来源：**
- 分包加载（官方指南）：https://developers.weixin.qq.com/minigame/dev/guide/base-ability/subPackage/useSubPackage
- 代码包（英文版，含缓存与白名单后缀）：https://developers.weixin.qq.com/minigame/en/dev/guide/framework/code-package.html
- 包体限制调整公告（官方，2023-10-09）：https://developers.weixin.qq.com/community/develop/doc/00088e009103508f3270aaf9c61001

> 公告原文：「对已开通虚拟支付的小游戏，现将代码包大小限制进行调整：整包大小限制从 20M 提升至 30M。主包/单个独立分包限制仍保持 4M。存量游戏已生效，新开通虚拟支付的小游戏在开通后也将自动生效。」

**多端对照（未来抖音/淘宝迁移参考）：**

| 平台 | 整包 | 主包 | 单分包 |
|---|---|---|---|
| 微信 | 20MB（虚拟支付后 30MB） | 4MB | 普通不限 / 独立 4MB |
| 抖音 | 20MB（虚拟支付后 30MB） | 4MB | 20MB |
| 淘宝 | 20MB | 4MB | 5MB |

### 🔴 对本项目的直接后果

- **一期（IAA 先行，无版号）**：整包 **20MB**，主包 **4MB**
- **二期（版号下来开通虚拟支付后）**：整包自动升到 **30MB**，无需改代码
- → **排期含义**：一期所有美术/音频资源必须按 20MB 规划；30MB 当作「版号红利」而非设计基线

## 二、内容装不下的三层解法（技术侧通用答案）

| 层 | 容量 | 装什么 | 加载方式 | 备注 |
|---|---|---|---|---|
| **① 主包** | ≤4MB | 引擎核心、启动逻辑、首屏（Logo/加载条/登录）、主界面首屏必需素材 | 启动即下载，阻塞 | 唯一无法回避的体积 |
| **② 分包** | 与 ① 合计 ≤20MB | 按模块划分的玩法内容（战斗/剿匪地图/城镇/小游戏） | `wx.loadSubpackage()` 按需或预加载，可取下载进度 | **代码必须在包内**（微信不允许执行远程 JS） |
| **③ 远程 CDN** | 无硬上限 | 超出包体的大资源：BGM、场景大图、后续更新内容 | `wx.downloadFile` → 沙箱持久化目录 | 域名须配白名单；建议 MD5 增量校验；双层缓存（内存 Asset + 磁盘二进制） |

**关键红线：远程资源只能放图片/音频/配置等「数据」，不能放可执行 JS。** 换言之——**玩法逻辑占的体积省不掉，能外置的只有资产**。

## 二·补 重度 MMORPG 小游戏是怎么做的

> 📌 **完整案例与路线对比已独立成篇** → `research/02-竞品拆解/重度MMO的小游戏化路线.md`
> 本文只保留与**包体 / 加载**直接相关的技术要点。

**两条路线**：A 全量远程（天龙八部荣耀版 = 完整 MMO 上小游戏，内容全走 CDN）；B 玩法裁剪（剑侠情缘：重逢 = 三端互通，小游戏端只留轻度玩法）。案例细节见竞品拆解文件。

**与包体相关的技术要点（微信官方 Unity WebGL 转小游戏文档 + 工程实践）：**

1. 官方原话：启动仅能加载少量资源，**其余部分都必须放 CDN 进行延迟加载**
2. 🔴 **微信不支持加载本地 Bundle** —— 无论 AA / AB / Instant Game 哪种方案，最终都得上传 CDN、运行时异步下载
3. 重度游戏推荐 **AB（AssetBundle）而非 AA**（Addressable）：AA 在大项目生成的未压缩 catalog 偏大、加载效率低
4. 首包 = 引擎 runtime + 启动场景 ≤4MB；**微信环境不支持 LZMA，必须用 LZ4**；纹理用 ASTC/ETC2/PVRTC
5. **网络并发上限 10 个请求** —— 影响加载队列与分块粒度设计
6. Instant Game（Unity 官方自动懒加载）省改造人力，但**不支持自选 CDN**（须用腾讯云）

## 三、MVP 包体预算粗算（⚠ 低置信度估算，待实测）

> 口径：HD-2D 像素风、PNG-8 索引色 + 图集整合；竖屏 750×1334 逻辑分辨率；MVP = 三模块（基础界面美术 / 战斗手感 / 放置无限流）

| 类别 | 内容 | 估算体积 | 风险 |
|---|---|---|---|
| 代码 | TS 编译后 JS（自研 Canvas 2D，无第三方引擎） | 400KB – 1MB | 🟢 低（自研无引擎是巨大优势） |
| 配置 | 武学/门派/事件池/掉落表 JSON | 100 – 300KB | 🟢 低 |
| 主角帧表 | 1 角色 × 8-12 帧 sheet（210px 渲染高） | 150 – 400KB | 🟡 中 |
| NPC 帧表 | 3 角色 × 各 8 帧 | 300 – 750KB | 🟡 中（模板换皮可省，但多套皮肤仍占体积） |
| 场景背景 | 江湖 + 战斗 ×2（1280×720 PNG-8） | 300 – 700KB | 🟡 中（剿匪多地图会线性增长） |
| UI 组件 | 面板底/按钮三态/像素图标全套 | 200 – 400KB | 🟢 低 |
| 掉落图标 | 8-12 个 | 30 – 80KB | 🟢 低 |
| **中文字体** | **像素中文字库** | **1 – 8MB** | 🔴 **最高风险** |
| **音频** | **BGM + 音效** | **1 – 5MB** | 🔴 **高风险** |
| **合计（不含字体音频）** | | **约 1.5 – 3.5MB** | 主包 4MB **勉强够** |
| **合计（含字体音频）** | | **约 3.5 – 16MB** | 🔴 **可能直接爆主包** |

## 四、两个隐形炸弹（必须先决策）

### 🔴 炸弹一：中文字体

像素风游戏通常想要「像素中文字」，但中文字库无法像英文那样用几十个字符解决：

| 方案 | 体积 | 代价 |
|---|---|---|
| A. 用系统字体 + Canvas `fillText` | **0** | 像素风不统一，但**最省**；可加描边/阴影弱化违和感 |
| B. 位图字体（BMFont）**子集化** —— 只打包实际用到的字 | 常用 3500 字约 1-2MB；**仅打包 UI 实际用字可压到 200-500KB** | 需维护字表；新增文案要重生成 |
| C. 完整字库内嵌 | 3-8MB | 🔴 直接吃掉整个主包，不可接受 |

**建议**：一期走 **B 的子集化极简版**（只打包 UI 固定文案用字，剧情文本走 A 系统字体）；后续内容稳定后再评估。

### 🔴 炸弹二：音频

一首 3 分钟 BGM @128kbps mp3 ≈ **2.9MB**，一首就能吃掉主包的 70%。

| 方案 | 体积 | 建议 |
|---|---|---|
| 短循环 BGM（8-16 秒无缝 loop） | 150-300KB | ✅ **一期推荐** |
| BGM 走远程 CDN | 0（包内） | ✅ 需配域名白名单；首次播放有延迟 |
| 完整 BGM 内嵌 | 2-3MB/首 | ❌ 一期禁止 |

**音效**（攻击/命中/按钮）：单条短音效 5-30KB，总量可控，可内嵌。

## 五、对素材管线的硬约束（须下发到 T10 / T11）

以下三条须作为**交付验收项**写进素材清单与任务卡：

1. **PNG-8 索引色 + 图集整合**：所有像素素材交付前转索引色（调色板 ≤256 色），同模块素材合并为图集（atlas），禁止逐帧散 PNG 入库
2. **体积预算列**：素材总表（Excel）每行增列「单件体积上限」，T10 素材清单须给出**每模块体积预算**，不是只列数量
3. **音频策略前置**：T10 清单须明确 BGM 走「短循环」还是「远程」，不得默认内嵌
