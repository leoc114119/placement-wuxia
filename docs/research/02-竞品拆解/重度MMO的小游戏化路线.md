## 〇、一句话结论

**两条路线，都成立，都不是"塞进去"：**

- **A · 全量远程（技术解）**：完整 MMO 真上小游戏，包内只留壳，内容全走 CDN
- **B · 玩法裁剪（产品解）**：小游戏只做轻量入口端，重度内容留给 APP/PC，靠账号数据互通

---

## 一、两个已上线实例

### 1.1 天龙八部荣耀版 —— 路线 A：全量远程

| 项 | 内容 |
|---|---|
| 出身 | 成都初心互动科技，金庸正版授权 |
| 形态 | 微信小游戏（亦被应用宝收录为小游戏） |
| 内容完整度 | **完整 MMORPG**：门派 / 珍兽 / 帮会 / 副本 / PK / 千人同屏 |
| 玩家侧体验 | 「微信直接点开游玩，无需下载」「挂机刷怪，平民也可以玩」 |
| 归类 | 渠道侧归为"武侠挂机类小程序" |

→ 它证明了：**完整 MMO 真的能跑在微信小游戏里**，代价是几乎所有资产都在 CDN 上。

### 1.2 剑侠情缘：重逢 —— 路线 B：玩法裁剪 + 三端互通

| 项 | 内容 |
|---|---|
| 出身 | 西山居正版授权 / 虎牙独家发行，2026-06-26 官宣开启预约 |
| 研发 | 《剑侠世界》端游原班核心团队 |
| 形态 | **三端互通**：微端小游戏（微信 + 抖音）/ 独立 APP / PC 客户端，账号数据无缝切换 |
| 内容分工 | 小游戏端 = **轻量化玩法**（门派养成 / 休闲 / 碎片时间做任务）；APP+PC = 宋金战场 / 野外 PK / 家族团战 / 师徒情缘 |
| 官方话术 | 「小程序版本支持免下载即时体验，满足碎片化娱乐需求」「无需下载几十 G 的包体，点开一秒直达临安城」 |

→ 它证明了：**小游戏可以只当入口端**，重度玩法留在别处，用账号互通把用户导过去。

### 1.3 两条路线的本质差异

| | A 全量远程 | B 玩法裁剪 |
|---|---|---|
| 解法性质 | 技术解 | 产品解 |
| 用户拿到什么 | 完整游戏，但首次加载重 | 轻量版，重度内容需换端 |
| 主要成本 | CDN 流量 + 加载体验 | 多端研发 + 数据互通架构 |
| 适配场景 | 内容必须完整才有意义 | 内容可分轻重，小游戏负责拉新/留存 |
| 代表 | 天龙八部荣耀版 | 剑侠情缘：重逢 |

## 二、技术要点（微信官方 Unity WebGL 转小游戏文档 + 工程实践）

1. **官方原话**：「小游戏需要做到即点即玩，启动仅能加载少量资源，**其余部分都必须放 CDN 进行延迟加载**」
2. 🔴 **关键限制：微信不支持加载本地 Bundle** —— 无论 AA / AB / Instant Game 哪种方案，**最终都得上传 CDN、运行时异步下载**（这是与原生 APP 最大的工程差异）
3. **重度游戏推荐 AB（AssetBundle）而非 AA（Addressable）**：AA 在大项目生成的未压缩 catalog 偏大、加载效率低，改 AB 后提升明显
4. **Instant Game**（Unity 官方自动懒加载纹理/模型/骨骼动画/音频）：省改造人力，但**不支持自选 CDN**（须用腾讯云）
5. 首包 = 引擎 runtime + 启动场景，必须 ≤4MB（需代码剥离 High/Full + 精简引擎模块）
6. **压缩格式：微信环境不支持 LZMA，必须用 LZ4**；纹理用 ASTC/ETC2/PVRTC
7. **网络并发上限 10 个请求** —— 影响加载队列与分块粒度设计
8. 红线不变：远程**不得放可执行 JS**，代码体积省不掉

### 代价

- 首次进入下载量大（几十~几百 MB），强依赖加载条设计与分场景预载
- **CDN 流量是持续真金白银的成本**（重度 MMO 可达每月数十 TB）
- 弱网 / 首次加载体验是留存杀手

## 三、对 placement-wuxia 的启示

| # | 结论 |
|---|---|
| 1 | **我们不必走 MMO 路线**：像素 + 放置 + 自研无引擎，体积天然小，20MB 大概率够用 ✅ |
| 2 | 🔴 **但架构要从第一天按「可远程」组织**：素材引用走统一资源管理器 + 配置表，**禁止代码里写死本地路径**；否则后期想挪 CDN 要全量重构（已写入 PROJECT-MEMORY 技术栈约束） |
| 3 | 大件（中文字体、BGM）**一期就放 CDN**，不占包体 |
| 4 | **自研 Canvas 2D 无引擎是巨大优势**：对比 Unity 转小游戏，光引擎 runtime 就要吃掉大半主包（Cocos 3.x 2D 基础资源约 2.5MB / 3D 约 3MB） |
| 5 | 若二期膨胀（多门派 / 多场景 / 多代际内容）→ 走路线 A（CDN 外置），**架构预留则无需重构** |
| 6 | 路线 B 备选记着：若哪天玩法膨胀到装不下，「小游戏做轻量入口 + 重度端在别处」是被验证过的解法——且剑侠的三端互通正是「跨端成为入场券」趋势的落地 |
