## 四、详细设计

### 4.1 AGENTS.md（增量补一节，不动现有内容）

**原则**：现有 ZCode 施工守则**一字不改**；只在最前面加"〇、工具无关总览"，让所有工具先看到全貌。

新增内容草案：
```markdown
## 〇、工具无关总览（所有 Agent 必读）
- 项目：放置武侠小游戏（微信小游戏），挂机 → 学武功 → 战斗 → 变强
- 技术栈：TypeScript + 原生 Canvas 2D + 微信云开发（已定，不换）
- 三工具分工：
  - ZCode → 写游戏代码（81 任务卡制，本节下方施工守则）
  - Codex → 开发以外的活（调研/文档/工具管线/浏览器桌面操作）
  - CodeBuddy → 编排 + 文档 + 质检（C 环）
- 项目级记忆：读 `docs/PROJECT-MEMORY.md`（单一真源，写决策前先读它）
- 文档索引：指向 docs/ 核心文档
```

### 4.2 docs/PROJECT-MEMORY.md（新建，项目级记忆单一真源）

**结构模板**：
```markdown
# 项目记忆 · placement-wuxia（单一真源 · 所有工具共用）

## 0. 怎么用这份记忆（铁律）
- 项目级决策/约定 → 只写这里（不写平台私有记忆）
- 平台私有记忆只放"会话过程日志"，不放项目真相
- 任何工具开工 → 先读本文件 + AGENTS.md

## 1. 项目定位（一句话 + 战略层级）
## 2. 设计回炉状态（两根支柱 / 方向 / 待拍板项）
## 3. 技术栈（已定不换）
## 4. 工具分工（ZCode / Codex / CodeBuddy 各管什么）
## 5. 关键决策与约定（追加制：日期 | 决策 | 理由 | 签字）
## 6. 管线教训（追加制：日期 | 教训 | 固化到哪）
## 7. 文档索引（核心文档链接）
## 8. 变更记录（git log 配合，本文件变更随 git 提交）
```

**写入规则（防漂移铁律）**：
1. 项目级决策 → 只写 `PROJECT-MEMORY.md`（单一真源）
2. 平台私有记忆（`~/.workbuddy/memory/`）→ 只放"会话过程日志/平台操作记录"
3. 任何工具读项目真相 → 只读 `AGENTS.md` + `PROJECT-MEMORY.md`
4. git：一决策一提交（含 PROJECT-MEMORY.md 变更）

### 4.3 persona（各自全局，内容同源）

- **CodeBuddy**：现有 expert 插件（game-development-studio-team-lead.md）**不动**
- **Codex**：把同一份 persona 写入 `~/.codex/AGENTS.md`——包含：
  - 我是谁（游承峰 · 主理人 · 编排者不建造）
  - 专家团成员表 + 路由表
  - 铁律（不亲自写 GDD/代码、成员间不直连、质量门、协作五步）
  - **Codex 专属边界**：🚫 不碰游戏代码（ZCode 地盘）、🚫 不改已验收设计文档、✅ 产出落约定目录 + 交付说明
- **同源机制**：persona master 存一份（WorkBuddy expert），变更时手动同步到 `~/.codex/AGENTS.md`（低频变更，手动可接受；后续可加同步脚本）

### 4.4 技能（跨项目资产，复制到 Codex）

- 技能是**跨项目资产**（不属 placement-wuxia 项目真相）→ 允许复制
- 复制 `~/.workbuddy/skills/` 下的 SKILL.md 到 `~/.codex/skills/`
- 当前技能：`ai-game-art-pipeline`、`vibe-coding-collab`（+ 后续沉淀的编辑器体系技能）
- **注意**：技能是"复制"（非共享），更新时需两边同步——低频、可接受；后续可加同步脚本

## 七、风险与缓解

| 风险 | 缓解 |
|---|---|
| 双平台记忆漂移 | 单一真源 PROJECT-MEMORY.md；平台私有只放日志；git 版本化可追溯 |
| Codex 乱动项目文件 | persona 写死边界（不碰代码/不改已验收文档）；CodeBuddy C 环把关 |
| AGENTS.md 被多工具读混 | "工具无关总览"在最前，施工守则在后面分区 |
| 迁移期两份记忆并存 | 过渡期允许共存；验证后平台私有记忆只做日志 |
| 技能/记忆双平台不同步 | 低频变更手动同步；后续可加同步脚本（待 Leo 拍板） |
