## 0. 目标与原则

1. **现实可执行**：微信小游戏有限制（无 DOM、包体限制、云函数本地不可直跑），测试方案先承认限制再给解法。
2. **分层测试**：纯逻辑可自动测（node 环境）；渲染/预览/线上行为必须 Leo 人工验收——**诚实声明边界**。
3. **测试即门禁**：第 1 环任何一项失败 → 打回 ZCode；第 1 环通过 ≠ 可用，第 2 环是最终裁决（07 §1）。

## 1. 微信小游戏环境限制盘点（测试方案的约束前提）

| # | 限制 | 对测试的影响 | 应对 |
|---|---|---|---|
| L1 | 无 DOM / 无 window / 无 document | jsdom 类前端测试框架基本不可用 | 渲染不进自动测试；纯逻辑模块化后 node 直测 |
| L2 | 包体限制（主包 ~4MB，总包 20MB） | 测试框架/依赖不能进包 | 运行时零 npm 依赖；devDeps（vitest/eslint/tsc）不打包 |
| L3 | Canvas 由 `wx.createCanvas()` 提供 | node 环境无 `wx` 全局 | 抽 `tests/mock/wx.ts` mock；或把 Canvas 访问收敛到 `game.ts` 薄层 |
| L4 | 云函数本地不能直跑 `wx-server-sdk` | settle 无法整函数单测 | settle 抽 `core.js` **纯函数层**（不依赖 wx-server-sdk），DB 薄壳分离 |
| L5 | 微信开发者工具预览/真机渲染 CodeBuddy 测不了 | 效果关必须 Leo | 渲染效果与线上行为明确划给 Leo 第 2 环 |
| L6 | 云函数部署后的线上行为本地不可复现 | 契约易漂移 | 契约测试（本地断言两端结构一致）+ Leo 云端验证 |

## 2. 六项检查落地表（第 1 环）

| 检查项 | 工具/命令 | 微信小游戏适配 | 判定 | 责任 |
|---|---|---|---|---|
| ① 编译 | `tsc --noEmit`（客户端） | 客户端 `src/` 单独 tsconfig（strict）；云函数侧用 `node --check`（JS）或独立检查 | 0 error | Z 修 / C 验 |
| ② 类型 | 同上 + eslint `no-explicit-any` | strict 下禁止 any 泄漏；契约类型（types.ts）不导出 any | 0 error | Z 修 / C 验 |
| ③ 静态 | `eslint` + 自定义规则 | **数值集中规则**：除 `config/numbers.ts` 与 `cloudfunctions/settle/core.js` 配置区外，禁止业务数字字面量参与公式（用 AST/正则扫描兜底）；**依赖方向规则**：禁止 `ui/` import `systems/`、禁止 `systems/` import `ui/`、禁止非 `net/cloud.ts` 调 `wx.cloud`；**循环依赖扫描**脚本 | 0 error | Z 修 / C 验 |
| ④ 单元测试 | `vitest`（node 环境） | 只测纯逻辑：SceneManager 生命周期、NUMBERS 完整性、云函数 core 结算函数、迁移函数；**不测渲染** | 全绿 | Z 写 / C 验 |
| ⑤ 模拟运行 | node 脚本直接调用 core.js（mock DB） | 用 `tests/mock/` 假 DB 薄壳模拟云函数运行；**不 mock 结算逻辑，只 mock 存储** | 输出符合设计文档 | C 执行 |
| ⑥ 设计一致性 | 人工对照 + 检查清单 | 对照 03/10/12/13/05 设计、04 色值、07 清单逐项；素材路径在 `assets/ui/` | 通过/打回+偏差说明 | C 执行 / L 裁决 |

**命令统一封装**（`package.json` scripts，Z 与 C 共用同一入口）：
```
npm run typecheck   # ①+②
npm run lint        # ③
npm run test        # ④（vitest run）
npm run simulate    # ⑤（node 模拟运行核心逻辑，输出断言）
npm run check:all   # ①~⑤ 一键全跑，Sprint 0 T06 目标
```

## 3. 单元测试策略（哪些能测、怎么测）

### 3.1 可自动测（node 纯逻辑）

| 被测对象 | 内容 | 说明 |
|---|---|---|
| `src/scenes/scene-manager.ts` | switch 生命周期顺序（onExit→onEnter）、非法场景 id | 不依赖 wx |
| `src/config/numbers.ts` | NUMBERS 完整性（对照 GameNumbers 接口所有键非空）、无 NaN/Infinity | 类型 + 值双重兜底 |
| `cloudfunctions/settle/core.js` | idle 挂机结算（时长×效率）、learn 校验（资源/前置/已学）、battle 站桩结算（伤害公式/胜负/掉落）、requestId 幂等、服务端时间锚防回拨 | **核心测试资产**，mock DB 入参出参 |
| `cloudfunctions/*/migrate` | 版本迁移（v1→v2） | 数据层守则 6 |
| `src/net/cloud.ts` 的 requestId/错误归一（纯函数部分） | 幂等键生成、code→提示映射 | 依赖注入 wx 调用 |

### 3.2 不可自动测 / 必须人工（诚实边界）

| 项 | 原因 | 责任 |
|---|---|---|
| Canvas 真实渲染效果、动画观感 | node 无渲染环境 | Leo 微信预览 |
| 微信开发者工具编译/预览/真机 | L5 | Leo |
| 云函数部署后的线上结算行为 | L6 | Leo 云端测试 + C 契约测试兜底 |
| 包体体积实测 | 依赖真实构建 | Leo 构建后查 |

### 3.3 mock 方案（`tests/mock/wx.ts`）

- mock 范围最小化：仅 mock `wx.createCanvas`（返回假 canvas 上下文桩）、`wx.cloud.callFunction`（回放预置响应）、`wx.getSystemInfoSync`（返回固定尺寸）。
- 原则：**只 mock 平台，不 mock 业务**——结算逻辑必须真实执行。

## 4. 模拟运行与契约测试（云函数侧落地）

### 4.1 为什么需要 core.js 抽离（ADR-002 影响项）

- `wx-server-sdk` 本地不可直跑（L4）→ 把"结算与校验"抽成 `core.js` 纯函数（输入：存档 + 请求 + serverTs；输出：delta + 新存档 + battleLog），`index.js` 只做三件事：解析 OPENID/参数、调 core、写 DB（薄壳）。
- 效果：core.js 在 node 里直接可测、可模拟运行；DB 用 mock 薄壳注入。

### 4.2 模拟运行用例（`npm run simulate`）

| 用例 | 输入 | 期望输出 |
|---|---|---|
| idle 在线结算 60s | 存档 + action=idle | 学点增量 = 时长×效率（与 numbers/设计一致）；lastSettleAt=serverTs |
| idle 离线 8h | offline=true | 按离线规则结算（12 设计：学点+熟练度，无实战/装备） |
| 时间回拨 | serverTs < lastSettleAt | 拒绝/按 0 结算，日志告警（ADR-005） |
| learn 前置不足 | 学点不足 / 前置等级不够 | 1002 / 1003 错误码 |
| battle 6v6 站桩 | 固定双方阵容快照 | battleLog 长度 ≤ 上限；胜负/伤害符合 13 设计公式；掉落入 delta |
| requestId 重放 | 同一 requestId 两次 | 第二次返回首次结果，不重复结算 |

### 4.3 契约测试（`tests/contract/`）

- 客户端 `types.ts` 契约类型与云函数 `common/contract.js` 结构**互相对齐断言**：
  - 序列化一次真实响应样例 → 用类型检查/运行时校验断言字段齐全、类型正确、错误码在冻结表内。
- 目的：拦截"客户端改了字段、云函数没跟上"的漂移（L6 兜底）。
