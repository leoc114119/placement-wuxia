## 0. 分工一句话

## 3. 流转流程

```
我方装卡（需求表+数据+用例+验证）→ DoR 全过 → 发单
  → ZCode 按需求表施工（架构自定，边界不可碰，需求含糊就问）
  → ZCode 提交（自测 DoD + 架构决策说明）
  → CodeBuddy：六项检查 + 跑用例 + 对照方案建议提问题（ZCode 需回应）
  → Leo 按验证要求点验 → 签字 → 下一张卡
```

## 4. 歧义与变更

| 场景 | 处理 |
|---|---|
| ZCode 遇需求含糊/冲突 | **停下提问**（引用需求表 # + 原文 + 暂停点），不自行假设；我们 1 工作日内回复并更新任务卡版本 |
| 架构/实现问题 | ZCode 自决，但须写入提交说明（决策+理由）；CodeBuddy 验收时提问审查 |
| 需求变更（含验收发现问题） | 停单 → 更新需求表（版本号+变更记录）→ 重发 → 增量施工，已验收部分不动 |
