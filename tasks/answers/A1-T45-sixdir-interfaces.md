## ① FACE-1 术语勘误（执行完毕）

**结论**：核实成立，已执行勘误。六边形实为 **pointy-top（上下尖，宽:高 1:0.7 压扁）**；「邻格无正上正下」系**奇偶行错位半格布点**（ROW_H=0.75×TILE_H，同列隔行不相邻）所致，非六边形朝向。结论六向不变，仅改术语与归因。

**理由（证据）**：
- `battle-hex-render.ts` drawTile 顶点序（L760-766）：上尖(0,-hh) / 下尖(0,hh)，左右为竖直边（lt/lb、rt/rb 同 x）——标准 pointy-top，非 flat-top（flat-top 应为上/下平边、左右尖）。
- `config/battle-hex.ts` TILE_SPEC（L10-15）：hRatio=0.7（纵向尖到尖压扁）、rowRatio=0.75（行距=格高×0.75）；`hexToWorld`（L30-33）奇数行 px 偏移 0.5×TILE_W——奇偶行错位半格布点，故紧邻格=左右+四斜角、无正上正下。
- 需求文档 v2.0 §1 已是正确表述（「同列隔行不相邻，非六边形朝向所致」）；美术线五处已先行勘误（commit 4976f34，LOG 09-04 17:00）——本次研发线侧对齐。

**改动位置**：`docs/design/03-战斗系统/战斗交互行为规格.md` FACE-1 条目（全文档唯一 flat-top 字样，grep 证实）+ 更新记录补勘误行。

## ② §8.1 左系镜像交付形态（定夺）

**结论**：**方案 A——美术管线直接产出左系 PNG 成品文件**（磁盘 156 文件，渲染路径零新增逻辑、换表即接）。

**理由（三面评估）**：
1. **FE 接线复杂度（决定性）**：A 六向统一按 `{动作}_{向}_{序号}.png` 查表，现有帧消费路径 `assets.frames.get(spriteKey)[帧号]`（battle-hex-render.ts drawPieces）零分支；B 需 drawPieces 朝向翻转分支 + weapon_anchor 运行时镜像（x′=W−x、angle 镜像）+ 呼吸帧程序化派生 + 后续出招特效/受击挂点**全部携带翻转知识**——横切决策点多点化，与《战斗交互行为规格》§八病灶总结（「同一决策的多点公式=漂移温床」）直接冲突，刚付完学费不该再引入。
2. **微信小游戏包体/加载**：实测帧均值 ≈47KB/张（battle45 现存 13 张，622KB/13），A 增 78 文件 ≈ +3.7MB；但六向全量 156 张 ≈ 7.4MB **本已超微信主包 4MB 限**，A/B 同需分包/资源外置通道（现加载器 ui/assets.ts 为 wx.createImage 本地包路径，外置属发布侧必做项），A/B 差异仅为用户下载量 +3.7MB，挂账发布侧规划、不阻塞生产。
3. **帧表数据结构**：A 六向平铺直接映射 ANIM_FRAMES、锚点元数据每帧独立登记（左系帧带镜像后锚点）；B 需 left→right 归一化映射 + flip 标志位，types 与帧表多一层翻转语义。
- 附加：镜像确定性由管线**程序化镜像 + check 校验门**（左右对称性可程序验证）在产线拦截，错误不进运行时。

**改动位置**：需求文档 §8.1（已闭标注+定夺理由，标"主架构定夺 2026-09-04"）+ §9 DoD 第 3 条同步 + 状态行/签行。

## ③ §8.3 weapon_anchor 元数据格式（定夺）

**结论**：**方案 B——代码常量表**。运行时真源 = FE 常量表（建议 `config/battle-frames-meta.ts`，ADR-004 只读展示参数口径；`WeaponAnchor{x,y,angle}` 类型进 types.ts，落码归战斗实装卡，本次零代码改动）。

**理由**：
1. **项目原则咬合**：锚点是渲染挂接参数、非结算数值——按「UI 只展示/数值集中」（ADR-004）归 config 只读常量，与 numbers.ts 同模式；「类型约束：数据结构定义在 types.ts」常量表直接咬合类型，伴随 json 无类型检查。
2. **三零门覆盖**：常量表受 typecheck/lint/build 管；json 文件不进门，错值只能运行时暴露。
3. **FE 消费方式**：渲染层棋子绘制内联同步查锚点（武器叠加与帧同拍），常量表零 IO；json 伴随 = 每帧一文件（叠加 §8.1 的 156 PNG → 312 文件）+ 预读解析与缓存管理，加载器复杂度净增。
4. **管线交付流不变**：按批产出 json 样例/manifest 作为**交付源**（批 0' 起并行给出，选型依据保留），战斗实装卡誊录进常量表；防誊录漂移 = 接线卡 DoD 加「manifest vs 常量表逐帧 diff 对表」。angle 冻结垂向右下、出招跟手不转（§2.5-4）口径不变。

**改动位置**：需求文档 §8.3（已闭标注+定夺理由+交付流，标"主架构定夺 2026-09-04"）。
