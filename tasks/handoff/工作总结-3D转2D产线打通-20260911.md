# 工作总结：3D→2D 动作帧产线从零打通 · 2026-09-11 · 美术 PM2

> **一句话**：今天从零打通了「Tripo 3D 模型 + 外部动作 → 渲染成 2D 动作帧」的完整产线，交付 **3 套动作 × 六向 × 5 帧 = 90 张成品帧**（每套约 350KB），并把它固化成可复现的流程与工具。全程 **0 积分**（纯本地计算）。

## 一、今天做成了什么（按重要性）

### 1. ★ 3D→2D 动作帧产线打通（核心成果）

**七步全链**（分界线：[1][2] 需人工，[3]~[7] 脚本全自动）：

```
[1] 图 → 3D 模型（Tripo 网页，Leo 手动）        ← 人工
[2] 下载动作（Mixamo，Leo 手动）                ← 人工
[3] 重定向（把外部动作搬到我们模型上）           ┐
[4] 渲染（4×超采样 / 近平涂 / 双线性 / 固定机位）  │
[5] 降采样（箱式滤波）                          ├ 全自动
[6] 后处理（描边 + 调色板量化 + 去斑）           │ 0 积分
[7] 挑关键帧（5 帧）→ 导出 PNG-8                ┘
```

**手册**：`docs/design/01-基础功能/3D转2D动作帧产线流程.md`（含全部命令、参数标定理由、踩坑记录）

### 2. 三套动作成品（各六向 × 5 帧）

| 动作 | 帧数 | 体积 | 单帧 | 用途 |
|---|---|---|---|---|
| **walk** | 30 | 354 KB | 11.8 KB | 已定，**将被 run 替代**（战斗行走） |
| **jump** | 30 | 338 KB | 11.3 KB | 跳跃（原 1 帧 → 5 帧） |
| **run** | 30 | 355 KB | 11.8 KB | **战斗行走帧**（Leo 裁定） |

统一：**256 色 / PNG-8 无损 / 240×320 / 六向 / 5 帧**

### 3. 规格定稿（Leo 拍板）

- **5 帧/动作**（每方向）
- **220 ms/帧**（总 1100ms）—— 跳跃定档
- **速度规范**：`每帧时长 = 源动作时长 ÷ 帧数`（防"偷偷快放"）
- **颜色口径**：256 色（32 色会导致肤色发灰，Leo 否掉）

### 4. 方向映射（Leo 亲定）

| 方向 | yaw | | 方向 | yaw |
|---|---|---|---|---|
| **leftdown** | **225** | | right | 90 |
| rightdown | 135 | | rightup | 45 |
| left | 270 | | leftup | 315 |

判据：脸心 − 发心 的横向偏移。**禁止目测判断方向**。

## 三、今天踩的坑（全部已修，教训固化）

### 渲染/后处理类

| # | 坑 | 根因 | 修法 |
|---|---|---|---|
| 1 | **花斑/脏边** | 贴图采样用最近邻（2048² 贴图渲到 256px，每像素对应 8×8 纹素只取一个） | 改**双线性** |
| 2 | **锯齿** | 直接在 240×320 光栅化 | 改 **4× 超采样 + 降采样** |
| 3 | **描边把人物涂黑**（86.5% 像素判为边缘） | 用**相对深度差**，深度跨零点时分母趋零 → 差值爆炸 | 改**绝对深度差** + 按实测分布标定 |
| 4 | **脸上/头发出红绿色斑** | **逐通道独立量化**会改色相（棕变红） | 改 **k-means 调色板量化** |
| 5 | **跳跃看不出起跳** | 渲染器**每帧自适应缩放**，把上下位移整个抵消 | 改**固定机位**（用静止姿态包围盒作唯一基准） |
| 6 | **头发呈"铁丝网"** | 法线阈值过低，把发丝细纹理也描出来 | 阈值 0.85 → **0.95** |
| 7 | **肤色发灰** | 32 色太少（Leo 亲指） | 改 **256 色** |
| 8 | **PNG-8 有损** | 量化 256 色 + 描边墨色 = 257 色，超边界 | 加 **`--palette-reserve 8`**（量化 248 色）→ 无损 |

### 重定向类

| # | 坑 | 根因 | 修法 |
|---|---|---|---|
| 9 | **手消失** | 用「世界系增量」公式，但 Mixamo rest 是 **T-pose**、我们模型是 **A-pose**（差 ~85°） | 改**以动画第 0 帧为基准** + **方向匹配（aim2）** |
| 10 | **人横躺** | `mul(a,b,c)` 传三参，而 mul 只接受两参 → **第三参被静默丢弃** → Root 算错 → Hip 偏 90° | 修未映射骨骼处理 |
| 11 | **帧序/头脚朝向乱跳** | 纯 aim 只约束「骨骼指向」，**绕轴扭转无约束** | 改**两段式（先取扭转增量，再做方向校正）** |

### 脚本/流程类

| # | 坑 | 根因 | 修法 |
|---|---|---|---|
| 12 | **批跑画质差** | zsh 不对未加引号变量做词分割 → `$PP` 被当成一个参数 → **静默用默认值** | 改**数组传参** + 脚本**自报生效参数** |
| 13 | **重复帧被选中** | 「最远点采样」优化器被源动画里的重复帧欺骗 | **循环动画必须用均匀相位采样** |
| 14 | **假 PNG 文件** | 后处理输出裸 RGBA，却给了 `.png` 扩展名 | 落盘时显式转 PNG |
| 15 | **方向靠猜** | 我先后试了三种自动配对（全图/头部/轮廓 IoU）**全部不可靠**（姿势不同污染特征） | **语义映射由人目验定** |

### ★ 最重要的一条方法论教训

**多次错误根因相同：我一直在"矩阵运算"层面推导，从没把两套骨架摆在一起比过。**

配套：**先看数、再看图**（「帧 0 = rest」校验）。
