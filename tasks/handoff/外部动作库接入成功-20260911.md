## 三、我做了什么（新工具）

### `tools/glb2d/retarget.mjs` —— BVH 重定向器

**原理**（标准骨骼重定向，非我自创）：

```
1) BVH 的 rest pose 各骨骼旋转恒为 0
   → 某帧的「世界旋转」即等于「相对 rest 的旋转增量」
2) 目标骨骼世界矩阵 = 增量 × 模型的 rest 世界矩阵
3) 局部旋转 = 父世界矩阵⁻¹ × 自身世界矩阵，写回节点
4) 未映射的骨骼（扭转骨/手指）继承最近已映射祖先的增量，
   避免子骨骼做反向补偿而扭曲
```

**用法**：
```bash
node tools/glb2d/retarget.mjs <模型.glb> <动作.bvh> <输出.json> \
     --frames 120 --fps 30 --root y
```

同时给渲染器（`render.mjs`）加了**外部动画 JSON 加载**，可以直接渲染重定向结果。

## 五、这条路的边界（如实说）

**✅ 能做到**：
- 动作数量**几乎无限**（CMU 2600+，且可继续接 Mixamo 2000+）；
- 动作**质量高**（真人动捕，不是 AI 生成的"看着像"）；
- **免费**（CMU 数据集可自由使用）；
- 全流程本地跑，**0 积分**。

**⚠️ 局限**：
1. **A-pose 与 T-pose 差异**会带来轻微姿态偏差（BVH 是 T-pose 参考、模型是 A-pose），已用"世界增量重定向"缓解，**但手臂轴可能有轻微偏移**——需要逐个动作目验校准；
2. **手指动不了**（模型没有手指骨），手部会保持握拳；
3. **根位移**默认只取 Y（上下），水平位移我关掉了（避免人物跑出画布）——如需位移可开 `--root xz`；
4. **CMU 动作不是武侠动作**——它是通用的剑术/拳击，**不是影视武打设计**，观感偏"真人运动"而非"武侠飘逸"；
5. **两个动作我各只看了 8 帧抽帧**，没逐帧检查质量问题。
