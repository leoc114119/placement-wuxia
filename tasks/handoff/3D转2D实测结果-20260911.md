# 3D 模型转 2D 序列帧 · 实测结果（2026-09-11 · PM2）

**你给的那个 GLB（`chibi+warrior+3d+model.glb`）我渲出来了——行走和跑步的腿部交替是真的，画面质量也比之前那张好得多。但有个关键问题：它是「正面朝向的模型」，转成 2D 帧后和我们的侧视/3/4 视角帧对不上。**

---

## 一、这个模型的情况（先解结构）

| 项 | 实测 |
|---|---|
| 骨骼 | ✅ **41 根**（Root/Hip/Pelvis/双腿/双臂/脊柱/头，含扭转骨） |
| 动作 | ✅ **2 个**：`preset:biped:walk`（2.375s）、`preset:biped:run`（1.29s），各 123 条通道 |
| 面数 | **95,521 三角面** |
| 文件 | **5.7 MB**（对比上一个：115 万面 / 33.8 MB） |
| 贴图 | 4096×4096 三张（baseColor / normal / metallicRoughness） |

**和上一个模型的本质区别：这个已经绑好骨、带动作了。** 上一个只是裸模型（10 个未绑骨部件）。

---

## 二、我怎么渲的（本机没渲染器，我写了一个）

本机**没装 Blender / 没有 3D 渲染库**，所以我写了个**软件光栅渲染器**（`tools/glb2d/`），自己做：

1. 解析 GLB（顶点/法线/UV/**骨骼权重**/逆绑定矩阵/动画曲线）；
2. **做蒙皮**（骨骼矩阵 × 权重 × 逆绑定）——所以动作是真的在动，不是摆姿势；
3. 采样动画时间轴 → 正交投影 → 三角形光栅化 + 深度测试 → 贴图采样；
4. 输出**和我们游戏完全一样的 240×320 画布**（人物高映射到 256px，和现有帧同规格）。

**这不是猜的，是逐像素渲出来的**；产物都在 `assets/_trial_20260911/glb2d/`。

## 三、结论：能做什么、不能做什么

### ✅ 能：动作是真的，而且是**高质量的真交替**

我渲了行走 8 帧、跑步 8 帧（正面）＋行走 8 帧（侧面）。**腿部交替经程序化测量证实**：

| | 测量结果 |
|---|---|
| 行走（正面） | 两腿最低点差 **-2 ~ +7px，符号翻转 3 次** → 两腿确实在换 |
| 跑步（正面） | 差 **-1 ~ +20px，符号翻转 4 次** → 更明显 |
| 行走（侧面） | 脚部 x 跨度 **51~103px 周期波动** → 前后迈步幅度真实 |

**这是我们折腾了很久没做到的事**（回想：2D 生图路线里，跑动的腿交替是"剪影分不出左右腿"的死结）——3D 骨骼这边**天然就对**。

### ⚠️ 关键问题：**视角对不上**

| 我们的需求 | 这个模型的现状 |
|---|---|
| 战斗帧 = **3/4 俯视侧视**（`battle_idle_right`） | 模型默认朝向**正面**，转 90° 得到的是**正侧面**（不是 3/4） |

**这不是模型的问题，是"它在网页上被生成时的朝向"决定的。** 从我们的正面素材生成 → 模型就是正面的。要拿 3/4 视角，得**在渲染阶段自己转角度**（我的渲染器已支持 `yaw` 参数，已验证 0/90/180 三个角度都能出图）——**但那个 45° 俯角 + 3/4 侧的具体角度，需要标定**，不能随便转。

### ✅ 画风：比预想的好，但仍不是我们的画风

| 项 | 我们现有 2D | 3D 渲染 |
|---|---|---|
| 色数 | **9,472** | 6,618 |
| 轮廓 | **粗黑描边、平涂** | 柔和明暗过渡、**无描边** |
| 观感 | 手绘像素/厚涂 | **干净的低模厚涂**（不像之前那版那么"塑料"） |

**这个模型的贴图质量明显好于上一个**——脸、发丝、衣服褶皱都有细节。**观感上比预期接近我们**，但仍缺**平涂 + 黑描边**这两个我们画风的标志性特征。

我试了一版**后处理**（量化色阶 + 描边）看能不能拉近：**方向是对的但做法太糙**——我的描边算法把发丝内部纹理全当成了边缘，头发变成一团黑。**这说明"后处理能调画风"这条路可行，但需要正经做法**（按深度/法线做描边，而不是按颜色差），不是我这种粗暴版本。

---

## 四、我的判断

**这条路的技术可行性，今天被证明了一部分：**
- ✅ **动作问题天然解决**（真骨骼、真交替、无漂移、无换手难题）
- ✅ **渲染管线可程序化**（我已经能批量出 240×320 帧，且支持任意视角）
- ⚠️ **视角需要标定**（45° 俯角 + 3/4 侧 = 我们的战斗帧规格）
- ⚠️ **画风需要后处理**（平涂 + 描边），**这一步没解决，但也没证明不可解**

**和之前那条"AI 生图"路线的根本差别**：那边是**模型能力边界**（换手怎么试都画不出）；这边是**参数调优问题**（视角、渲染设置），**性质完全不同**。

**但我必须说清楚：画风这一关还没过。** 决定这条路能不能用的，是「3D 渲染 + 后处理能不能出来像我们手绘的画面」。今天只证明了**渲染管线通了、动作没问题**，画风只做到"接近但不同"。

---

## 五、建议的下一步（如果你要继续）

**第一步（最关键，决定生死）：标定视角。**
把渲染角度调成和我们 `battle_idle_right` 完全一致，渲一帧和它叠在一起对比。**角度对了才有可比性**——现在拿正面帧跟 3/4 帧比是不公平的。

**第二步：画风后处理做正经版。**
按深度/法线做描边（不是按颜色差），看能不能出来"平涂 + 黑边"。**我可以做这个**——我已经有渲染器，加一层后处理不难。

**第三步（如果前两步都好）：批量验证。**
一个方向 8 帧 → 全动作族 → 6 方向。

## 七、我没做到的（如实登记）

1. **没在 Cocos 里渲**——MCP 服务没启动（autostart 关闭），我用的是自写渲染器。**自写渲染器的光照模型比 Cocos 简单**（只有方向光 + 无阴影），所以**Cocos 里的实际效果会和我这个不同**（可能更好）。
2. **画风后处理只做了糙版**（粗描边把发丝纹理全吃掉了），**不能据此判断"这条路画风不行"**。
3. **视角没标定**——我渲了 0°/90°/180°，但**没找到与 `battle_idle_right` 精确对应的角度**。
