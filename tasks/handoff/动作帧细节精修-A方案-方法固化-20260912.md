## 0. 为什么旧版作废（必读，别重复踩）

旧版把 **6 行 × 5 列 = 30 格**的整张图（1224×1948 = 2.384 MP）交给 `image_gen` 做"只提清晰度"的编辑。
实测结果：**色调变了、精细度没变，30 帧平均锐度 −10.86%（27/30 帧更钝）**。

根因（已定量证实）：**生成模型的工作分辨率低于源图**。
- 模型回传的图纸是 **994×1582 = 1.573 MP**，长宽比与输入完全一致 ⇒ **等比缩到 0.812×** 才开始画。
- 1.5 × 1024² = 1,572,864 ≈ 实测 1,572,508 ⇒ **模型输出预算 ≈ 1.5 MP，图纸超了就等比缩**。
- ⇒ 每格 240×320 实际只被画在 **≈195×260（源像素的 59%）**，再被放大回 240×320：**净降采样**，没有像素预算承载新细节。
- 指纹佐证：损失幅度与源帧本身锐度成正比（最锐的方向掉 13~22%，最软的方向掉 0~8%）。

**结论：格子越多，每格分到的像素越少；图纸像素数超过模型预算，这一趟注定变钝。**

## 1. A 方案（已验证有效）

**核心：把"每格分到的像素"做到源帧的 2.27 倍。**
- 一条方向一张图（**不是**全部动作一张图）
- 3 列 × 2 行网格（第 6 格留空），图纸 **1024×1024**（1:1 是 1K 档能拿到总像素最多的画幅）
- 每格 341×512，帧按 323 宽居中放入 ⇒ **每格 = 源像素的 2.27×**
- 模型实际回传 **1280×1280 = 输入图纸的 1.25×**（即每格再放大到 ~427×640 = 源像素的 3.55×）

### 1.1 逐步骤命令

```bash
# ① 建输入图纸（每个动作一组，一条方向一张）
python3 assets/_trial_20260912/build_refine_sheets_A.py
#    ↳ 当前写死 idle；换动作时把 SRC 目录与 FACINGS 换成目标动作的六向 5 帧

# ② 生成（每个方向一次；gpt-image-2 / 1:1 / 1K = 2 积分）
python3 scripts/mxai_img2img.py \
  assets/_trial_20260912/精灵图_精修输入A/精灵图A_<facing>.png \
  --out <raw>_<facing>.png \
  --prompt-file assets/_trial_20260912/refine_prompt_A.txt \
  --model gpt-image-2 --aspect 1:1 --resolution 1K
#    ↳ 一条动作 6 个方向 = 6 次调用 = 12 积分

# ③ 切帧 + 轮廓配准 + 回填原 alpha
python3 assets/_trial_20260912/split_refine_A2.py <raw>_<facing>.png <facing> <out_dir>
#    ↳ 每方向约 60 秒

# ④ 全 30 帧共用一套调色板 → PNG-8 无损
python3 assets/_trial_20260912/png8_shared_palette.py <out_dir>
python3 tools/glb2d/png8_encode.py <out_dir> <out_dir>
```

### 1.2 prompt（`refine_prompt_A.txt`）—— **锁尺寸那两段不能删**

模型**默认会把人物放大**（实测不锁时 **宽 +16.5% / 高 +18.2%**，套原 alpha 会把头发和靴子切平）。
加上下面两段后收敛到 **宽 +1.2% / 高 +5.0%**：

```
★★每一格里人物的**大小和位置必须与现在完全一致**：头顶到格子上沿的空隙、脚底到格子下沿的空隙、
左右两侧的空隙，全部保持现在的比例不变；**不要放大、不要缩小、不要移动、不要改变头身比**。

★★**不要改动人物的外形轮廓与体积**：头发（含马尾）的外轮廓、衣摆的外轮廓、靴子的外轮廓
都要与现在**完全重合**，只在轮廓**内部**补充细节，不要让任何部位变大或往外鼓。
```

其余段落（3 列 2 行说明、"只把糊变成清"、保留 3D 质感、禁平涂/线稿/加文字）照原文保留。

### 1.3 配准为什么必需（`split_refine_A2.py` 里三个坑已修）

即使 prompt 锁了尺寸，模型仍会**整体右移 + 微放大**，直接套 alpha 会切出平边。所以切帧时要按
「模型人物掩膜 ∩ 源 alpha 掩膜」的 **IoU 最大化**搜出缩放与偏移，把人物拉回源尺寸/位置再套 alpha。

三个已修的坑，**别改回去**：

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 背景色取右下角单像素 | 格宽 427 时右下角正好压在分隔线上 → 灰色分隔线被当背景 → 掩膜覆盖 94% | **四角小块取中值**（`bg_color()`） |
| 取"最高频颜色值" | 零频值在稳定排序里挤进前几名 → 中值被拉到 0 附近 | 同上，用**均值再取中值**（别用频次法） |
| 用"掩膜内亮度均值 − 掩膜外"当贴合判据 | 会被"**缩到只剩亮部**"骗到（实测同一组帧搜出 0.842~0.938 的乱跳缩放） | 用 **IoU**（缩小会掉重合，不会虚高） |

另外**不能用亮度阈值取人物掩膜**：本项目头发是深色，在近黑背景上会被亮度阈值整块漏掉。
必须用**背景距离**（`BG_THR=20`，逐通道差之和）。

配准后验收指标：**IoU ≥ 0.74**（实测 idle 六向 0.745~0.946），**被 alpha 切掉的面积 ≤ 4%**（实测 1.94%）。

### 1.4 门检（**必须含"本次改动的目的项本身"**）

```bash
# 源帧 vs 精修帧，主体内部腐 3px 后的梯度均值（口径锁死）
# 判据：每个方向 ≥ 源帧；任一方向为负 → 打回
```

**口径必须写清并锁死**（这是上一轮翻车的地方：任务书里 5 条验收全是"轮廓更锐利"这类形容词，
没有一条能算，对方自检就写了 `pass: visually sharper`）：

- 主体掩膜 = `alpha > 32`，再 `MinFilter(2e+1)` 腐蚀 **e=3** 像素
- 梯度 = L 通道向右/向下各偏移 1px 求绝对差，掩膜内取均值，横竖取平均
- **为什么必须腐 3px 而不是 1px**：源帧的轮廓是硬混叠边（1px 阶梯），**腐 1px 会把这条边算进去**，
  于是"把轮廓修柔和"会被误判成"变钝"。实测 `leftdown` 腐 1px 是 **−6.8%**、腐 3px 是 **+2.1%** ——
  两张图肉眼一看就是右边细节多得多，判据自己反了。**判据实现必须锁死"是否含轮廓带"。**

**实测结果（idle，腐 3px 口径，PNG-8 交付件）**

| 方向 | 源帧 | A 方案 | 变化 |
|---|---|---|---|
| left | 1.124 | 1.401 | **+24.6%** |
| leftdown | 2.244 | 2.257 | **+0.6%** |
| leftup | 0.908 | 1.497 | **+64.8%** |
| right | 0.970 | 1.483 | **+52.8%** |
| rightdown | 2.121 | 2.270 | **+7.0%** |
| rightup | 0.964 | 1.348 | **+39.9%** |
| **合计 30 帧** | **1.389** | **1.709** | **+23.1%** |

其他必过项：
- **alpha 与源帧逐字节一致**（轮廓像素级不变，保证与其他动作/现有素材对齐）
- 尺寸 240×320、`png8_encode.py` 报 **lossless**（共用一套 248 色调色板，不抖动）
- **循环一致性**：同方向相邻帧平均差 1.4~3.2（数值低=顺，不会闪）
- ★ **人眼过图**：`assets/_trial_20260912/预览_细节精修A.html`（图片内嵌，直接打开）

### 1.5 已知边界（如实记录，别过度承诺）

- 朝下的两个方向（leftdown/rightdown）增益最小（+0.6% / +7.0%）——它们的源帧本身阴影过渡最重、
  硬边最少，可加的"线"detail 本来就少。
- 配准是"整格刚性变换"，模型若把某一格画歪太多（IoU < 0.74），该帧要单独处置。
- 本方法只提升**清晰度/细节**，不解决**比例/姿势/朝向**问题——那些归 3D 产线（`docs/design/01-基础功能/3D转2D动作帧产线流程.md`）。
