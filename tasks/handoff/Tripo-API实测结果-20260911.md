已下载的 `import_model_rendered.png` 显示：从我们 2D 帧生成的 3D 模型，**是低模厚涂质感、明显"3D 感"，不是我们的水墨/像素手绘画风**。

这与 3D 路线评估文档里预判的最大风险一致（「画风是生死判据」）。但**单张免费预览图不足以定论**——它的分辨率、光照、渲染设置都不是我们最终会用的配置，且这是"直接导入已有 GLB"而非"我们的图重新生成"。

**要下画风结论，必须花钱走到「渲成 2D 序列帧」那一步**（评估文档 §六 第 2 步）。

## 六、已落盘的工具（可直接复用）

`tools/tripo/tripo.py` —— 最小命令行客户端，已封装：
```
balance                      查余额
upload <file>                上传拿 file_token
image-to-model --input ...   图像→3D（本地文件自动先上传）
rig-check --input ...        绑骨能力探测（免费）
rig --input ... --spec mixamo 自动绑骨
retarget --input ... --animation preset:biped:xxx  动作重定向
convert --input ... --format FBX                    格式转换
wait <task_id>               轮询
```
用法：`python3 tools/tripo/tripo.py <子命令>`；key 存于 `~/.config/tripo/api_key`（600 权限，**未入仓库、未写进任何日志**）。

**实测踩到的两个坑（写给后续执行者）**：
1. 文档写 `model` 可用 `tripo-v3.1`／`tripo-p1` 这类**品牌名**，但 API 实际只认**带日期的版本号**（`v3.1-20260211`、`P1-20260311`、`P2-20260801`、`v3.0-20250812`、`v2.5-20250123`）。传品牌名报 `400 invalid model`。
2. `POST /v3/tasks/list` 的字段是 **`task_ids`（下划线复数）**，不是 `taskIds`；空数组会报 `task_ids: must not be empty`。
