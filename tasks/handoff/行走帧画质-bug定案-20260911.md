# 行走帧画质差 = 我的批脚本 bug（参数没传进去）· 2026-09-11 · PM2

**你说得对，行走帧的画质确实没优化——不是优化不够，是我批跑时后处理参数根本没生效。已修复，重导全套。**

---

## 一、真因：zsh 不对变量做词分割，参数被当成一整个字符串

我批跑时是这么写的：

```zsh
PP="--palette 16 --outline 1 --depth-thresh 0.05 --normal-thresh 0.85 ..."
node postprocess.mjs in out 240 320 $PP     # ❌
```

**zsh（与 bash 不同）默认不对未加引号的变量做词分割**，`$PP` 被作为**一个参数**传给脚本。结果是脚本的 `--flag` 匹配**全部失败**，**静默回落到默认值**：

| 参数 | 我想要的 | 实际生效（默认值） |
|---|---|---|
| 量化 | `--palette 16`（k-means） | `levels 8`（逐通道） |
| 深度阈值 | 0.05 | **0.012**（过低 → 描边过密） |
| 法线阈值 | 0.85 | **0.35**（过低 → 体内线条过多） |

**实测证据**（脚本自报，一眼可见）：

```
批跑时:  {"levels":8,"depthThresh":0.012,"normalThresh":0.35,"outlinePctOfSubject":26.9}
修好后:  {"levels":"kmeans-16","depthThresh":0.05,"normalThresh":0.85,"outlinePctOfSubject":13}
```

**描边占比 26.9% → 13%**——批跑时描边密度是正确值的两倍，所以画面脏、有彩色噪点。

**验证**：同一方向、同一帧，只换参数：

```
$ PP="--a 1 --b 2"; python3 -c "import sys;print(len(sys.argv)-1)" $PP
1                      ← 整串被当成 1 个参数
$ PPA=(--a 1 --b 2); python3 -c "import sys;print(len(sys.argv)-1)" $PPA
4                      ← 数组正确拆分
```

**为什么单独跑那张是对的**：我是手写完整命令行跑的（参数逐个列出），**没走这个变量**——所以我看到的是好的，批跑出来的是坏的，**两边不一致**。

---

## 二、修复

1. **批脚本改用 zsh 数组传参**：`PP=(--palette 16 --outline 1 ...)` 然后 `... $PP`；
2. **脚本加了警示注释**，把这个坑写在文件头，防复发；
3. **让脚本自报参数**——现在每次运行都会打印实际生效的参数，**下次一眼就能看出参数有没有传进去**（这次就是靠它抓到的）。

脚本：`tools/glb2d/export_frames.sh`（批量导出：方向 × 帧数，一条命令搞定全套）

## 四、教训（写进工具注释，防复发）

**批处理脚本必须自证参数生效。** 这次我犯的错是：脚本静默用了默认值，而**没有任何输出提示我**——直到你看出画面不对。现在脚本会打印生效参数，**参数没传到会立刻暴露**。

配套纪律：**批跑产物必须先目验一张再交付**（这次我要是先看一眼，就能在交付前发现）。
