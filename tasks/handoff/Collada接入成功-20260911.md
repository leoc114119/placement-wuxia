## 二、Collada 为什么更干净（实测印证）

| | FBX Binary | **Collada (.dae)** |
|---|---|---|
| 格式 | 二进制 | **XML 文本** |
| 动画数据 | **欧拉角**（有顺序歧义） | **直接给 4×4 矩阵** |
| 轴朝向 | 要读 GlobalSettings | 明确声明 `<up_axis>Y_UP` |
| 单位 | 要推 | 明确声明 `<unit meter="0.01">` |
| 名称编码 | 带 `\x00\x01Model` 尾巴 | 干净 |

**结论：以后优先下 Collada (.dae)**，其次是 FBX ASCII。FBX Binary 我也能读了，但它是三者里最容易出问题的。

## 三、这次踩的 3 个坑（都是我的实现问题）

### 坑 1：Collada 的 `<sampler>` 里两个元素同名 `<input>`

Collada 规范里，sampler 的输入/输出**都写成 `<input>`**，靠 `semantic="INPUT"` / `"OUTPUT"` 区分——**没有 `<output>` 标签**。
我一开始按名字找 `<output>` → 找不到 → **动画绑定静默失败**（"有动画的骨骼: 0"）。
**修正**：按 `semantic` 属性取。

### 坑 2：Collada 的 `<matrix>` 是**行主序**

glTF 是列主序、Collada 是**行主序**——必须转置。我没转的后果很具体：

- **位移数据全为 0**（位移在行主序的 `[3][7][11]`，我读的是 `[12][13][14]`，那是底行 `0,0,0,1`）→ **跳跃完全不动**；
- 旋转部分对纯旋转矩阵恰好等于自身转置（即逆），所以在「相对量」计算里**侥幸抵消**，帧 0 校验居然通过——**这种"看起来对但语义错"的最危险**。

**修正**：统一转成列主序再使用。

### 坑 3：**又犯了「局部矩阵 vs 世界矩阵」的语义混淆**

未映射骨骼（Root/扭转骨/手指）的处理，我写成了 `L[parent] × restLocal` —— 但 `L[]` 存的是**局部矩阵**，这个写法等于**把父级旋转叠加两次**，导致 `Pelvis` 偏 **53.7°**、各 Twist 骨偏 **~175°**。

**这是本轮第二次同类错误**（FBX 那边是 `mul` 传三参被静默丢弃）。**根因相同：对「矩阵在哪套坐标系里」不严谨。**
**修正**：未映射骨骼直接保持自身局部 rest，父级动画由层级自然传导。

**共同教训**：**矩阵运算里"这套数据在哪个坐标系、什么序"必须写死在注释和校验里，不能靠记忆。**
