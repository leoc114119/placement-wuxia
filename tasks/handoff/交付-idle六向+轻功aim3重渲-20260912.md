## 二·补 帧时长口径（09-12 Leo 追问后明确，**两条规则勿混用**）

| 动作类型 | 每帧时长 | 本项目实测值 | 说明 |
|---|---|---|---|
| **循环类** idle / walk / run | **源循环时长 ÷ 帧数** | idle 6633÷5 = **1327ms**；run 1292÷5 = 258ms；walk 2375÷5 = 475ms | 保住**运动速度**——源多快就多快 |
| **一次性** jump / 攻击（游戏**演出时钟**驱动） | **演出时长 ÷ 帧数** | 2 格跳 0.6s÷5 = **120ms** | 与战斗手感参数对齐（接入需求 §三方案 A） |

**为什么 idle 1327ms 而 jump 120ms 差这么大，却不会「卡」**——量化实测（left 向，人物高约 250px）：

| | 相邻两帧最大位移 | 每帧时长 | 每秒位移 |
|---|---|---|---|
| **idle** | **4.1 px** | 1327 ms | 3.1 px/s |
| run（对照） | 51.3 px | 258 ms | 199 px/s |

idle 的**动作本身极小**（源整个 6.6s 循环里骨轴最大只动 7.6°），相邻帧在画面上只差 4px（人物高的 1.6%）——
**每帧停 1.33s 看不出"跳帧"**，观感是缓慢的呼吸式摆动。反过来，**若把 idle 也按固定 220ms 播**，
5 帧 1.1s 走完源 6.6s 的循环 = **快放 6 倍**，那才会出事（摆动变成抽搐）。

> ⚠️ **PNG 素材本身不带时长**，帧时长是**运行时参数**；GIF 只是预览。
> 本批已把预览 GIF 统一按「游戏内推荐帧时长」重建（此前 jump 预览随手抄成 `walkFrameMs=140`，是笔误，已改 120ms）。

**idle 的 5 帧是否够**（供 Leo 判断）：5 帧 × 1327ms 是"每 1.33s 换一张"，因为单帧间只差 4px，够用；
若希望更细腻，可把 idle 提到 8~10 帧（每帧 ~660ms）——**代价是包体与产出量，等 Leo 定**。



### 现象
重定向出的帧**集体低头**——Leo 原文：「为什么会莫名奇妙的低头，轻功也是。。。不正常啊」。

### 根因
`collada2anim.mjs` 的 `aim2` 分支，「骨骼指向」两侧取法**不同源**：

| | 源侧 | 目标侧 |
|---|---|---|
| aim2（旧） | `子骨骼位置 − 自身位置` | `自身位置 − 父骨骼位置` |
| aim3（今） | **骨骼自身世界 Y 轴** | **骨骼自身世界 Y 轴** |

两者只在「子骨骼正好落在骨骼末端」时等价。22 根映射骨里**恰好 5 根不等价**：

| 骨 | 偏差 | 病灶 |
|---|---|---|
| `Head` | **25.78°** | Mixamo 的 `HeadTop_End` 不在头骨 Y 轴上（差约 26°）；模型 Head 是叶子骨，参照退化成「父→自身」＝头骨 Y 轴本身 → **头被恒定多拧 25.78°** |
| `Hip` | 50.65° | `Waist − Hip` 实测长度 **0.0000**（Tripo 绑定里两者同位置）→ 参照是零向量 → `hypot > 1e-9` 守卫**静默跳过修正**，身体整体偏 50° |
| `L_Hand` / `R_Hand` | 71.72° / 48.14° | 同「子−自身」与「自身−父」不等价 |
| `NeckTwist01` | 16.92° | 同上 |

其余 17 根骨全部 ≤0.06°（即：aim3 对它们**零影响**，改动面精确等于出问题的 5 根）。

### 验证

新增门检 `tools/glb2d/qa_retarget_bones.mjs`（逐骨朝向残差，可当门调用，退出码 0/1）：

```
aim3  idle(Orc) → ✅ 22/22 骨残差 0.000°  退出码 0
aim3  轻功      → ✅ 22/22 骨残差 0.000°  退出码 0
aim2  idle      → ❌ 5 项超容差（最大 71.72°）退出码 1     ← 负例对照
aim2  轻功      → ❌ 5 项超容差（最大 70.87°）退出码 1     ← 负例对照（09-11 交付件确有此病）
```

另有人眼证据：修后 idle/轻功渲染帧头部**直立**（与模型 rest 帧一致），轻功火柴人对比图
（源 vs 我们，5 帧）逐帧姿态吻合。

### 影响范围

- **受影响**：只走 `collada2anim` 的产物 —— idle（本日新产）、轻功（09-11 交付的 30 帧，已重渲）
- **不受影响**：`walk` / `run` 是模型自带动画（`preset:biped:*`，不经重定向）；
  `retarget.mjs`(BVH) 与 `fbx2anim.mjs` 不含该 aim 逻辑

### 为什么旧门检没拦住（🔴 全绿假象）

①「帧 0 校验」只比**源自己 rest vs 源自己帧 0**（恒等），与跨骨架映射对不对无关；
②「火柴人对比图」只看整体形状，头 25° 的偏差被躯干四肢的大位移掩盖；
③门检里**没有任何「骨骼朝向保真度」判据**——而"姿态对不对"恰恰是重定向的唯一目的。
与 BUG-11/BUG-12 同一类病：**门检没查本次改动的目的项本身**。已补入产线手册 §2.4①。

## 四、今天沉淀的两条教训（已入产线手册）

1. **门检必须包含「本次改动的目的项本身」**——重定向的目的是"姿态对"，就得直接量姿态（逐骨朝向残差）。
2. **选源动作必须量源自己的数，不能看名字/看感觉**——`Standing Idle` 名字听着最合适，实测却是
   膝弯 48°/57° 的**屈膝错步站姿**；`Orc Idle` 名字和角色都"不搭"，实测膝弯 31°、左右对称、
   髋高 93.4，渲染出来才是我们要的直立站姿。**判据 = 源膝弯 / 大腿离垂直角 / 源髋高 + 渲染后脚底 y**。
