# 根因实证：轻功头偏大源自「包围盒自适应归一」，不是生成端 · 2026-09-10

**Leo 判断正确，实测证实**：轻功在**生成时头的大小是正常的**，是**归一化到成品画布那一步被放大**的——因为下蹲时人物矮，包围盒自适应就把矮的帧放大以顶到固定高度。

---

## 一、原始生成帧实测（1086×1448 RGBA，v2 批次 raw/）

| 帧 | 原始生图人物高 | 原始生图脸宽 | 说明 |
|---|---|---|---|
| idle（锚） | 1151 | 149 | 站立 |
| jump_1 | **951** | **158** | 蹲——**最矮** |
| jump_2 | 1010 | 159 | 腾空 |
| jump_3 | 1029 | 161 | 落地 |

**关键读数**：**jump 三帧原始脸宽 158/159/161 → 极差仅 1.88%**。
→ **生成端三帧的头是完全一致的**（差异在测量噪声内）。**头偏大不是生成端的问题。**

## 二、两种归一化的对照（同一批源图）

### 方案 A ＝ v2 单系数（现行口径，`系数 = 256 ÷ idle源高 = 0.222415`）

| 帧 | 归一后脸宽 |
|---|---|
| jump_1 | 35.1 |
| jump_2 | 35.4 |
| jump_3 | 35.8 |
| **极差** | **1.88%** ✅ 生成端的一致被完整保住 |

### 方案 B ＝ 包围盒自适应（旧管线：每帧把自身包围盒顶到 256）

| 帧 | 每帧系数 | 归一后脸宽 |
|---|---|---|
| jump_1 | 256/951 = **0.2692** | **42.5** ← 被放大 |
| jump_2 | 256/1010 = 0.2535 | 40.3 |
| jump_3 | 256/1029 = 0.2488 | 40.1 |
| **极差** | — | 6.05% ❌ 被破坏 |

**放大倍数**：`0.2692 ÷ 0.2224 = 1.210`
→ **蹲姿帧被放大 1.21 倍，头因此大 21%** —— 正是 Leo 反复看到的「jump 头明显偏大」。

## 三、根因链（完整还原）

```
生成端：四帧的头一致（原始脸宽 158/159/161/149，极差 1.88%）   ← 无病
   ↓
旧归一：包围盒自适应 = 每帧各自把 bbox 顶到 256
   → 蹲姿 bbox 矮(951) → 被赋予更大系数(0.2692)
   → 该帧整体放大 1.21×，头随之放大 21%                        ← 病根
   ↓
表现：动画里 jump 头忽大忽小（Leo 两次目视命中）
```

**误诊史**：此前把病因归于"生成端比例漂移"，并据此做了多轮重生成、连续七种头尺测量法——**方向错了**。真实病因是**归一化算法**，生成端一直是对的。

## 四、结论与处置

1. **v2 单系数归一是正确解法**（方案 A：极差 1.88%），**9-10 已落规范红线 9**——本实证为该口径提供了直接证据；
2. **旧批（63 张基准帧 + 已过门的右上/右下 20 帧）全部按包围盒归一**（bbox 高恒 256 即其指纹）→ **含此放大缺陷，需按单系数重做**；
3. **验收口径**：任何归一批次，判据不是"每帧高度=某值"，而是**"组内刚体量（发冠/脸宽）极差最小"**——生成端一致多少，归一就该保住多少。

## 五、给"工程管理系统"的输入（判据固化）

- **归一必须是"全批单系数"**，系数**只由锚帧推导**；
- **门必须能抓本缺陷**：`max/min(组内刚体量)` 超阈值即报警——本实证中旧管线是 6.05% / 放大 1.21×，一测即露；
- **禁**任何"逐帧自适应"的缩放实现（含"每帧顶到固定高度"这类等价写法）。
