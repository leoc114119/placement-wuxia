## 一、要回答的问题（Leo 令）

> 用**链式生成**，能否解决**左右手 / 左右腿不分**的问题？

**背景**：并行单参考生成下，同族帧之间存在**肢体不交替**的缺陷——实测（v2 已过门 walk 三帧）：

| 帧 | 后脚 x | 前脚 x | 前脚跨度 |
|---|---|---|---|
| walk_right_1 | 64~83 | 145~173 | — |
| walk_right_2 | 80~101 | 142~180 | — |
| walk_right_3 | 74~87 | 146~182 | — |
| **三帧对比** | 74~101（摆动 27px） | **142~182（几乎不动）** | 前脚位置三帧几乎重合 |

→ **后脚在动、前脚基本钉住**＝"双腿没真正交替"的量化签名。目视（腿区放大）同样可见：三帧的**前腿姿势几乎一样**，主要变化在后腿。

**假设**：链式（每帧以上一帧为输入做 edit）中，模型能看到"上一帧的姿势"，因此更可能产生**交替**（这次抬左、下次抬右），而并行生成每帧都从同一张站姿锚出发，天然倾向重复同一姿势。

**本验证只回答这一个问题**，不做比例/尺度评估（那已由 BUG-12 与 v2 口径覆盖）。

## 二、链的定义（写死，禁改写）

```
起点：assets/_trial_20260910/t45_v2_right_batch_seq328/normalized/idle_right.png（现有产物）
  ↓      walk_right_1   输入 = idle_right
  ↓      walk_right_2   输入 = 上一步产物
  ↓      walk_right_3   输入 = 上一步产物
```
**共 3 次 edit（原生通道，0 积分）**；每步**只改动作姿势**，身份/比例/服饰/朝向不动。

**机械检查（PM2 必核）**：第 N 步输入**必须是第 N−1 步产物**（路径+SHA 对上）。任一步不符 → 该步作废重跑一次。

## 三、判据：用「腿交替」的两个客观量

**量 1 — 前后脚位置的三帧序列**（轮廓切片法，PM2 已验证可用）：
- 在**踝部高度带**（底部往上 8 / 16 / 26 / 40px）取 `alpha>32` 的横向连通段；
- 每帧提取**后脚 x 区间**与**前脚 x 区间**（左右各一段）。

**量 2 — 交替性判据（核心）**：

| # | 判据 | 通过条件 |
|---|---|---|
| 1 | **前脚也在动** | 三帧前脚中心 x 的**极差 ≥ 15px**（对照基线：并行版仅 8px，见 §五） |
| 2 | **前后脚相位交替** | 三帧中至少两帧的**前-后脚间距符号不单调**（即不是"一直同一只脚在前"） |
| 3 | **步幅合理** | 每帧前后脚中心间距 ≥ 20px 且 ≤ 160px |

**补充（辅助判据，非门）**：目视腿区放大图，记录三帧的抬腿/落地是否交替（画面逐项描述，禁只给路径）。

## 四、对照基线（已测，不必重跑）

**并行版 v2 walk 三帧**（seq=335 已过门，`t45_v2_right_batch_seq328/normalized/walk_right_{1,2,3}.png`）：

```
踝部 8px 带：  脚段 x[64,83] / x[80,101] / x[74,87]   ← 后脚，摆动 27px
               脚段 x[145,173] / x[142,180] / x[146,182] ← 前脚，极差仅 8px
```

→ **并行版前脚极差 8px**；链式若能把前脚极差推到 ≥15px，即为**交替性改善的量化证据**。

（若链式的结果与基线相近，则**结论为链式不解决此问题**，本单关闭，转其他路线。）
