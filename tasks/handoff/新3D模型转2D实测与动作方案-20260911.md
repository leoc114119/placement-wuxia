# 新 3D 模型（v2）转 2D 实测 + 动作方案 · 2026-09-11 · PM2

**新模型明显比上一个好**——你说的「质量不错了」在数据上也成立。下面是实测，以及**「换更好的动作」这件事的可行做法**。

模型：`chibi+warrior+3d+model (1).glb`

## 一、新模型 vs 旧模型（程序化实测）

| 项 | 旧模型 | **新模型** |
|---|---|---|
| 三角面 | 95,521 | **191,184（2 倍）** |
| 顶点 | 54,891 | **103,316** |
| 文件 | 5.7 MB | 9.7 MB |
| 骨骼 | 41 根 | 41 根（同） |
| 动作 | walk 2.375s / run 1.292s | **walk 1.875s** / run 1.292s |
| 贴图 | 4096² ×3 | 2048² ×3 |

### 最关键的两点改进（肉眼可见 + 可测量）

**① 手臂完全分离了** —— 这是新图（A-pose）最直接的成果。
旧模型渲染出来，手臂与身体是**长在一起**的（我实测过：旧模型侧视时手臂贴袍）；新模型**双臂与躯干之间有清晰的背景间隙，从头到尾分开**。

**② 头部侧视不再糊成一坨** —— 这是「头部简化」的成果。
旧模型侧视时头发占轮廓 **77%**（那坨黑色的东西）；新模型侧视**头型清晰、马尾轮廓可辨**，不再是黑团。

### 走路依然正常（步幅还略大）

| | 脚部 x 跨度周期 |
|---|---|
| 旧模型 | 51~103px |
| **新模型** | **59~112px** |

两版都是干净的周期波动（说明双腿交替正常），新的步幅略大一点。

## 二、画风差距 —— 这把尺子现在量得很清楚

我把新模型渲染到 **45°（和战斗帧同视角）**，和我们的 `battle_idle_right` 并排：

| | 我们的 2D | 3D 渲染 |
|---|---|---|
| 光影 | **平涂**，只有固有色 | **有立体明暗**（受光/背光） |
| 轮廓 | **粗黑描边**（手绘感的关键） | **无描边**，靠明暗分界 |
| 观感 | 手绘/厚涂 | 干净的 3D 渲染 |

**结论没变**：**差的就是「平涂 + 黑描边」这两件**——这正是我之前调研里指出的、工业管线里必做而我们还缺的那两步（Dead Cells 那套流程后段的「调色板量化 + 描边」）。

## 三、「动作换更好的」——这件事有几条路，我说清楚

### 现状：Tripo 给的是**通用动作预设**，不是为武侠设计的

新模型自带 `walk` / `run` 两个动作。它们**能用、正确、不漂移**，但是**通用走跑**——不是武侠的走法（侠客走的应该是轻捷、带袍摆感、不是这种标准步行）。

### 路 A：Tripo 有 **90+ 个动作预设**（最省事，但有上限）

Tripo 的 `retarget` 接口能往已绑骨的模型上套预设动作。**完整清单我已拉到**，和我们需求对得上的有：

| 我们的需求 | Tripo 有的对应预设 |
|---|---|
| 待机 | `preset:biped:idle`、`standing_relax`、`wait`、`swagger` |
| 走路 | `preset:biped:walk` |
| 跑步 | `preset:biped:run` |
| 跳跃/轻功 | `preset:biped:jump`、`jump_down`、`flip`（空翻） |
| 挥砍/攻击 | **`preset:biped:slash`**、`chop`（劈砍）、`box_01/02/03`（拳击） |
| 施法 | **`preset:biped:cast_a_spell`** |
| 受击 | `preset:biped:hurt`、`hit_to_body_01/02`、`hit_to_head`、`hit_to_side`、`hit_to_stomach` |
| 倒地 | `preset:biped:fall`、`defeat_02/03` |
| 转身 | `preset:biped:turn` |

**好消息**：我们的动作族（待机/走/跑/跳/攻击/施法/受击/倒地/转身）**在 Tripo 的预设里基本都有对应**——`slash`（挥砍）、`cast_a_spell`（施法）、`hurt`（受击）这几个是我们打斗最需要的，都存在。

**但注意三点**：
1. **这些是通用动作，不是武侠动作**——`slash` 是通用的挥砍，不是剑招；观感偏"通用 3D 角色"，不是侠客；
2. **套一个动作 = 20 积分**（API 定价；网页版可能不同）；
3. **网页版能不能做 retarget、界面在哪，我不知道**——你自己在网页上找一下有没有「动作/Animation」这个入口。

### 路 B：用 Mixamo（**免费**，动作库大得多，但要有 Adobe 账号）

Tripo 的绑骨支持 **`spec: mixamo`**（Mixamo 兼容骨骼命名）——**这意味着 Mixamo 的动作可以直接套到我们的模型上**。

- **Mixamo**（Adobe 免费服务）：**2000+ 个人体动作**，含大量格斗/武术动作，**免费、可商用**；
- 流程：模型 →（Tripo 或 Mixamo 自己）绑骨 → Mixamo 选动作 → 下载带动作的模型。

⚠️ **我没实测过**（需要 Adobe 账号登录，我没有）。但"Tripo 绑骨可选 mixamo 骨骼命名"这个事实说明**两者是设计上互通的**。

### 路 C：自己调/自己做动作（最自由，成本最高）

在 Blender 里对已绑骨的模型手动摆姿势/做动画。**最自由、最贴合武侠**，但需要 Blender 技能与时间——**这是"美术的活"，不是自动化的活**。

### 路 D（**我认为最值得先试**）：**先别急着换动作，先把画风补上**

理由：**画风是生死判据，动作不是**。

- 现在的 walk/run **动作本身没问题**（腿在交替、无漂移）——它只是"不够武侠"；
- 但**画风不过关，动作再好也用不了**（现在渲染出来是 3D 塑料感，不是我们的手绘风）；
- **动作可以在画风过了之后再优化；画风不过，优化动作是白做**。

---

## 四、我的建议（按顺序）

**第一步：先解决画风（这是生死线）。**
按我之前调研的工业做法，补上 **调色板量化 + 描边 + 卡通着色**。这一步**我可以直接做**——我手上已经有渲染器和全部帧产物，照 `GenshinCelShaderURP` 的技术要点实现即可（ramp 降色阶 → 硬化阴影边缘 → 描边 pass）。

**第二步：画风过了之后，再谈动作。**
优先级建议：`slash`（挥砍）→ `hurt`（受击）→ `cast_a_spell`（施法）→ 待机/走跑微调。**Tripo 套动作 20 积分/个**，先套 1~2 个验证观感，再批量。

**第三步：如果 Tripo 的通用动作观感不行，再上 Mixamo（免费、库大）。**
