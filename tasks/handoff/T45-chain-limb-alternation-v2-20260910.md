# T45 · 验证单 v2：链式交替（加姿势示意图 + 强制幅度）· 2026-09-10

**背景**：v1（seq=349）链路真实性 PASS（SHA 逐级对上）、prompt 也含"换手/换相位"要求，但**实测相位反转 0 次、换手 0 次**：

| 量 | v1 实测 | 并行基线 | 判据 |
|---|---|---|---|
| 腿：前脚三帧极差 | **10.9px** | 8px | ≥15px ✗ |
| 腿：相位反转次数 | **0** | 0 | ≥1 ✗ |
| 拳：前拳位置极差 | **0.9x / 3.1y px** | 8px | ≥15px ✗ |
| 拳：换手次数 | **0** | 0 | ≥1 ✗ |

**诊断：链式通了，但模型"改不动"**——收到"换手"指令却只做极小改动的姿态复制。

**修正方向**（两条，都来自本仓已验证的经验）：

1. **加姿势示意图**（规范 §1c）：文字方位词已证明不可靠（cast_down_2 五连败），**示意图一次过**。本次由 PM2 出图（禁代理自绘自判）；
2. **强制幅度**：v1 的 prompt 说"clear hand switch"但**没给可量化的位移幅度**。v2 明确给出**目标位置**（拳要伸到哪、脚要迈到哪）。

## 一、新增：姿势示意图（PM2 已绘制，随单交付）

```
assets/_trial_20260910/t45_chain_limb_alternation/pose_diagrams/
  legs_A_right_forward.png   画面右腿在前（蓝=动作腿）
  legs_B_left_forward.png    画面左腿在前（蓝=动作腿）
  fist_A_right_out.png       画面右拳伸出（蓝=动作拳，伸向画面右）
  fist_B_left_out.png        画面左拳伸出（蓝=动作拳，伸向画面左）
```

**图例约定（prompt 必须声明）**：**蓝色肢体 = 该帧要处于"前/伸出"状态的肢体**；灰色 = 收在后方/腰侧。**画面坐标**（左=画面左）。

**用法**：每步 img2img/edit 时，**参照 1 = 上一步产物（姿势真源）；参照 2 = 目标姿势示意图（只取姿势）**，prompt 声明各自分工。

## 二、链与目标（写死）

```
链 A（腿）：idle_right → walk_1 → walk_2 → walk_3
   walk_1 目标图 = legs_A_right_forward（右腿在前）
   walk_2 目标图 = legs_B_left_forward （左腿在前）★必须换腿
   walk_3 目标图 = legs_A_right_forward（右腿在前）
   每步输入 = 上一步产物

链 B（拳）：idle_right → atk_1 → atk_2 → atk_3
   atk_1 目标图 = fist_A_right_out（右拳伸出）
   atk_2 目标图 = fist_B_left_out （左拳伸出）★必须换手
   atk_3 目标图 = fist_A_right_out（右拳伸出）
   每步输入 = 上一步产物
```

**共 6 次 edit**（原生通道、0 积分）。**机械检查**：第 N 步输入必须是第 N−1 步产物（路径+SHA 对上）。

## 三、强制幅度（写进 prompt，解决"改不动"）

**腿（相对上一步产物，必须可量化的幅度）**：
- 动作腿的**脚部横向位置**要与上一步**相差 ≥40px**（在 240 宽画布上；原始 1086 画布上 ≥180px）；
- 明确写出：**"前腿换成另一条腿；原来在前的腿必须移到后面，两脚间距保持 ≥20px"**。

**拳（同样给出幅度）**：
- 伸出拳的**拳心横向位置**要与上一步**相差 ≥40px**（240 画布；原始 ≥180px）；
- 明确写出：**"原来的伸出拳收回腰侧，另一只拳伸到最前；两只拳的横向位置必须互换"**。

**禁**：把"轻微调整手臂角度"当作完成（v1 失败形态）；prompt 里**必须包含"must be a clear swap, not a small adjustment"**并附具体像素幅度。

## 六、红线

- **只跑 6 张**（两条链各 3），不铺量；
- 透明/背景不判；**比例不判**（本单只验交替性）；
- **示意图由 PM2 提供，禁代理自绘**（规范 §1c）；
- 每步机械失败重跑至多 1 次，再失败停手上报；
- 交付须附**画面逐项描述**（哪只脚在前、哪只拳在前、另一只在哪）；
- **若 v2 仍 0 反转 / 0 换手** → 结论为"链式在原生 edit 下无法产生交替"，本路线关闭，转其他方案（PM2 上报 Leo）。

## 七、若仍失败的备选（先不做，登记备查）

1. **单帧独立生成 + 强制要求**（不走链）：对每一帧直接生成，prompt 用示意图 + 像素幅度；风险是回到"每帧无关联"的老问题；
2. **两帧强对照法**：把"A 帧"和"B 帧（目标姿态）"并排做成双格参照（§1c 双格对比用法），让模型在**同一张参照里看到"当前 vs 目标"**；
3. **代码级解决**：步行/出拳的交替**由 runtime 承担**（左右镜像或参数化），美术只出"一个方向的一次动作"——**这可能才是最优解**（本仓唯一先例：呼吸帧就是程序化的）。
