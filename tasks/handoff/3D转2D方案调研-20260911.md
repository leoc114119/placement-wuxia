# 调研：3D 转 2D 的其他靠谱流程与方案 · 2026-09-11 · PM2

**起因**：Leo 问「3D 转 2D 有没有别的靠谱的流程或者方案」。结论先说：

> **有，而且这是一个有成熟工业方案的领域**——`Dead Cells` 就是这么做出来的。我们今天是**自己手搓了一个渲染器**，缺了这套方案里最关键的三个技术件（**调色板量化 / 描边 / 卡通着色**），所以看着别扭。**市面上有成套现成工具，不用自己写。**

---

## 一、最重要的发现：我们要做的事，业界叫「3D-to-2D sprite baking」

**`Dead Cells`（死亡细胞）就是 3D 模型渲成 2D 像素图的产物**——这不是我的推测，是多个独立开源项目的共同标注：

> Broxxar/PixelArtPipeline 自述："an example project of how to render 3D characters as Toon-lit sprites"，**"based on the character art pipeline of the popular game, Dead Cells"**
> workavast/PixelArtPipeline 自述：inspiration is the character art pipeline from **Dead Cells**

⚠️ **我没能拿到 Motion Twin（Dead Cells 开发方）的一手访谈**（搜索站点大多反爬），所以"Dead Cells 用 3D 渲 2D"这一点是**通过多个第三方开源项目的自述交叉印证的**，不是我读到的官方原话。但这么多独立项目都指向同一个源头，可信度较高。

**这条路的标准流程**（综合各工具文档）：

```
3D 模型（带骨骼+动作）
  → 卡通着色（toon/cel shading，不是 PBR 真实光照）
  → 正交相机按方向渲（每方向一组）
  → 按时间轴逐帧烘（bake）
  → 像素化（降采样 + 最近邻）
  → 调色板量化（颜色数压到 N 色）
  → 描边（outline）
  → 拼 sprite sheet
```

**关键点：画风 = 后四步决定的，不是模型决定的。** 我们今天就缺了这几步。

### 2.2 卡通着色 / 描边（画风的关键件）

| 工具 | ★ | 说明 |
|---|---|---|
| **Gaolingx/GenshinCelShaderURP** | 767 | **仿原神卡通渲染**，最值得参考的实现。技术要点见下 |
| **JasonMa0012/OutlineNormalSmoother** | 97 | 自动计算**平滑法线**供描边用——**解决硬边处描边断裂** |
| **AleFeng/OutlineSmoothNormalsGenerator** | 4 | 同上（中文项目） |
| **colesloow/moebius_shaders** | 7 | Moebius 风格描边 + 排线 |
| **blurfeng/blur-toon-urp** | 16 | 二次元卡通渲染 |

**GenshinCelShaderURP 的技术要点**（这是"怎么把 3D 渲成手绘感"的标准答案）：
1. **ramp 贴图**把连续光照**压成几个色阶**（"把色彩从多色阶降到低色阶"）；
2. **half-Lambert** 当 ramp 的 X 坐标 → 暗部取左、亮部取右；
3. **用光照图（ILM）的 alpha 通道选 ramp 的第几行**（分层控制）；
4. 阴影边缘用 smoothstep 重映射 → **"硬化阴影边缘"**（手绘感的来源）；
5. **SDF 贴图**控制脸部阴影（脸不能按几何算，否则会脏）；
6. **描边用单独的 toon outline pass**，粗细由顶点色 alpha 控制；
7. 额外：Fresnel 边缘光、发丝高光、matcap 金属高光。

> **一句话**：手绘感 = **降色阶 + 硬化阴影边缘 + 描边**。我们今天的渲染是连续光照、无描边、无量化——所以像塑料。

### 2.3 Blender 内置（不用装插件）

- **Freestyle**：非真实感渲染的描边系统（轮廓线、折痕线、可调粗细与变化）；
- **Line Art 修改器**（Grease Pencil 下）：从几何体生成线稿，**支持遮挡剔除**。

⚠️ 这两个我**没能读到官方文档正文**（Blender 手册页面只返回了导航索引），所以只能确认它们存在且定位如此，**具体参数能力我没验证**。

## 三、另一条路：EDSynth（保画风的关键，我认为对我们更重要）

上面那套是**「3D → 像素风」**。但我们的目标是**「3D → 我们的手绘武侠风」**——这两者不同。**像素化 + 调色板**能做出像素风，但做不出我们的水墨/厚涂手绘风。

**EBSynth 解决的是这个问题**：它的模式是「**只手绘一帧，自动传播到其余所有帧**」。

| 工具 | ★ | 说明 |
|---|---|---|
| **jamriska/ebsynth** | 1675 | 原始实现。**非神经网络**、基于 PatchMatch 的样例合成，"**preserve all the fine detail present in the original image**"（保留原图全部细节） |
| **s9roll7/ebsynth_utility** | 1274 | **AUTOMATIC1111 扩展**，把「img2img + Ebsynth 做视频风格化」做成 7 步流水线，**不用 AE** |
| **FuouM/ComfyUI-EbSynth** | 112 | ComfyUI 版 |
| **Trentonom0r3/Ezsynth** | 135 | 另一个实现 |

**ebsynth_utility 的完整 7 步流程**（可直接照搬）：
```
1. 导出视频全部帧 + 每帧蒙版
2. 选关键帧 —— 间隔是「动作多则密、动作少则疏」（自适应，非固定）
3. 关键帧用 img2img 风格化（可用 ControlNet）
4. 尺寸对齐回原视频
5. 生成 .ebs 文件
6. 跑 .ebs —— Ebsynth 把编辑过的关键帧传播到其余帧
7. 导出成片
```

**已知问题**（作者原话）：
- **动作断裂 → 增大关键帧间隔；闪烁 → 减小**（一句话诊疗）；
- 自动标签可能出错，需加黑名单；
- 脸部裁切放大后与身体合并会**错位**。

**对我们的意义**：如果 3D 渲染出来的**动作是对的**（今天已验证：腿交替、无漂移），那么**只需要手绘/风格化少数几帧，让 EBSynth 铺满全部** —— 这比"逐帧手绘"省一个数量级的工作量，而且**画风 100% 是我们自己定的**（因为我们手绘的那几帧就是我们的画风）。

⚠️ **未验证**：EBSynth 原本是为**视频**设计的（帧间连续性高）。游戏精灵图的帧是**离散动作**（走 8 帧循环），不是连续视频流 —— **能不能这么用、效果如何，我没有实证**。这是这条路的**最大未验证点**。

## 五、我的建议（三条路，按推荐度排序）

### 🥇 路线 A：补上「量化 + 描边 + 卡通着色」，继续用 3D 渲染
**成本最低、见效最快。** 我们已经有渲染器（`tools/glb2d/`），今天缺的就是这三个后处理件。参考 **GenshinCelShaderURP 的技术要点**自己实现：ramp 降色阶 → 硬化阴影边缘 → 描边 pass。
- **优点**：立刻能做，我手上已经有渲染器和 48 帧产物；
- **缺点**：出来的是**像素/卡通风**，**不会自动变成我们的水墨手绘风**——但会比现在接近得多。

### 🥈 路线 B：EBSynth「手绘几帧 → 传播全部」
**画风匹配度最高。** 3D 渲染只用来**提供正确的动作与结构**，画风由人手绘的少数关键帧定义，EBSynth 铺满。
- **优点**：画风**100% 是我们的**（手绘帧即画风），且**工作量比逐帧手绘省一个数量级**；
- **风险**：EBSynth 是为视频设计的，**用在离散精灵帧上没有实证**——**这是要先验的一件事**（成本很低，装个 ComfyUI 节点或 A1111 扩展就能试）。

### 🥉 路线 C：换现成的 3D→2D 工具
直接用 **workavast/PixelArtPipeline**（Unity，公共领域）或 **Godot 的 threeToTwo**，省掉自己写渲染器。
- **优点**：现成、有人踩过坑；
- **缺点**：要装 Unity/Godot；且它们默认也是**像素风**，画风问题依旧要自己解。

### ❌ 暂不推荐：换开源 3D 生成
Hunyuan3D / TRELLIS 能出模型+贴图，但**绑骨与动作仍要靠 Tripo**——换不掉核心环节，收益有限。

## 七、一句话总结

**今天我们不是"这条路走不通"，是"自己手搓漏了三个关键件"。** 这个领域有成熟方案（Dead Cells 派），工具现成、思路公开。**建议先补路线 A 的三个后处理件（我马上能做），同时低成本试一下路线 B 的 EBSynth（画风上限最高）。**
