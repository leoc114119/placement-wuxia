## 0. 模块目标

**跑通助战闭环**：右上角助战入口 → 好友列表 → 勾选 0~2 好友 → 生成快照 → 战斗布阵好友入队 → 助战次数扣减（10 场/天/好友，每日刷新）。

**验收标准：** 助战入口显示今日可助战；勾选 2 好友后战斗为 3v3；好友助战次数用尽显示「今日助战已尽」；次日刷新恢复。

## 1. 数据

```
interface FriendData {
  id: string              // 微信 openid（或内部好友 id）
  name: string            // 好友名
  avatarUrl: string       // 微信头像
  power: number           // 战力（快照用）
}

interface AssistSnapshot {       // 助战快照（R-03 ✅ 拍板）
  friendId: string
  name: string
  avatarUrl: string
  attrs: DerivedAttr      // 攻/防/血/内（快照时抓取，模块 05）
  martial: string[]       // 装配武功
  weapon: string          // 装配武器
  capturedAt: number      // 快照时间
}

interface AssistState {
  selected: string[]      // 本次已勾选好友 id（0~2）
  dailyCount: Record<friendId, number>   // 今日已助战次数（≤10，按自然日重置）
  snapshots: Record<friendId, AssistSnapshot>  // 快照缓存
}
```

## 2. 核心流程

### 2.1 入口（右上角常驻）

- 江湖场景右上角胶囊入口：头像 + 徽章（已邀数）+「助战」+「2/2 · 剩 10 场」（72 §5b）
- 徽章数字 = 当前已勾选好友数；剩 10 场 = 显示最少剩余次数（防超限）

### 2.2 邀请好友（点击入口 → 好友列表弹窗）

```
好友列表（微信好友关系链，14 §2）
  ├─ 勾选 0~2 名好友（3v3 阵容必需，可只选 0/1 人 = 人数不足降级）
  ├─ 已用尽次数（=10）的好友置灰「今日助战已尽，且看少侠独闯」
  └─ 确认 → 生成/刷新快照（AssistSnapshot）
```

- 快照时机：**勾选确认时抓取**（R-03 ✅）；战斗固定用快照，不实时拉取
- 快照缓存：本次会话复用；重开游戏后重新抓取

### 2.3 战斗入队（模块 01 / 模块 08 / 模块 04 联动）

| 战斗场景 | 助战生效 |
|---|---|
| 手动点怪开战（01） | ✅ 已勾选好友入队 |
| Boss 挑战（08，手动/挂机自动） | ✅ 入队 |
| 挂机推图（04） | ✅ 自动使用已勾选好友 |

- 战斗开始前：校验快照可用 → 入队；无好友/好友次数耗尽 → 玩家独战（人数不足）

### 2.4 次数扣减与刷新（R-03 ✅）

- 每场战斗结束（胜利/失败均计）→ 参与助战的好友 `dailyCount++`
- **同好友 ≤10 场/天**，满 10 场 → 该好友当日不可再助战
- **每日刷新**：`dailyCount` 按自然日清零
- v1.0：广告加成/恢复次数后置

## 5. 测试要求

- 能跑：微信开发者工具 / 浏览器
- 观察：① 入口显示已邀数与剩余次数；② 勾选 2 好友 → 战斗 3v3；③ 好友次数到 10 → 置灰不可选；④ 次日刷新恢复；⑤ 无好友空态 + 邀请引导
- 边界：快照生成失败（好友离线/无权限）→ 弹提示不阻塞；战斗中好友次数恰好耗尽 → 本场照常，下场禁用；1 好友/0 好友 → 降级人数可战
