## 0. 模块目标

**跑通一个最小但完整的自走棋对战**：8×12 棋盘，6v6，双方即时对战，一方全灭判定胜负。不含阵法/武功/特技（后续模块再加）。

**验收标准：** 跑起来能看到 12 个棋子在棋盘上互相移动、攻击、掉血、死亡、分出胜负。

---

## 1. 棋盘

- 尺寸：**8×12**（8 列 × 12 行，96 格，Leo 2026-08-19 拍板，覆盖 8×8/12×12/10×10），坐标 `(x, y)`，x=0~7, y=0~11
- 主战方：**下方**（y 大，y=9~11 区域）
- 敌方：**上方**（y 小，y=0~2 区域）
- 渲染：Canvas 画出 8×12 格子，色块即可（预览参考 `preview/battle-preview.html`）

---

## 2. 棋子

- 每方 **最多 6 个**，共 12 个
- 属性（第一个模块用简单值）：
```
interface Fighter {
  id: string
  team: 'player' | 'enemy'
  hp: number        // 初始 100
  attack: number    // 初始 10
  speed: number     // 行动条速度，初始 10
  x: number
  y: number
  actionBar: number // 0~100
}
```

---

## 3. 初始布阵（第一版：固定位置）

- 主战方 6 个：放在 y=10 一行（x=1~6 中间 6 格）
- 敌方 6 个：放在 y=1 一行（x=1~6 中间 6 格）
- （后续模块：阵法决定布阵，本模块固定）
- **⚠ MVP 实际规模（Leo 2026-08-20 拍板）**：战斗 = **1v 多**（我方 1 棋子 y=10；敌方按玩家实战档位 <100:1 / 100~1W:1-3 / ≥1W:1-6，R-07）。本原型 6v6 仅作自走棋逻辑验证，不直接用于 MVP 对战。

---

## 4. 战斗规则（即时制 + 行动条）

### 4.1 行动条
- 每帧：`actionBar += speed * dt`
- 满 100 → 该棋子**立即行动** → 行动后 actionBar 归 0

### 4.2 行动（每次行动做两件事）
```
① 移动：如果最近的敌人不在"攻击距离"内 → 向它移动一格（上/下/左/右）
② 攻击：如果最近的敌人已在攻击距离内 → 造成 attack 点伤害
```

### 4.3 攻击距离/范围
- **最小原型（本模块第一版）**：曼哈顿距离 ≤ 1（相邻格），先跑通对战逻辑
- **完整战斗（第三梯队融合，Leo 2026-08-19 定）**：攻击范围 = **武器形态 × 武功等级档位**（03 §3.3/§3.3b + 公式总览 R-05）：
  - 剑/拳 = 移动小十字 3×3 → 5×5 → 7×7（随使用者移动/可指定落点）
  - 棍/棒 = 中心大十字 每向 3 → 5 → 7（以自身为中心）
  - 鞭/刀 = 正前方扇形 中长 3 → 4 → 5（朝攻击方向）
  - 暗器 = 可移动单格 射程 4 → 6 → **9**（Leo 2026-08-20 定，满档可及初始行距 9）
  - **档位随武功等级提升（阈值 Lv 20/40/60，60 封顶），不限制武功阶数**
  - **出招前提**：装配武功需匹配武器类型（R-05），不匹配降级普攻（单体）
- 范围判定实现：`getAttackRange(weaponType, martialLevel) → RangeShape[]`（03 §3.3 表 + §3.3b 档位映射）

### 4.4 索敌规则
- 每个棋子找"最近的敌方棋子"（曼哈顿距离最小）
- 距离相同 → 取 x 较小者（规则写死，避免随机）

### 4.5 死亡与胜负
- hp ≤ 0 → 移出棋盘
- 一方全部死亡 → 战斗结束，另一方胜
- **防死循环超时（Leo 2026-08-20 定）**：战斗总时长 90s 双方均未全灭 → 存活 hp 总量高者胜（总量相同判玩家负）
- **手动模式超时**：行动条满后 90s 无操作 → 当前回合自动 AI 代行；再 90s → 切回自动模式（F-05）

## 5. 渲染要求（Canvas）

- 8×12 棋盘格子（浅色格子线）
- 棋子：色块 + 文字（id 或序号），主战方一种颜色、敌方另一种
- 血条：棋子上方画一条小血条
- 战斗结束：屏幕中央显示"胜利/失败"

## 6. 代码结构（第一版够用）

```
project/
├── game.ts          # 入口：主循环 requestAnimationFrame + dt
├── types.ts         # Fighter 接口
├── battle.ts        # 棋盘/棋子/行动条/移动/攻击/胜负逻辑
├── render.ts        # Canvas 绘制棋盘与棋子
└── config.ts        # 数值（hp/attack/speed/棋盘尺寸）
```

## 7. 测试要求

- 能跑：微信开发者工具 / 或浏览器打开
- 观察：12 棋子开始移动、交战、掉血、死亡、出胜负
- 边界：敌方 6 个全灭 → 主战方胜利（反之亦然）
