## 2. 依赖关系（核心）

> 方向约定：**A → B = A 依赖 B**（A 需要 B 提供的数据/能力）。数据流 = 提供方 → 消费方。

```
         ┌────────────────────────────────────────────────────┐
         │                 05 人物属性系统（地基，无依赖）        │
         │   提供：DerivedAttr（攻/防/气血/内力/战力）+ 六维      │
         └─────────────┬──────────────┬──────────────┬─────────┘
                       │              │              │
         提供属性给战斗   │  提供属性给NPC  │  提供属性给装备  │ 提供实战给门派
                       ▼              ▼              ▼
               ┌───────────┐   ┌───────────┐   ┌───────────┐
               │ 01 战斗系统│   │ 03 NPC系统 │   │ 06 装备系统│
               └─────┬─────┘   └─────┬─────┘   └─────┬─────┘
                     │               │               │
         ┌───────────┘     ┌─────────┘     ┌─────────┘
         ▼                 ▼               ▼
┌─────────────┐   ┌──────────────┐   ┌──────────────┐
│ 04 挂机系统  │   │ 08 Boss 挑战 │   │ 07 门派系统    │
│(读场景+NPC)  │   │(场景+NPC+战斗)│   │(读属性+挂接战斗)│
└──────┬──────┘   └──────────────┘   └──────────────┘
       │
       ▼
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│ 02 场景系统  │   │ 09 闭关系统  │   │ 10 助战系统  │
│(容器/入口)   │   │(场景切换)    │   │(入口+3v3入队)│
└─────────────┘   └─────────────┘   └─────────────┘
```

### 2.2 数据流（运行时闭环）

```
① 成长流：05 属性 → 06 装备 → 战力 → 01 战斗 / 04 挂机
② 经济流：04 挂机/01 战斗 → 结算（学点/实战/银两）→ 05 属性（胆识/实战）
         → 装备掉落 → 06 背包 → 分解 → 银两 → 商店买药
③ 战斗流：03 NPC → 04 挂机/01 战斗（对手）→ 07 门派技能（触发）→ 结算
④ 社交流（⚠ MVP 后置）：10 助战 → 01 战斗布阵（好友入队）/ 04 挂机（好友助战）
```

## 3. 开发顺序（依赖拓扑）

> ZCode 按此顺序逐模块实现，每块独立验收后再进下一块。

| 梯队 | 模块 | 依赖已满足 | 验收前置 |
|---|---|---|---|
| **第一梯队**（无依赖，地基） | 05 人物属性 → 02 场景系统 | — | 05 算得出属性；02 场景跑得起来 |
| **第二梯队**（依赖地基） | 03 NPC 系统（依赖 02）｜06 装备系统（依赖 05）｜07 门派系统（依赖 05） | 02 / 05 | 03 怪会动会打；06 装备闭环；07 能入门学武 |
| **第三梯队**（组装战斗） | 01 战斗系统（依赖 05/07）｜04 挂机系统（依赖 02/03/05/06） | 05/07、02/03/05/06 | 战斗能打；挂机能跑能结算 |
| **第四梯队**（扩展系统） | 08 Boss 挑战｜09 闭关系统｜10 助战系统 | 02/03/01、02/05、02/01/04 | Boss 能挑战；闭关能挂；助战能入队 |

> **注意**：01-最小自走棋盘.md 是独立验证用最小原型（自走棋逻辑验证），完整战斗系统（读属性+门派技能+助战入队）在第三梯队实现时融合。
