> 状态：**规格草稿（待 Leo 审）**
> 日期：2026-08-19
> 定位：**场景系统骨架**——2.5D 场景渲染 + 角色手动移动 + 布局。场景系统的入口模块，为 NPC 系统（03）、挂机系统（04）、Boss 挑战（08）、闭关系统（09）、助战系统（10）提供场景载体。

## 0. 模块目标

**跑通场景系统骨架**：一张 2.5D 场景图铺底，角色立绘居中可点击移动，右上角助战入口常驻，场景内底部三按钮（闭关/挂机/挑战Boss）。NPC 由模块 03 接入，本模块只铺场景和角色。

**验收标准：** 打开江湖 Tab 能看到——场景背景图 + 角色（点击场景任意位置 → 角色走过去）+ 场景名标签 + 助战入口 + 底部三按钮。无 NPC（模块 03 接）。

---

## 1. 场景渲染

- 全屏 2.5D 背景图（竖版 9:16，素材 scene_jianghu，AI 生成）
- 渲染：Canvas 铺底 + 图层叠加（背景 L0 → 角色 L1 → UI 浮层 L2）
- 场景名：左上角悬浮标签（「青牛山下 · 野径」，读场景配置）

### 1.1 逻辑坐标
```
逻辑坐标 (x, y)：x=0~1（宽比例），y=0~1（高比例）
渲染换算：px = x * canvas.width, py = y * canvas.height
角色用"脚底锚点"定位（立绘底部贴地，2.5D 感）
```

### 1.2 场景数据（读取方式）
- 场景基础数据（名称/背景图/实战要求）在 `config/scenes.ts`
- **本模块只消费 SceneConfig 的 `id/name/bg/unlockPractice`**；`npcs/boss/hangup` 字段由模块 03/04/05 消费
- 新增场景 = 加配置，不改代码

## 2. 角色

### 2.1 数据
```
interface PlayerAvatar {
  x: number          // 逻辑坐标 0~1
  y: number
  speed: number      // 移动速度，如 0.4 逻辑坐标/秒
  moving: boolean    // 是否在移动
  targetX: number    // 移动目标
  targetY: number
  state: 'idle' | 'walk' | 'fight' | 'hangup'  // 状态
  direction: 'left' | 'right'  // 朝向（立绘翻转）
}
```

### 2.2 移动规则（手动模式）
- **点击场景任意位置** → 角色向该点直线移动（`moving=true`，每帧 `pos += dir * speed * dt`）
- **点击命中优先级**（Leo 2026-08-20 定）：**UI 浮层 > NPC > 地面**（点按钮不触发移动；点 NPC 触发开战由模块 03 处理）
- **移动不碰撞**：直线穿过 NPC/场景元素；穿过主动 NPC 的 aggroRange 时由模块 03 触发追击（弹确认「迎战/暂避」，P1-8）
- 目标坐标 **clamp 到 [0.05, 0.95]**（点边界外取最近合法点）
- 到达目标（距离 < 0.01）→ 停止（`state='idle'`）
- 朝向：目标在左 → `direction='left'`（立绘水平翻转）；在右 → `'right'`
- 移动动画：**walk 4 帧循环**（起步抬腿 → 迈出 → 落地 → 另一脚跟步，Leo 2026-08-19 定，参考老网金；帧表见 `docs/77-开工素材清单-v0.1.md` §0.1，hero 帧表 = walk 4 + attack 2 + idle 2）+ 沿朝向左右翻转；无帧时回退为代码上下颠簸模拟
- 挂机模式（模块 04）时移动交给自动寻怪，本模块不管
- **状态机转移**（Leo 2026-08-20 定）：`fight` 由模块 03/08 进入战斗时置位、战斗结束回 `idle`；`hangup` 由模块 04 挂机开启/关闭时置位；本模块渲染两种状态下的角色静止表现

### 2.3 渲染
- 立绘：**hero 动画帧表 00 帧（待机站立）**，脚底锚点对齐场景地面（2026-08-21 更新：不再使用 hero_idle_transparent——那张已归位闭关系统（模块 09）专用打坐像；帧表 = `assets/ui/frames/hero/`）
- 名字标签：角色头顶「少侠·无名 Lv.8」（墨底淡金描边小胶囊）

## 3. 布局（自上而下）

```
┌──────────────────────────────┐
│ [场景名]              [助战入口] │  ← 顶部悬浮
│                              │
│       2.5D 场景背景图          │
│                              │
│        [角色立绘]              │  ← 点击场景移动
│                              │
│  [闭关修炼] [挂机] [挑战Boss]  │  ← 场景内底部三按钮
└──────────────────────────────┘
```

- 助战入口：右上角悬浮胶囊（`[头像] 助战 2/2·剩10场`），点击弹窗交**模块 10**，本模块只展示
  - ⚠ **MVP（Leo 2026-08-20 定）不做助战**：入口隐藏/置灰，模块 10 后置（R-03）；验收不包含助战交互
- 底部三按钮：闭关（模块 06）/ 挂机（模块 04）/ 挑战Boss（模块 05），本模块只渲染按钮+切换场景占位

## 4.5 状态持久化（Leo 2026-08-20 定）

- **session 内保持**：NPC 击败消失不复活、角色位置、Boss 已击败态，进战斗/闭关再返回场景时保持
- **NPC 散布例外（Leo 2026-08-22 拍板）**：氛围版 NPC（T04）为**每次进入江湖场景时随机重刷**（数量/类型/位置随机，见模块 03 §2.0）——切 Tab 回江湖、从战斗/闭关返回均重刷；**主角位置仍 session 保持不重置**
- **存档（本地 storage，MVP）**：`currentScene / playerPos / bossDefeated[] / sceneCleared[]`；save/load 云函数后置
- 场景全清后刷新数量 = 按玩家实战档位（R-06：<100→1、100~1W→1-3、≥1W→1-6），刷新间隔 30s

## 5. 测试要求

- 能跑：微信开发者工具 / 浏览器
- 观察：① 场景图正常铺底；② 点任意位置角色走过去（UI 浮层点击不触发移动）；③ 场景名显示；④ 助战入口（MVP 隐藏/置灰）；⑤ 底部三按钮可见
- 边界：角色不能移出场景边界（x/y 夹在 0.05~0.95，点击出界 clamp）；进出战斗/重进游戏后场景状态（NPC 存活/角色位置/Boss 状态）保持一致
